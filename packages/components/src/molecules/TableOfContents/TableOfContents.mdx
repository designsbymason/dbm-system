<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="TableOfContents" tier="Molecule" />

A table of contents is an outline of the page a reader is on: a list of links to its sections, with the
section they are reading marked as they scroll. It renders a `<nav>` around a list of links, each going
to `#id`, so it works as plain anchor links before any script runs.

Give it `items` — each an `id` to link to, a `label`, and an optional `level` (1 to 4) that indents it —
or leave `items` out and it reads the `h2` and `h3` headings from the page (or from one element, with
`contentRef`). The marked entry follows the scroll position, and a click scrolls to the section,
smoothly unless the reader prefers less motion. `scrollOffset` keeps a section clear of a sticky
header, and `scrollContainerRef` points it at a scrolling box instead of the page. `sticky` keeps it in
view beside long content, `collapse` folds it behind an "On this page" button on a small screen, and an
outline that is taller than its own box keeps the current entry in view in it. `minLevel` and `maxLevel`
choose which levels are drawn, `numbered` writes the entries as an outline, `movingMarker` slides one bar
between entries, and `collapsibleGroups` lets an entry fold the deeper entries under it away. An entry can carry
an icon, trailing content or `disabled`.

### Import

```tsx
import { TableOfContents } from "@dbm-system/components";
```

## Variants

### All sizes

<Canvas of={TableOfContentsStories.Sizes} />

### Tones

`"brand"` (the default) colours the current entry and its marker with the brand theme's accent;
`"neutral"` keeps the current entry in primary text with a strong neutral marker — the one to use on
`bg.canvas`, where brand text is under the contrast floor.

<Canvas of={TableOfContentsStories.Tones} />

### Highlighted current entry

The current entry has a subtle background in the tone's own tint — `highlightActive`, on by default. The
marker bar stays, so the background is never the only cue.

<Canvas of={TableOfContentsStories.Highlighted} />

### Without the highlight

`highlightActive={false}` leaves just the marker bar and the change of colour.

<Canvas of={TableOfContentsStories.NotHighlighted} />

### Numbered entries

`numbered` writes the entries as an outline — 1, 1.1, 1.2, 2 — from the levels that are drawn, which suits a
documentation page whose sections are numbered too. The number is part of the link's text, so it is read with the
label; the page's own headings are not numbered by this. `formatNumber` writes the digits, for a locale's own
numerals.

<Canvas of={TableOfContentsStories.Numbered} />

### Moving marker

By default the bar appears beside the current entry. `movingMarker` draws one bar that slides from entry to entry
as the page is read, and resizes to fit a wrapped entry. It starts where it belongs rather than travelling there,
doesn't slide for a person who prefers reduced motion, and is a border, so forced colours keeps it. Scroll the
article to watch it.

<Canvas of={TableOfContentsStories.MovingMarker} />

### Collapsible groups

With `collapsibleGroups`, an entry that has deeper entries after it gets a small button that folds them away; a
group inside a group goes with it. A closed group that holds the current entry carries the marker bar on its
heading, so the place in the outline is never lost, and a group that holds keyboard focus stays open. Groups start
open.

<Canvas of={TableOfContentsStories.CollapsibleGroups} />

### Groups that start closed

`groupsDefaultOpen={false}` starts every group closed except the one holding the current entry, and that group
opens as the page is read — the outline unfolds to show where you are. A group you have opened or closed by hand
keeps your choice from then on. Scroll the article, and open one by hand to see both.

<Canvas of={TableOfContentsStories.GroupsStartClosed} />

### Choosing the levels

`minLevel` and `maxLevel` (1 to 4) draw only some levels; what is left is indented from `minLevel`. They
apply to `items` and to headings read from the page alike, so a page with `h2`, `h3` and `h4` headings can show
just the first two without writing a selector.

<Canvas of={TableOfContentsStories.Levels} />

### Icons, badges and disabled entries

An entry can take an `icon`, `trailing` content (a `Badge`, say) that sits at the far edge and is read with the
label, and `disabled`, which dims it and blocks it but leaves it focusable, as `aria-disabled`.

<Canvas of={TableOfContentsStories.EntryExtras} />

### Folded behind a button

`collapse` folds the outline into an "On this page" button that opens the list: `"always"`, or `"auto"` to do it
below the `sm` breakpoint only. Choosing an entry closes the list again, `Escape` closes it from inside it, and
`open`, `defaultOpen` and `onOpenChange` control it. A list with keyboard focus inside it stays open while it
does, so a screen that narrows never drops focus. On this page the box is a fixed width, so `"always"` shows it;
open the story on its own at a phone size to see `"auto"`.

<Canvas of={TableOfContentsStories.Folded} />

### Folded as a dropdown, sticky

`foldedStyle="dropdown"` draws the folded outline as a select-like button that **always shows the entry being
read** — it changes as the page scrolls, on one line with an ellipsis, so the bar never resizes — and opens the
list as an overlay floating over the page. With `sticky="folded"` the button stays in view as a bar across the
top, on the page's surface with a rule below it, and only while the outline is folded: above the breakpoint it is
the plain outline again. The headings are kept clear of the bar for you (a click, the `#id` correction and the
marked entry all allow for its height), so `scrollOffset` only has to cover what is *above* it. The bar sticks
to the page or to `scrollContainerRef`, and its parent must be as tall as the content it follows. This is the phone
setup: `collapse="auto" foldedStyle="dropdown" sticky="folded"`. It is a disclosure of real links, not a `Select`:
an entry stays a link (it can be opened in a new tab), and the panel closes on a choice, `Escape` or a press outside.

<Canvas of={TableOfContentsStories.Dropdown} />

### A row of pills
A row (`layout="row"`) is for the top of a page on a phone or tablet, where a column has no room. It is drawn by [`NavigationMenu`](/docs/organisms-navigation-navigationmenu--docs): one rounded pill for each top-level entry, and a pill that has entries inside it is a split pill, its link to its own section and a caret that opens a panel of the entries inside it. The pill that holds the section being read is marked, so the row says where you are even when the section is in a panel. With `sticky` it sticks to the top of the page or the scrolling box (`stickyOffset` takes a CSS length, such as a sticky header's measured height), and the headings are kept clear of it. A row that is longer than the room scrolls sideways inside itself, keeps the marked pill in view and **fades out the end that has more** (and the start, once it has been scrolled), so a pill cut off at the edge reads as "more this way". It has no title, does not fold, and ignores `tone` and `collapse`, so give it a name with `aria-label` or `labels.navigation`.

`layout` also takes a width map, `{ base: "row", lg: "list" }`, which draws one outline that is a row on a phone and the list from `lg`, with one set of entries and one name. It changes the layout where the outline is; it cannot move it, so a page that keeps the column at the end of the page and the row at the top (the [Documentation Page](/docs/templates-application-shells-documentation-page--docs)) draws two outlines from one list of entries and shows one at each width.

<Canvas of={TableOfContentsStories.Row} />

### Sticky

`sticky` keeps the outline in view as the content scrolls. It is built on `Affix`: it sticks to the page, or
within `scrollContainerRef` as here, and `stickyOffset` (on the spacing scale) leaves room for a sticky header
of your own. Give its column the height of the content, so it has room to travel.

<Canvas of={TableOfContentsStories.Sticky} />

### A long outline in a box of its own

An outline taller than its box scrolls inside that box, and the current entry is kept in view in it — only the
box moves, never the page. Scroll the article and watch the outline follow.

<Canvas of={TableOfContentsStories.LongOutline} />

### Nested levels

`level` indents an entry, one step per level, up to four.

<Canvas of={TableOfContentsStories.Nested} />

### Read from the page

With no `items`, the outline is read from the headings in the browser. Each needs an `id`; one without is
skipped (with a warning in development). It is read after the first render and again whenever the
container's content changes, so headings that arrive later join the outline. A server-rendered page has no
outline until it loads — pass `items` where that matters. Here the article's own headings make the outline.

<Canvas of={TableOfContentsStories.ReadFromPage} />

### In a scrolling box

When the headings live in a box that scrolls rather than the page, `scrollContainerRef` tells the outline
which one to measure and scroll. Every other story on this page uses it for the same reason: a story must
not scroll the whole Docs page.

<Canvas of={TableOfContentsStories.InAScrollingBox} />

### Under a sticky header

`scrollOffset` is the height, in pixels, of a header that sits over the top of the content. A heading
counts as reached when it gets to just under that header, and a click leaves its section there.

<Canvas of={TableOfContentsStories.StickyHeader} />

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use an outline on a long page, or one with several sections a reader will want to jump between:
  documentation, an article, a settings page, a policy.
- Keep it beside the content, with `sticky` so it stays in view while the page scrolls.
- Point it at headings that already have `id`s, and keep the labels short — the heading's own text.
- Use `scrollOffset` whenever a sticky header covers the top of the page, so a section isn't left under it.
- Pass `items` for a server-rendered page, or one whose outline must be there before scripts run.
- Name each outline with `aria-label` when a page holds more than one.
- Put a `"brand"` outline on `bg.surface`; use `"neutral"` on `bg.canvas`.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a short page — a few sections are already visible at once.
- Don't use it as the site's navigation, or to show the steps in a process. It outlines one page — use
  `Tabs`, `Breadcrumb` or a stepper for those.
- Don't nest more than two or three levels; an outline that deep is a second table of contents.
- Don't list every heading. Pick the level (`selector`) that gives a scannable list.
- Don't point entries at elements that aren't on the page: a link to nowhere does nothing.
- Don't put the outline inside the scrolling content it outlines, where it scrolls away.

</Callout>
</div>

## Best practices

- The marked entry is the last heading that has reached the top of the scrolling area. Before any has,
  it is the first heading showing in the area, so an outline is marked on load when a heading is in view.
  When the first heading is still below the fold nothing is marked, which is honest about an introduction
  that belongs to no section.
- At the very end of the page the last entry is marked even if its heading can never reach the top, so
  a short final section isn't unreachable.
- Leave some room after the last section, as a long page usually does, so every section can be scrolled
  to the top by a click.
- A click scrolls to the section and puts `#id` in the address (without adding a history entry per
  click); a click with a modifier key, or a middle click, is left to the browser, so "open in a new tab"
  works.
- After a click made with the keyboard, focus moves to the section, so the next `Tab` continues from
  there. The heading is given `tabindex="-1"` for that, unless it already has a `tabindex`.
- An outline that is longer than the screen can sit in a box with its own height (a `ScrollArea`, or any box
  that scrolls); the current entry is scrolled into view in it, and only that box moves.
- Use `collapse="auto"` where the outline sits above the content on a phone, so it costs one line until it is
  asked for. The title on the button is `labels.title`.
- A page opened at `#section` is moved to that section by the outline, clear of a sticky header, even when
  the headings are read from the page after the first render (`scrollToHash`). Give the headings a
  `scroll-margin-top` too, so a plain link to them lands clear of the header before the outline loads.
- Use `numbered` where the page's own headings carry the same numbers, so the outline and the page agree, and
  not otherwise — an outline numbered differently from the page it points at is confusing.
- `movingMarker` is the more polished look and the plainer one is the safer default: keep it for an outline that
  stays in view (`sticky`) where the slide is seen, and leave it off where the outline scrolls out of sight.
- `collapsibleGroups` is for outlines long enough to need it. For a short outline the buttons add a tab stop per
  group and nothing else; `groupsDefaultOpen={false}` with `sticky` is the "unfolds as you read" pattern.
- **On a phone**, use `collapse="auto" foldedStyle="dropdown" sticky="folded"`: one line that always says where
  you are, a list a tap away, and nothing at all taken from the content above the breakpoint. A plain
  `collapse="auto"` (inline) suits a phone outline that sits above the content and doesn't need to follow you.
- Don't also put `sticky` (true) on a folded outline: its box would cover the content. `sticky="folded"` is the
  one that is drawn as a bar.
- Use `disabled` for a section the reader can't use yet, rather than leaving it out, so the outline still
  shows the whole structure.
- Every piece of text the component writes itself is in `labels` — the title, the name of the nav when the title is hidden, the name of a group's button (`groupToggle`) and the name of the dropdown's button (`dropdownTrigger`), the last two functions of the text they name — and the digits of `numbered` go through `formatNumber`.

## Accessibility

<Callout tone="info" title="A named navigation landmark holding a list of links, with the section being read marked">

The outline is a `<nav>` — a navigation landmark, named by its visible heading ("On this page"), or by
`labels.navigation` when the heading is hidden, or by your own `aria-label` / `aria-labelledby`, so a
reader who lists a page's landmarks can tell it from the main navigation. Inside is a list of links, so a
screen reader announces how many sections there are. The list and its items state their `list` and
`listitem` roles outright, because Safari with VoiceOver otherwise stops treating a list with its markers
removed as one. The entry being read carries `aria-current="location"`, announced as "current location".

| Key | Behaviour |
|---|---|
| `Tab` | Moves to the next link — every entry is one stop |
| `Shift+Tab` | Moves to the previous one |
| `Enter` | Follows the link: scrolls to the section and moves focus to it |

The dropdown's button is a disclosure of a panel (`aria-haspopup`, `aria-expanded`): the panel is a named dialog
holding a navigation landmark and the same real links, focus goes to the entry being read when it opens, `Escape`
and a press outside close it and give focus back to the button, and choosing an entry with a key leaves focus on
the section instead. The button's text is the entry being read, and its accessible name says the outline's name
first ("On this page: Setup"), so the visible text is always inside the name. It is **not a live region**: the
label changes silently as the page scrolls, because announcing every section passed would be noise.

A group button is a disclosure too: it carries `aria-expanded` and a name from `labels.groupToggle` ("Subsections of
Setup"), and folding never takes the entry that has focus out of the page. A closed group holding the current entry
shows the bar on its heading, and does not claim `aria-current`, which belongs to the entry itself. The moving
marker is decorative (`aria-hidden`) — `aria-current` says it in words — and stays still for a person who prefers
reduced motion. A number is plain text in the link, so it is part of its accessible name.

When the outline is folded, the button is a disclosure: it carries `aria-expanded` and `aria-controls`, and
closing the list — by choosing an entry or with `Escape` — never leaves focus on something that has just
disappeared: after a key press focus goes to the section, after a mouse click or `Escape` to the button. A list
holding keyboard focus stays open even if the screen narrows. A `disabled` entry stays in the tab order with
`aria-disabled`, as WAI-ARIA recommends, and does nothing when activated.

A mouse click scrolls without moving focus, as a plain anchor does; a keyboard activation also moves focus
to the section. The marker is not colour alone: the current entry also has a thicker, differently coloured
bar beside it (a system highlight colour in forced-colours mode), and `aria-current` says it in words. Its
text keeps the same weight as the others, so entries never reflow as it moves. Every entry is at least 24
pixels tall at every size.

**Contrast**, measured in light and dark. On `bg.surface`, an entry (`text.secondary`) is 6.88:1 and
10.47:1, and a hovered or `"neutral"`-current entry (`text.primary`) is 14.11:1 and 13.53:1. A
`"brand"`-current entry (`text.brand`) is 7.37:1 (Purple) or 6.08:1 (Emerald) in light, and 7.45:1 or
6.49:1 in dark; its bar (`border.brand`) is 7.37:1 and 6.08:1 in light, 7.45:1 and 8.51:1 in dark. The
`"neutral"` bar (`border.neutral-strong`) is 4.70:1 and 6.08:1. **Put a `"brand"` outline on
`bg.surface`, not `bg.canvas`**, where brand text falls under the 4.5:1 floor in dark mode (3.63:1 Purple,
3.16:1 Emerald). The `"neutral"` tone is 6.05:1 and 5.10:1 for entries and 12.41:1 and 6.59:1 for the
current one there. By default (`highlightActive`), the current entry's text sits on its tone's fill: `text.brand` on `bg.brand-subtle` is
7.03:1 (Purple) and 5.83:1 (Emerald) in light, 8.29:1 and 7.22:1 in dark; `text.primary` on
`bg.neutral-subtle` is 13.53:1 and 9.66:1. In dark mode `bg.brand-subtle` is a step darker than the surface and
only about 1.1:1 from it, which is why the bar stays the main cue. The track the bars sit on (`border.default`) is a decorative line and isn't held to 3:1.

</Callout>

## Code examples

```tsx
<TableOfContents
  items={[
    { id: "overview", label: "Overview" },
    { id: "installation", label: "Installation" },
    { id: "requirements", label: "Requirements", level: 2 },
    { id: "usage", label: "Usage" },
  ]}
/>

{/* Read the h2 and h3 headings inside an article */}
<TableOfContents contentRef={articleRef} />

{/* ...and h4 too */}
<TableOfContents contentRef={articleRef} selector="h2, h3, h4" />

{/* Beside long content, in view while the page scrolls, clear of a 56px sticky header (offset 16 is 64px) */}
<TableOfContents contentRef={articleRef} scrollOffset={56} sticky stickyOffset={16} />

{/* Folded behind a button below the sm breakpoint */}
<TableOfContents contentRef={articleRef} collapse="auto" />

{/* Only the first two levels, with an icon, a badge and a disabled entry */}
<TableOfContents
  maxLevel={2}
  items={[
    { id: "guide", label: "Guide", icon: BookOpenIcon },
    { id: "news", label: "News", trailing: <Badge size="xs" tone="info">New</Badge> },
    { id: "soon", label: "Soon", disabled: true },
  ]}
/>

{/* The headings are in a scrolling box of your own */}
<TableOfContents contentRef={boxRef} scrollContainerRef={boxRef} />

{/* You decide which entry is marked */}
<TableOfContents items={items} activeId={active} onActiveIdChange={setActive} />

{/* Neutral, with no visible heading, named for screen readers */}
<TableOfContents items={items} tone="neutral" showTitle={false} aria-label="Chapters" />

{/* A native <nav> attribute, passed straight through */}
<TableOfContents items={items} onFocus={() => track("toc-focus")} />
```
