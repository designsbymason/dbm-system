<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="RangeSlider" tier="Molecule" />

A slider with two thumbs, for choosing a range of values — a price band, a date span, a volume
window. It is built on Radix UI's Slider primitive and drawn exactly like `Slider`: the same track,
thumb, sizes and labels, with the stretch between the two thumbs filled. The value is a
`[minimum, maximum]` pair, lower first, in both controlled (`value`/`onValueChange`) and
uncontrolled (`defaultValue`) use, and a thumb can never pass the other. `onValueCommit` fires once,
on release, distinct from `onValueChange`'s continuous firing while dragging or stepping.

### Import

```tsx
import { RangeSlider } from "@dbm-system/components";
```

### Right to left

`dir="rtl"` mirrors the slider for right-to-left languages: the minimum sits at the right, the filled range and
both thumbs run from there, the arrow keys move the other way (`ArrowLeft` raises a thumb), and the range text and
the min/max labels swap sides with them. It is passed through to the underlying Radix slider. It is not read from the page: with `dir` left out the slider
follows the nearest `DirectionProvider`, else left-to-right, so its parts always agree.

### Keeping the thumbs apart

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `RangeSlider` when the question is "between what and what" — a price band, a date span, a
  volume window. For a single value, use `Slider`.
- Reach for `onValueCommit` for anything expensive that should only run once the user settles on a
  range (a search, a filtered query) — `onValueChange` fires continuously while dragging.
- Pass `aria-label` (or `aria-labelledby`) — each thumb's name is built from it, so without one the
  thumbs are only "Minimum" and "Maximum".
- Set `minStepsBetweenThumbs` to at least `1` when the two ends of the range must stay distinct, so a
  thumb is never hidden underneath the other.
- Set an explicit `height` via `style` whenever `orientation="vertical"` — a vertical slider has no
  intrinsic height.

</Callout>
<Callout tone="danger" title="Don't">

- Don't pass `value` with the two numbers the wrong way round — the lower value comes first, always.
- Don't drive `value` from a live control without a real `onValueChange` wired back — the thumbs
  would appear frozen.
- Don't use `RangeSlider` to pick two unrelated values (a width and a height): it draws them as one
  filled stretch, which reads as a single range.
- Don't treat `showValueTooltip` as a substitute for `formatNumber` — the tooltip is a visual aid,
  while `formatNumber` also changes what assistive tech announces.

</Callout>
</div>

## Best practices

- Match `size` to the surrounding layout's density, same as `Slider` and `Input`.
- Keep `step` a "round" value relative to the value's own natural granularity, and set `min` and `max`
  so the whole track is a meaningful range (a price from 0 to 500, not 0 to 487).
- Show the range as text with `showValue` when no other element reflects it, and add `formatNumber`
  for a unit — "$100 – $300" says more than "100 – 300".
- Reach for `showValueTooltip` instead of `showValue` when the numbers only matter *while*
  interacting; it appears on hover, drag or focus and otherwise gets out of the way.
- Pair with `FieldHelperText` to state the valid range in plain language, and with `FieldError` and
  `hasError` to say why a range failed validation.
- Keep `labels.minimum` and `labels.maximum` short — they are spoken after the slider's own name on
  each thumb.

## Accessibility

<Callout tone="info" title="Two sliders in one control, each named and reachable on its own">

- Each thumb is its own `role="slider"`: `Tab` moves from the lower thumb to the upper one, and each
  takes the arrow keys, Page Up/Down, Home and End, per the WAI-ARIA slider pattern.
- Each thumb's name is the slider's own (`aria-label`, or the visible label named by
  `aria-labelledby`) followed by "Minimum" or "Maximum" — "Price Minimum", "Price Maximum" — so a
  screen reader user always knows which end they are moving. `labels` changes those two words. A
  dev-mode console warning fires once when there is no name at all.
- `aria-valuenow`, `aria-valuemin` and `aria-valuemax` reflect the real state of each thumb. A thumb
  can never pass the other, and `aria-valuemin`/`aria-valuemax` are the track's ends, not the other
  thumb's value.
- **Home and End move the focused thumb to its own limit**: the lower thumb goes to `min` (or, with
  End, as far as the upper thumb allows), and the upper thumb the reverse. The underlying primitive
  would instead move the first thumb on Home and the last on End whichever one has focus; this
  component handles the two keys itself so the thumb you are on is the thumb that moves.
- `dir="rtl"` flips which arrow key moves which way (`ArrowLeft` raises a thumb) along with the layout; Home and End still send the focused thumb to its own limit.
- `aria-invalid="true"` is set on both thumbs while `hasError`, in addition to the visual danger
  colours.
- `aria-describedby` is set on both thumbs, so a helper or error message is announced with either.
- With `formatNumber`, each thumb's `aria-valuetext` becomes its formatted number, so what a sighted
  user reads and what a screen reader announces agree; `aria-valuenow` stays the plain number.
- A `disabled` slider is skipped by `Tab` entirely and ignores pointer and keyboard input.
- `id` is applied to the lower thumb, the first focusable part, and the upper thumb gets the same id
  with `-maximum` added. `autoFocus` focuses the lower thumb on mount.
- Each thumb's pointer and touch target is at least 24 × 24px at every size (an invisible area around the smaller thumbs), meeting WCAG 2.5.8. Where two thumbs sit close together the areas overlap and the upper one is on top.
- Tick marks, the min/max labels and the tooltip are all purely visual; none changes what is
  announced.
- The filled range (`bg.brand`) is checked against real WCAG contrast ratios. The unfilled track
  (`bg.track`) deliberately doesn't clear the 3:1 non-text floor, an accepted exception since the
  thumbs and the filled range already carry the boundary and state information.

</Callout>

## Code examples

```tsx
<RangeSlider aria-label="Price" defaultValue={[20, 80]} />
<RangeSlider aria-label="Price" value={range} onValueChange={setRange} min={0} max={500} step={10} />
<RangeSlider aria-label="Price" onValueCommit={runSearch} showValue />
<RangeSlider aria-label="Volume" orientation="vertical" style={{ height: "12rem" }} />
<RangeSlider aria-label="Age" minStepsBetweenThumbs={5} showValueTooltip />
<RangeSlider aria-label="Price" defaultValue={[100, 300]} max={500} showValue showMinMaxLabels formatNumber={(n) => `$${n}`} />
<RangeSlider aria-label="Zoom" min={0} max={200} step={10} showTicks tickInterval={50} />
<RangeSlider aria-label="Preis" labels={{ minimum: "von", maximum: "bis" }} />
<RangeSlider aria-label="Price" onFocus={() => trackFieldFocus("price")} />

{/* Inside a <form>, two values are submitted under price[] — the lower, then the upper */}
<form>
  <RangeSlider aria-label="Price" name="price" defaultValue={[20, 80]} />
</form>

{/* Composed inside a FormField for the label/helper-text wiring — see that
    component's own Docs page for the full pattern. */}
<FormField label="Price" helperText="Between 0 and 100">
  {(fieldProps) => <RangeSlider {...fieldProps} />}
</FormField>
```
