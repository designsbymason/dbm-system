<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Tabs" tier="Molecule" />

A set of tabs, each switching which of several panels is showing, built on Radix Tabs. A compound
component: put a `Tabs.List` holding one `Tabs.Trigger` per tab inside `Tabs`, and one
`Tabs.Content` per trigger beside it, matched by `value`. Only the selected tab's panel is in the
page, and the keyboard works the way a reader of any tabbed interface expects: `Tab` enters the
list once, and the arrow keys move between tabs from there (this is called *roving focus* — the
whole list is a single stop in the tab order).

Choose how the selected tab is marked with `variant` (an underline, a soft tint, a tint with a border
on every tab, or a solid fill), how big everything is with `size`, whether the tabs have fully round
ends with `rounded`, and whether the tabs run across or down with `orientation`. `Tabs.List`'s own
`align` places the tabs at the start, the middle, or the end when they don't fill the list. A list
that outgrows its container — too wide for it, horizontal, or too tall for it, vertical — scrolls
along its own axis, keeps the selected tab in view, and shows a fade and a button wherever there
are more tabs that way. Nothing bounds a vertical list's height on its own; give `Tabs.List` a
height to respond to — wrapping it in a `display: flex` box works, a plain percentage on its own
doesn't — for the overflow handling to actually engage.

### Import

```tsx
import { Tabs } from "@dbm-system/components";
```

## Properties

`Tabs` is uncontrolled with `defaultValue`, or controlled with `value` and `onValueChange` — pass
one of them, since with neither no tab is selected and no panel shows. `variant`, `size`,
`orientation` and `fullWidth` are set once here and apply to every part inside. `ref` forwards to
the root `<div>`. Also accepts any other native `<div>` attribute beyond what's listed here (e.g.
`onFocus`, `onMouseEnter`) — passed straight through to the root element.

<PropertiesTable of={TabsStories} order={rootPropOrder} />

`orientation` also accepts a mobile-first map of breakpoint to value, such as
`{ base: "horizontal", md: "vertical" }` — see the responsive example below. A map is resolved in
JavaScript, so a server-rendered page uses the `base` value until the page loads in the browser.

### Tabs.Item properties

A tab with a control beside it, such as a close button: it wraps one `Tabs.Trigger` and an `action` drawn at the tab's end as a sibling of the tab button, never inside it. The trigger keeps every look it has and its place in the arrow-key order; the item only makes room for the action and positions it. The action is hidden from assistive technology, because a tab list may only own tabs, so it is a pointer shortcut and what it does needs a key or a menu as well. `EditorTabs` is built on it. Also accepts any other native `<div>` attribute beyond what's listed here (e.g. `title`) — passed straight through to the wrapper.

### Too many tabs for the height

A vertical list works the same way, along the block axis instead. Drag the bottom-right corner of
the box to change how much room the tabs have, or shrink the canvas itself — the box's own height
tracks it the same way the width example's box tracks the canvas's width. Nothing bounds a
vertical list's height on its own the way the page's own width naturally bounds a horizontal one,
so `Tabs.List` needs a height of its own to respond to: wrap it in a box that stretches it, such as
a `display: flex` container, rather than a plain percentage (which has nothing definite above it
to resolve against — a page's height, unlike its width, was never bounded by the viewport in the
first place); cap that box's own height in `vh` rather than `%`, for the same reason.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `Tabs` for peer views of the same subject where a reader needs one at a time — a project's
  overview, activity and settings.
- Always pass `defaultValue` (or a controlled `value`), and give every tab a matching
  `Tabs.Content`.
- Name the list with `aria-label` when a page holds more than one set of tabs, or when the
  surrounding heading doesn't already say what they switch between.
- Keep labels to a word or two. When there are many, the list scrolls; past six or seven,
  consider a vertical list or a `Select`.
- Use `activationMode="manual"` when showing a panel is expensive (a large table, a network
  request), so a reader can move through the tabs without loading each one.
- Use `forceMount` on a panel that holds state a reader would be upset to lose, such as a form
  they've started filling in.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use `Tabs` to move between pages. Tabs switch views in place; use links, or a navigation
  component, for a change of page. Tabs rendered as links with `asChild` are for tabs that still
  switch panels.
- Don't hide content every reader must see behind a tab — someone may never open it.
- Don't leave `defaultValue` out. With no tab selected, nothing is shown and the list has no
  obvious place to start.
- Don't disable a tab without saying why somewhere nearby; a disabled tab can't be focused, so a
  keyboard reader gets no explanation from it.
- Don't nest tabs more than one level deep, or put a `Tabs` inside a `Tabs.Trigger`.

</Callout>
</div>

## Best practices

- Put the tabs' own controls (a filter, an "Add" button) inside the panel, not in the list. The
  list is only for choosing a view.
- To let a reader share or bookmark a tab, control it: keep the selected value in the URL, pass it
  as `value`, and update the URL from `onValueChange`.
- `size` also sets the space between the list and its panel, so tabs and their content stay in
  proportion. A trigger's height matches a `Button` or `IconButton` of the same size, so a tab list
  lines up beside either.
- For a vertical list beside its panel on a wide screen that has to become a strip on a phone, use a
  breakpoint map on `orientation` rather than two separate components — the arrow keys follow the
  layout.
- An icon-only tab needs an `aria-label`; the icon is decorative. A count or status belongs in the
  label itself — a `Badge` placed next to the words.

## Accessibility

<Callout tone="info" title="Roles, state and keyboard behaviour come from Radix's own tabs primitive">

The list is a `tablist`, each trigger a `tab` with `aria-selected`, and each panel a `tabpanel`
named by its trigger (`aria-labelledby`). Each trigger's `aria-controls` points at its panel, and
the list's `aria-orientation` follows `orientation`. A panel is focusable, so a reader can press
`Tab` from the list straight into it. An unselected panel is not in the page at all, so it can't be
read or reached (with `forceMount` it stays, hidden from view and from assistive technology).

| Key | Behaviour |
|---|---|
| `Tab` | Enters the list on the selected tab; pressed again, moves to the panel |
| `Shift+Tab` | Moves back out of the panel, then out of the list |
| `Right` / `Left` | Next / previous tab in a horizontal list (swapped when the text runs right to left); selects it too, unless `activationMode="manual"` |
| `Down` / `Up` | Next / previous tab in a vertical list |
| `Home` / `End` | First / last tab |
| `Enter` / `Space` | Selects the focused tab (needed only in manual mode) |

Arrow keys wrap from the last tab to the first unless `loop={false}`, and skip a disabled tab. A
list's own scroll buttons — "Scroll tabs to the start"/"Scroll tabs to the end" — are plain
buttons outside the tab list itself, reached in normal tab order rather than by the arrow keys;
they appear only while there is something that way to scroll to, except that one briefly stays,
inert, if it still has keyboard focus the moment it would otherwise disappear — so focus is never
dropped to the top of the page. `Tabs.List`'s `showScrollButtons={false}` hides them outright; the
list still scrolls the same way underneath — the fade, the arrow keys, and a touch or trackpad
swipe are all unaffected — only the pointer-only buttons themselves are gone.

**Contrast**, measured for every pairing in Purple and Emerald, light and dark: an unselected label
on the surface is 6.88–10.47:1, and 13.46–15.05:1 once hovered (on `bg.brand-subtle`); a selected
label is 5.83–8.29:1 on its tint and 6.08–8.51:1 on the solid fill; a hovered selected label is at
least 4.63:1; the underline bar and the outlined variant's selected border are 6.08–8.51:1 against
the page; icons are at least 3.67:1. The unselected tabs' borders in the outlined variant are a
faint decorative tint (1.08–1.24:1), so the selected tab's border and every label carry the state,
not those.

**The focus ring** is drawn inside the tab, so a list that scrolls, along either axis, can't clip it. On the
underline and subtle variants it is `border.focus` (4.16–6.49:1 against the page). On the outlined
variant it is `bg.brand-hover` (8.64–11.74:1 against the tab's fill and the page), drawn just inside
the border so it doesn't sit on top of it. On the selected tab of the **solid** variant it is also
`bg.brand-hover`, which is only 1.24–1.48:1 against that tab's own fill — well under the 3:1 a focus
indicator should have — and is the same colour as the fill while the tab is hovered. A keyboard
reader will find the ring hard to see there; where that matters most, choose another variant.

A scroll button that has just run out of anything to scroll to stays visible, marked
`aria-disabled` rather than natively `disabled`, for exactly as long as it still has keyboard focus
— a natively disabled button is dropped from the page the instant it becomes disabled, taking focus
with it (confirmed live: it really does, in a real browser, not only in principle).

</Callout>

## Code examples

```tsx
<Tabs defaultValue="overview">
  <Tabs.List aria-label="Project">
    <Tabs.Trigger value="overview">Overview</Tabs.Trigger>
    <Tabs.Trigger value="activity">Activity</Tabs.Trigger>
    <Tabs.Trigger value="settings" disabled>Settings</Tabs.Trigger>
  </Tabs.List>
  <Tabs.Content value="overview">A summary of the project.</Tabs.Content>
  <Tabs.Content value="activity">Recent changes to the project.</Tabs.Content>
</Tabs>

{/* Vertical on a wide screen, horizontal below the md breakpoint */}
<Tabs defaultValue="overview" orientation={{ base: "horizontal", md: "vertical" }} variant="subtle">
  {/* ... */}
</Tabs>

{/* Controlled, and kept in the URL so a tab can be shared */}
function Example() {
  const [tab, setTab] = useTabFromUrl("overview");
  return (
    <Tabs value={tab} onValueChange={setTab}>
      {/* ... */}
    </Tabs>
  );
}

{/* A count next to the label, and an icon-only tab */}
<Tabs.Trigger value="inbox">Inbox <Badge size="sm">12</Badge></Tabs.Trigger>
<Tabs.Trigger value="settings" icon={GearIcon} aria-label="Settings" />

{/* A native <button> attribute on Tabs.Trigger, passed straight through */}
<Tabs.Trigger value="reports" onFocus={() => prefetchReports()}>Reports</Tabs.Trigger>

{/* Keep a panel's state while its tab isn't selected */}
<Tabs.Content value="details" forceMount>
  <form>{/* ... */}</form>
</Tabs.Content>
```
