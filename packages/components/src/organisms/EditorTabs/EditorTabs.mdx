<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="EditorTabs" tier="Organism" />

A tab strip for tabs a person opens, closes and arranges themselves: the files open in an editor, the records open in a
workspace, the views someone has saved. It is given as data (`tabs`, an array of `{ id, label, … }`) rather than written
as one element per tab, because the set of tabs is part of the person's own working state and changes while they work.
It is built on `Tabs`, so it keeps that component's looks (`variant`, `size`, `rounded`), its single tab stop with
arrow-key movement, and its scrolling with a fade and buttons when the tabs outgrow the width.

`EditorTabs` owns no list. `tabs` is the order and the contents, and `onClose`, `onAdd` and `onReorder` *ask* for a change:
the strip shows whichever array it is given next, so your state stays the single source of truth. A tab can be closed with
its close button, the Delete key, or a middle-click; added with the add button; moved by dragging it (with a mouse or pen)
or with the keyboard; and acted on with a single press through `tabMenu`, the strip's own menu (Close, Close others, Close
tabs after this one, Close all, and the moves). A tab can be marked `dirty` (unsaved changes), `pinned` (kept at the
start) or `status` (busy, error, warning), and can show a tooltip. The strip can run vertically, binds the shortcuts you
choose, and eases tabs to their new places when the list changes. Panels are optional: draw the content yourself from the selection, or put
`EditorTabs.Panel` elements inside the strip.

## Properties

`ref` forwards to the root `<div>`, and `className`, `style`, `id` and `data-testid` land there too. Also accepts any other native `<div>` attribute beyond what's
listed here (e.g. `onFocus`, `title`) — passed straight through to the root element.

<PropertiesTable of={EditorTabsStories} order={rootPropOrder} />

Each item of `tabs` takes `id` (unique and stable), `label` (what is shown; a string or number also names the tab for a screen reader),
`icon`, `title` and `tooltip` (detail shown in a tooltip; `tooltip` wins), `dirty`, `pinned`, `closable`, `disabled`, `status`
(`"busy"`, `"error"` or `"warning"`, with `statusText` to say it in your own words) and `aria-label`. Any field you add comes back
in every callback. A tab is closable when `onClose` is given, unless it is pinned; set `closable` to override either way.

`onReorder(from, to, via)` gives positions in `tabs` as it is now, so `move(tabs, from, to)` applies it. `onCloseMany(tabs, via)` gets the
tabs that were asked to close together (Close others, Close all), already limited to those that can be closed: remove them from `tabs` in one update.
`controllerRef` receives
`{ select(id), close(id), closeMany(ids), add(), move(id, to), focus(id) }`: one object for the strip's life, whose methods ask the way a press does
and return whether there was something to do.

### EditorTabs.Panel properties

Draw panels as direct children of `EditorTabs`, or inside a fragment. A panel wrapped in another component is not found, so its tab does not point at it with `aria-controls`.

A panel is `Tabs.Content`: it shows while the tab with the same `id` is selected. Also accepts any other native `<div>` attribute beyond what's listed here (e.g. `title`) — passed straight through to the underlying element.

## Usage guidelines

**Do**

- Use it where the tab set belongs to the person: open files, open records, saved views, comparison workflows. Use `Tabs` for a fixed set of views the page defines.
- Apply `onClose`, `onAdd` and `onReorder` to your own array; the strip changes only when `tabs` does.
- Give every tab a stable, unique `id` (a file path, a record id), not its position.
- Mark a tab `dirty` while it holds unsaved changes, and ask the person before `onClose` removes it.
- Put pinned tabs first in `tabs`.
- Turn on `tabMenu` wherever `onClose` or `onReorder` is given, and give it `onCloseMany`: it is how a person on a touch screen, or with a screen reader, closes or moves a tab.
- Bind `hotkeys` to combinations the page can receive, such as Control and Option (`ctrl+alt+ArrowRight`), not the browser's own: Ctrl+Tab and Ctrl+W, and on a Mac ⌘⌥ with the arrow keys or W, which the browser uses to change and close its own tabs and never passes on. `mod` (⌘ on a Mac, Ctrl elsewhere) is safe only with keys the browser leaves alone.
- Say how a tab is doing with `status` while it saves or when it fails, and `dirty` while it holds changes.

**Don't**

- Don't use it for navigation between the pages of a site: that is `Navbar` or `Sidebar`.
- Don't put the close button's operation only on the pointer. It is hidden from assistive technology on purpose; the Delete key and the tab menu are the other ways.
- Don't put a long description in `tooltip`: it is a hint, shown on hover and focus, and is not read as part of the tab's name.
- Don't expect a tab to jump between strips, nest, or be dragged across the pinned boundary.
- Don't use more than a handful of pinned tabs: they stay at the start and take its room.

## Best practices

- **Closing is your decision.** `onClose` is a request. Remove the tab from `tabs` when it is fine to go; leave it when a dialog is asking about unsaved changes. The selection moves to a neighbour only once the tab has actually gone.
- **Say what you select afterwards.** The default (`closeSelects="neighbor"`) selects the next tab, or the one before it when the last closed. `"previous"` goes back to the tab that was selected before; with nothing to go back to it falls back to a neighbour. Set `"none"` when the app has its own rule.
- **Close several in one update.** `onCloseMany` is given the tabs together so one change to `tabs` removes them all and the strip chooses what to select once, not once per tab.
- **Keep content mounted when it is costly to rebuild.** `forceMount` on a panel keeps an editor's undo history and scroll position while another tab is shown; leave it off for a panel that is cheap to draw.
- **Name tabs by text.** A string label is announced as the tab's name; a label that is not text needs an `aria-label` or a `title`.
- **A long strip is fine; keep what you pass stable.** Each tab is drawn only when its own fields change, so selecting a tab, dragging one and announcing a close redraw only the tabs involved, and a strip of a thousand tabs stays responsive (closing or adding a tab redraws the ones after it). A list rebuilt on every render is fine too, since tabs are compared field by field, but a `label` that is a new element every render, and a `labels` or `menuPresentation` object written inline, count as changes: define them once, or in `useMemo`.
- **Use `overflow="menu"` for many tabs.** Scrolling alone makes a far tab slow to reach; the menu lists them all.

## Accessibility

`EditorTabs` is a WAI-ARIA tabs pattern: a `tablist` of `tab`s, each pointing at its panel when one is drawn. The close and add buttons sit beside the tabs, and the close button is not part of the tab list for assistive technology.

| Key | Action |
|---|---|
| `Tab` | Enters the strip on the selected tab (one tab stop), and leaves it |
| `←` `→` | Move focus between tabs (flipped right to left); `↑` `↓` also work for a vertical flow |
| `Home` `End` | First and last tab |
| `Enter` `Space` | Select the focused tab (when the tabs are not selected on focus) |
| `Delete` | Close the focused tab, if it can be closed |
| `Alt` + `←` `→` | Move the focused tab one place |
| `Space` on a tab | Pick the tab up to move it; `←` `→` `Home` `End` move it, `Space` or `Enter` drops it, `Escape` puts it back |
| `↑` `↓`, `Alt` + `↑` `↓` | The same movement and reordering in a vertical strip |
| Context-menu key, `Shift` + `F10` | Open the tab's menu, when `tabMenu` or `tabContextMenu` is given |
| Your `hotkeys` | Select the next or previous tab, close the selected tab, add a tab, from anywhere on the page |

- A pick-up, move, drop and cancel are announced through a polite live region, as is a tab (or several) the strip was asked to close once they have gone, with text from `labels` and numbers from `formatNumber`. Replacing the whole list is not a close and announces nothing.
- A tab that holds unsaved changes, is pinned, or is busy or in error says so in its name ("App.tsx (unsaved changes, save failed)"), so the state is never carried by the dot, the pin, the spinner or the colour alone.
- A tab's tooltip is the system's tooltip: it opens on hover and keyboard focus, closes on Escape, and describes the tab without being part of its name. A tab with detail of its own, or a cut-short name, gets one; a short name with nothing to add does not.
- Tabs ease to their new places and a new tab fades in; under `prefers-reduced-motion` neither is animated.
- The close button is a pointer shortcut: it is out of the tab order and hidden from assistive technology, because a tab list may only hold tabs. The same operation is the Delete key and the tab menu. A tab that can be closed has `aria-keyshortcuts="Delete"`.
- A press on a touch screen scrolls the strip, so dragging is for a mouse or pen. A person on a touch screen closes or moves a tab through the tab menu (`tabMenu`), opened by a long press.
- Every close and add button is at least 24 × 24 px. Disabled tabs are skipped by the arrow keys.
- The selected tab and the drop marker keep their meaning in forced-colours mode.

## Code examples

### A strip that closes, adds and reorders

```tsx
const [tabs, setTabs] = useState([
  { id: "index", label: "index.ts" },
  { id: "app", label: "App.tsx", dirty: true },
]);
const [open, setOpen] = useState("index");

<EditorTabs
  aria-label="Open files"
  tabs={tabs}
  value={open}
  onValueChange={setOpen}
  onClose={(tab) => setTabs(tabs.filter((t) => t.id !== tab.id))}
  onReorder={(from, to) => setTabs(move(tabs, from, to))}
  onAdd={() => setTabs([...tabs, { id: crypto.randomUUID(), label: "untitled.ts" }])}
/>;
```

### Refusing to close a tab with unsaved changes

```tsx
<EditorTabs
  tabs={tabs}
  value={open}
  onValueChange={setOpen}
  onClose={(tab) => {
    // Leave the tab in `tabs` until the person has answered.
    if (tab.dirty) askToSave(tab).then((ok) => ok && setTabs(tabs.filter((t) => t.id !== tab.id)));
    else setTabs(tabs.filter((t) => t.id !== tab.id));
  }}
/>
```

### Closing several tabs at once

```tsx
<EditorTabs
  tabs={tabs}
  value={open}
  onValueChange={setOpen}
  onClose={(tab) => setTabs(tabs.filter((t) => t.id !== tab.id))}
  onCloseMany={(closing) => setTabs(tabs.filter((t) => !closing.includes(t)))}
  tabMenu
/>
```

### Shortcuts

```tsx
<EditorTabs
  tabs={tabs}
  value={open}
  onValueChange={setOpen}
  hotkeys={{ next: "ctrl+alt+ArrowRight", previous: "ctrl+alt+ArrowLeft", close: "ctrl+alt+w" }}
/>
```

### Native attributes on the root

```tsx
<EditorTabs tabs={tabs} value={open} title="Open files" onFocus={() => log("strip focused")} />
```
