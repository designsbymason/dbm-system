<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Timeline" tier="Organism" />

A timeline is a record of things that happened, one after another: an order's tracking history, an audit
trail, a changelog, an activity feed. A compound component: put one `Timeline.Item` per event inside
`Timeline`, in the order you want them read. Each event has a marker (a plain dot, an icon, or anything of
your own such as an `Avatar`), a title, a time, and an optional description and body, joined to the next
event by a line.

`Timeline` is a read-out, not a flow. It has no current position and nothing in it can be pressed, which is what
separates it from `Stepper`; links and buttons you put in an event's body are yours. It does not sort, fetch
or format dates: the order is the order of its children, and a time is the text you pass. An event still under
way is `pending`, and a long history can be capped with `maxVisible`, with a button for the rest.

Choose how big it is with `size`, how the markers look with `variant`, their colour with `tone` (and on an item
for one event), the line with `connector` (and `colorfulConnector`, to draw it in each event's tone), which way it
runs with `orientation`, whether the content sits on one side of the line or alternates with `align`, and where the time
goes with `timePlacement`. A colour says nothing to a screen reader, so say what it means in words with an item's
`statusText`.

Around the events: `Timeline.Group` puts a heading before a run of them ("Today"), `Timeline.End` marks where it
stopped, an item's `href` or `onPress` makes the whole event a link or a button, and its `detail` keeps more of it behind
a button. For a history you page yourself, `onLoadMore` draws a "load more" button, `loading` draws placeholders, and
`empty` says what an empty one shows. `announce` says when events are added, and `formatRelativeTime` writes "2 hours
ago" for a time.

### Import

```tsx
import { Timeline } from "@dbm-system/components";
```

## Properties

Every event reads `size`, `variant`, `tone`, `connector` and `timePlacement` from `Timeline`, so they are set once,
on the root (an item may set its own `tone` and `connector`). `ref` forwards to the `<ol>`. Also accepts any other native `<ol>` attribute
beyond what's listed here (e.g. `dir`, `title`) — passed straight through to the root element.

<PropertiesTable of={TimelineStories} order={rootPropOrder} />

Only `Timeline.Item`, `Timeline.Group` and `Timeline.End` elements are drawn: a fragment, or plain text, placed among
the children is ignored (with a warning in development), so build the list from those directly. Give them a stable `key`
when you map over data. `maxVisible` draws only that many events, and a button for the rest; events past it are not rendered at all.
There is no windowing, because events have different heights: a history of hundreds is better paged by your own code
(load the next page, then add its items).

`align="alternate"` works from the `md` breakpoint (768px) up; on a narrower screen every event is on one side, so what is
read stays in one column (below the line, when horizontal). `timePlacement` has two sets of values: a vertical timeline
reads `"top"` and `"side"`, and a horizontal one `"same"` (on the same side of the dot as the content, above the title)
and `"opposite"` (on the other side of the dot, with `align="alternate"` alternating along with the content); a value for
the other orientation is read as the default. A horizontal timeline scrolls sideways when its events are narrower than
the `timeline.item-min-width` token allows; while it scrolls the row is
a tab stop, so a keyboard can scroll it. `loading` with no events stands placeholders in for the list; with events it adds
them after the last one and busies the "load more" button. `announce` says "N new events" when events are added to a
timeline that is showing, never on its first render, and never for events a "show more" reveals.

### Timeline.Item properties

One event — the `<li>`. Its marker and line are hidden from assistive technology. Also accepts any other native `<li>`
attribute beyond what's listed here (e.g. `onClick`) — passed straight through to the underlying element.

<PropertiesTable of={TimelineItemStories} order={itemPropOrder} />

With `href` the title is a link and with `onPress` a button, stretched over the whole event so a press anywhere on it
counts; a link or button you put in `children` or `detail` sits above it and still takes its own press. `href` wins when
both are set, and either needs a `title`. A keyboard ring is drawn once, around the whole event.

### Timeline.Group properties

A heading for the run of events after it, drawn in the text column with the line passing by. It is a list entry that
announces itself as a heading, not a container: the events are the entries after it, up to the next heading. It is drawn
only while an event after it is, so `maxVisible` never leaves a heading over nothing. Also accepts any other native `<li>`
attribute beyond what's listed here (e.g. `onClick`) — passed straight through to the underlying element.

<PropertiesTable of={TimelineGroupStories} order={groupPropOrder} />

### Timeline.End properties

Where the timeline stopped: a bar across the line (or an icon in a disc) and the words you give it. The line stops there.
It is drawn only once every event is shown. Also accepts any other native `<li>` attribute beyond what's listed here (e.g.
`onClick`) — passed straight through to the underlying element.

## Usage guidelines

<div style={{ display: "grid", gridTemplateColumns: "repeat(auto-fit, minmax(16rem, 1fr))", gap: "var(--dbm-space-4)" }}>
<Callout tone="success" title="Do">

- Use it for a history a person reads, newest first or oldest first: an order, an audit trail, an activity feed.
- Keep a title to what happened, in a few words, and put detail in `description` or the body.
- Say what a tone means with `statusText` ("Failed", "Approved"), since the colour reaches only the eye.
- Mark the event still under way as `pending`, and put it first when newest is first.
- Give the list a name with `aria-label` or `aria-labelledby` when a page has more than one.
- Group a long feed with `Timeline.Group` ("Today", "Yesterday") rather than repeating the date in every time.
- Use `align="alternate"` for a short, wide, presentation-style history; it is a wide-screen layout only.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for progress through a flow with a current step — that is `Stepper`.
- Don't use it for key/value facts about one thing — that is `DescriptionList`.
- Don't use a tone as the only sign that something failed or succeeded.
- Don't put controls in the markers; the markers are hidden from assistive technology.
- Don't expect it to sort: pass the events in the order to read them.
- Don't put a long body in every event when `detail` would keep it out of the way until it is asked for.
- Don't use `orientation="horizontal"` for more than a handful of events: it scrolls, and a vertical list reads better.

</Callout>
</div>

## Best practices

- `Timeline` owns no data. Map your events to items, with a stable `key`, in the order to read them; it never reorders them, so what is on screen is what a screen reader reads.
- Pass the time as the text you want shown ("2 hours ago", "14 Mar, 09:30"), and add `dateTime` with the machine-readable value so it becomes a `<time>` element. Format dates in your own code, in your own locale.
- Use `maxVisible` for a history that is long but not huge. For a feed that grows without end, load a page at a time and add its items; a timeline has no windowing.
- A person reading from the top finds the newest event first in most feeds; an order's history often reads oldest first. Either is fine, as long as the line, which always runs down, reads the same way as the order of the children.
- Put a link in an event's body for "open the order"; don't make the whole event a link.
- A `pending` event reads "In progress" after its title; give it its own `statusText` when another word is better ("Waiting for the courier").
- Events added while the page is open are not announced unless you set `announce`, which says "N new events" in a polite live region. Leave it off where a reader should not be interrupted.
- For a history you page yourself, hold the events in your own state: `onLoadMore` asks for the next page, `loading` shows placeholders while it comes, and `hasMore={false}` hides the button once everything is in. Add the new events to the end of the list.
- `formatRelativeTime(date)` writes "2 hours ago" once, in the language you name (`{ locale: "fr" }`); it does not tick, and a server render and the browser can differ by the time between them, so use it where that does not matter. Keep the exact value in `dateTime`.
- Use `Timeline.End` when how it ended is worth saying ("Order closed"); an end on a timeline that is still going would mislead.

## Accessibility

<Callout tone="info" title="An ordered list of events, with the marker and line hidden and the meaning in words">

The timeline is an `<ol>` with its `list` role stated outright, and each event an `<li>` with its `listitem` role
stated outright, because Safari with VoiceOver otherwise stops treating a list with its markers removed as one. A
screen reader announces how many events there are and which one it is on. It is not a landmark: name the list with `aria-label` or `aria-labelledby`
when a page holds more than one. The marker and the line are `aria-hidden`; an event's accessible content is its time, its
title, its description and its body, in that order, and a `statusText` or the pending words are read right after the title,
so the meaning of a colour never relies on seeing it. A time with a `dateTime` is a `<time>` element.

There is no keyboard interaction of its own. Events are not focus stops, so `Tab` moves through the links and buttons in their
bodies in reading order, and the focus order and the visual order are the same, since the time can sit beside the marker but
the markup never reorders. The button that shows the events past `maxVisible` is a native button; it keeps the focus when it
changes from "Show 3 more events" to "Show fewer events", and a polite live region says how many events appeared when they are shown (only a change,
never the first render). If you collapse a timeline from your own code while focus is in an event that disappears, move the focus
yourself.

A `Timeline.Group` announces itself as a heading at the level you give it (3 by default), so it fits the page's outline; it is a list entry, so a screen reader counts it among the items. `Timeline.End` is a list entry too. The placeholders `loading` draws are hidden from assistive technology and the list is `aria-busy` while they show. An event's `detail` button is a disclosure (`aria-expanded`, `aria-controls`) with a fixed name, "Details" (`labels.details`), and the closed content is not drawn or read. With `href` or `onPress` the event's title is a real link or button, stretched over the event with a pseudo-element, so there is still one focus stop per event and the accessible name is the title (and its status text); one keyboard ring goes round the whole event. `announce` says "N new events" in a polite live region, only when events are added to a timeline that is already showing. A "load more" button that is pressed and becomes disabled while it loads hands its focus back to itself when loading ends, if the browser dropped it.

A horizontal timeline that scrolls is a tab stop while it scrolls, with its ring drawn inside its box, so a keyboard can scroll it with the arrow keys. `align="alternate"` changes only where the content is drawn: the markup and so the focus and reading order are the same as without it.

| Key | Behaviour |
|---|---|
| `Tab` | Moves through the focusable things in the events (a linked or pressable event's title, a `detail` button, links and buttons in a body), then to the show-more and load-more buttons when there are any; a scrolling horizontal row is itself a stop before them |
| `Enter` / `Space` | Presses the focused button, or follows (Enter) the focused link |

In forced-colours mode the line is drawn as a border in `GrayText`, and each marker is a `CanvasText` dot or ring (a pending one in `Highlight`), since a
filled background is erased. Every target is the browser's own control inside an event's body; the show-more button is a `Button` at least 24 by 24 pixels at every size.

</Callout>

## Code examples

```tsx
{/* An order's history, oldest last, with the part still under way first */}
<Timeline aria-label="Order 1042" tone="success">
  <Timeline.Item title="Out for delivery" time="Today, 08:15" dateTime="2026-03-14T08:15" icon={TruckIcon} pending />
  <Timeline.Item title="Shipped" time="Yesterday, 17:40" dateTime="2026-03-13T17:40" statusText="Done">
    <Link href="/track/1Z999">Track the parcel</Link>
  </Timeline.Item>
  <Timeline.Item title="Order placed" time="12 Mar, 14:22" description="Paid by card" statusText="Done" />
</Timeline>
```

```tsx
{/* An audit trail that shows the latest five, then the rest on request */}
<Timeline aria-label="Changes" maxVisible={5} timePlacement="side" size="sm">
  {changes.map((change) => (
    <Timeline.Item
      key={change.id}
      title={change.summary}
      time={change.when}
      dateTime={change.iso}
      marker={<Avatar name={change.author} size="xs" />}
      tone={change.failed ? "danger" : undefined}
      statusText={change.failed ? "Failed" : undefined}
    />
  ))}
</Timeline>
```

```tsx
{/* A feed that pages: your own state holds the events, the timeline asks for more and shows placeholders meanwhile */}
<Timeline aria-label="Activity" loading={isFetching} hasMore={hasNextPage} onLoadMore={fetchNextPage} announce>
  {/* Parts are direct children (a fragment is not drawn), so flatten each day into one list */}
  {days.flatMap((day) => [
    <Timeline.Group key={day.date}>{day.label}</Timeline.Group>,
    ...day.events.map((event) => (
      <Timeline.Item
        key={event.id}
        title={event.title}
        time={formatRelativeTime(event.at)}
        dateTime={event.at.toISOString()}
        href={`/events/${event.id}`}
      />
    )),
  ])}
</Timeline>
```

```tsx
{/* Native props: a name from a heading, and a direction */}
<h3 id="history">History</h3>
<Timeline aria-labelledby="history" dir="rtl" data-testid="history-list">
  <Timeline.Item title="Created" time="12 Mar" />
</Timeline>
```

```tsx
{/* Text the component writes, in your language, with your own digits */}
<Timeline
  aria-label="Historique"
  maxVisible={2}
  formatNumber={(n) => new Intl.NumberFormat("fr").format(n)}
  labels={{ showMore: (hidden) => `Afficher ${hidden} de plus`, showLess: "Afficher moins", pending: "En cours" }}
>
  {/* … */}
</Timeline>
```
