<ComponentHeader title="Menubar" tier="Organism" />

A desktop-style bar of menus (File, Edit, View) for the commands of an application window or an editor. Built on Radix
Menubar, so one tab stop, the arrow keys between triggers, a menu that opens onto its first item, and a hover or arrow
that moves from one open menu to the next come with it, as do checkbox and radio items, labelled groups and submenus.
Its items are `Menu`'s, drawn the same. A compound component: put a `Menubar.Menu` (named by its `value`) per menu inside
`Menubar`, each holding a `Menubar.Trigger` and a `Menubar.Content`, and the items, labels, groups and separators inside
the content.

A menubar is a desktop pattern: it suits an app that holds many commands behind a few headings, and it expects a
keyboard and a pointer. A site's navigation is `NavigationMenu` or `Navbar`, a single button of actions is `Menu`, and a
row of buttons is `Toolbar`.

### Import

```tsx
import { Menubar } from "@dbm-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use a `Menubar` for the commands of an application window or editor, grouped under a few short headings (File, Edit,
  View, Help) that people already know.
- Name the bar with `aria-label` ("Application menu"); a page with more than one needs one on each.
- Keep each trigger's label to one word, so the bar stays short and typeahead is unambiguous.
- Put the destructive action last in its menu, after a `Menubar.Separator`, with `tone="danger"`.
- Bind the keys a `shortcut` hint shows yourself, and open a menu from your own key (Alt+F for File) with the bar's `value`.
- Give each `Menubar.Menu` a stable `value`: it is what `value` and `onValueChange` report.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a site's navigation: that is `NavigationMenu` or `Navbar`, which are links, not commands.
- Don't use it as a single button of actions: that is a `Menu`. A bar of one trigger is a `Menu` with extra steps.
- Don't rely on a `shortcut` hint to make a key work. It only displays the key; bind it yourself.
- Don't put a form or arbitrary content in a menu. A menu holds `menuitem`s only.
- Don't count on it on a phone: it expects a keyboard and a pointer, and there is no sheet presentation. Show a `Menu`
  or a `NavigationMenu` from a button on a touch screen.
- Don't hide an action that only the menubar offers: also put anything people need often within reach on the page.

</Callout>
</div>

## Best practices

- Order the menus as people expect (File, Edit, View, then the app's own, Window, Help) and the items in each by how
  often they are used, grouped with `Menubar.Label` and `Menubar.Separator` past about seven.
- A leading `icon` helps recognition when most items have one; give every item in a set one, or none.
- The bar leaves the page usable behind an open menu, as a native menu bar does; a press elsewhere closes it and keeps the
  focus that press gave.
- A bar wider than its container scrolls sideways, with a fade at each end that has more behind it, and keeps the focused
  trigger in view. Prefer fewer, shorter menus to a bar that scrolls.
- `tone` colours the triggers' hover and open fills and, on an `outlined` or `filled` bar, its border and fill, all from subtle tokens (the trigger label is `text.primary` in both tones): `brand` (the default) suits an application's own chrome, `neutral` a bar that should sit back. It does not change the menus the bar opens, which keep `Menu`'s look.
- `size` sets the trigger height and the row size of its menus; give a `Menubar.Content` its own `size` only to differ.
- A menu taller than the room there is scrolls inside its panel, with a fade at each end that has more behind it. The panel flips to
  stay inside the viewport; give it `collisionPadding` where a fixed header or footer covers the edge.

## Accessibility

<Callout tone="info" title="Keyboard and ARIA state come from Radix's menubar primitive">

- The bar is `role="menubar"` and each trigger a `menuitem` with `aria-haspopup="menu"` and `aria-expanded`. Each panel is
  `role="menu"`, named after its trigger, and holds `menuitem`, `menuitemcheckbox` and `menuitemradio` elements.
- The bar is one tab stop: `Tab` enters it on the trigger last used and leaves it from there; the arrow keys move between
  triggers (`ArrowLeft` and `ArrowRight`, swapped in right-to-left text), skipping disabled ones and wrapping unless `loop` is off.
- `Enter`, `Space` and `ArrowDown` open a menu onto its first item; `ArrowUp` opens it onto its last. `Escape` closes the menu
  (one level of submenu at a time) and returns focus to its trigger.
- With a menu open, `ArrowLeft` and `ArrowRight` move to the previous or next menu, and moving the pointer onto another
  trigger opens that one. Inside a panel, `ArrowDown` and `ArrowUp` move between items, skipping disabled ones, `Home` and
  `End` jump to the first and last, and typing letters moves to the item that starts with them.
- `ArrowRight` opens a submenu and `ArrowLeft` closes it, swapped in right-to-left text (`dir="rtl"`).
- A `description` is announced as the item's description, not as part of its name. A `disabledReason` keeps the item focusable and
  `aria-disabled`, shows the reason in a tooltip and announces it as the description. An item with a pending action is
  `aria-busy` and `aria-disabled`, and ignores presses until it settles.
- A `Menubar.Label` inside a `Menubar.Group` or `Menubar.RadioGroup` names that group through `aria-labelledby`, wired automatically.
- The focused trigger and item show a ring in the focus colour drawn inside them. The open menu's trigger is tinted; in forced-colours
  mode it gets an outline in a system colour.
- Every trigger and item is at least 24 × 24 CSS pixels at every size.
- The page behind an open menu stays usable, so a press elsewhere closes the menu and keeps the focus it gave.

</Callout>

## Code examples

```tsx
{/* An application menu bar */}
<Menubar aria-label="Application menu">
  <Menubar.Menu value="file">
    <Menubar.Trigger>File</Menubar.Trigger>
    <Menubar.Content>
      <Menubar.Item icon={PencilSimpleIcon} shortcut="F2" onSelect={rename}>Rename</Menubar.Item>
      <Menubar.Item icon={CopyIcon} onSelect={duplicate}>Duplicate</Menubar.Item>
      <Menubar.Separator />
      <Menubar.Item icon={TrashIcon} tone="danger" onSelect={remove}>Delete</Menubar.Item>
    </Menubar.Content>
  </Menubar.Menu>
</Menubar>

{/* Open a menu from your own key: hold the open menu in state */}
function AppMenu() {
  const [open, setOpen] = useState("");
  useEffect(() => {
    const onKeyDown = (event: KeyboardEvent) => {
      if (event.altKey && event.code === "KeyF") setOpen("file");
    };
    document.addEventListener("keydown", onKeyDown);
    return () => document.removeEventListener("keydown", onKeyDown);
  }, []);
  return (
    <Menubar aria-label="Application menu" value={open} onValueChange={setOpen}>
      <Menubar.Menu value="file">
        <Menubar.Trigger>File</Menubar.Trigger>
        <Menubar.Content>
          <Menubar.Item>New</Menubar.Item>
        </Menubar.Content>
      </Menubar.Menu>
    </Menubar>
  );
}

{/* A checkbox item leaves the menu open, and a radio group does too */}
<Menubar.CheckboxItem checked={showGrid} onCheckedChange={setShowGrid}>
  Show grid
</Menubar.CheckboxItem>
<Menubar.RadioGroup value={layout} onValueChange={setLayout} aria-label="Layout">
  <Menubar.RadioItem value="list">List</Menubar.RadioItem>
  <Menubar.RadioItem value="grid">Grid</Menubar.RadioItem>
</Menubar.RadioGroup>

{/* An action that takes time: a spinner shows and the menu closes when the promise resolves */}
<Menubar.Item onSelect={() => exportRows()} onSelectError={(error) => showError(error)}>
  Export as CSV
</Menubar.Item>

{/* A native <button> attribute on a trigger, passed straight through */}
<Menubar.Trigger title="File commands">File</Menubar.Trigger>
```
