<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="DateRangePicker" tier="Organism" />

A start date and an end date: two date fields side by side, each with separate day, month and year segments you type into
or step with the arrow keys, and one button that opens a calendar to choose the whole range from with a pointer or a
finger. The first date you choose is the start and the second the end. The value is one `["YYYY-MM-DD", "YYYY-MM-DD"]`
pair, with `""` for an end that is not chosen yet, whichever order the segments are written in. The order is chosen with
`format`, never read from the browser's locale, so a server-rendered page and the client agree. For a single date, use
`DatePicker`; for a time of day, `TimeRangePicker`.

### Import

```tsx
import { DateRangePicker } from "@dbm-system/components";
```

`onKeyDown`) — passed straight through to the group element that holds the two ends. `ref` forwards to that group, and the
`id` goes on the start's first segment, which is what a `FieldLabel`'s `htmlFor` should point at.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `DateRangePicker` for a stay, a booking window, a report period: a start and an end that belong together. For one
  day use `DatePicker`; for several separate days, a `Calendar` in `multiple` mode.
- Choose `format` for your users and say so explicitly; the pair never guesses it from the locale. The same goes for
  `weekStartsOn`.
- Use `min` and `max` for a window and `isDateDisabled` for gaps in it; the calendar disables what cannot be reached.
- Use `minRangeDays` and `maxRangeDays` for a shortest and longest stay, and `rangeSpansUnavailable={false}` when a
  range cannot run over a closed day: the calendar disables the end dates that would break them and a typed end that does
  is flagged with a message that says why.
- Use `unavailableReason` when people will wonder why a day is greyed out ("Fully booked"): it is read out, shown under
  the calendar and used as the form's message.
- Use `presets` for the periods people pick most ("Last 7 days", "This year").
- Use `presentation={{ base: "full-width", sm: "anchored" }}` where the pair is used on a phone: the panel spans the
  screen instead of floating beside a narrow field. One month is shown on a phone and two beyond it by default.
- Put it in a `FormField` for a visible label, helper text and error text wired together.
- Pass `labels` and `formatNumber` for a language that isn't English or digits that aren't 0–9, and the calendar's own
  `labels` through `calendarProps` for its month and weekday names.

</Callout>
<Callout tone="danger" title="Don't">

- Don't store or compare the displayed text. The value is a `"YYYY-MM-DD"` pair, and an end is `""` while it is only
  partly filled or holds numbers that are not a real date (the 31st of February).
- Don't treat a `min`/`max` or length violation as refused input: the pair flags it and still reports it, so your own
  validation decides what to do.
- Don't build your own "is it filled in?" check for a plain form: `required`, a half-filled end, an impossible date and a
  date the pair flags are real form constraints, so the browser blocks the submit.
- Don't convert a value through `new Date("2026-10-03")` and then read it in local time: that string is read as UTC
  midnight and can show the day before. Split the string, or use a UTC formatter.
- Don't mix the two kinds of value: `granularity` decides whether the pair takes whole dates or months, and a value of the
  other kind reads as empty.
- Don't use it for a date and a time; put a `DatePicker` and a `TimePicker` side by side.

</Callout>
</div>

## Best practices

- The first date chosen in the calendar is the start and the calendar stays open for the end, so by default
  `onValueChange` is called with `[start, ""]` and then with the whole range. Set `commitOn="complete"` or `"blur"` to
  hear only about a finished range (or what was chosen when the calendar closes); a preset and the clear button are
  always reported at once.
- Typing works the way a native date field does, for each end: a digit that can't start a two-digit number is the whole
  number and moves on, one that can waits for a second, and the year takes four. A separator key finishes the segment.
- The end can never be before the start: an end that is is reported as typed and flagged on that end. The start is not
  flagged for being after the end, since it would flag whenever the end is half typed.
- The calendar opened from the button, or from a start that has no end yet, starts a new range with the first date you
  choose (or ends the one in progress). Opened with `Alt`+`ArrowDown` from a segment of the end, it chooses the end and
  leaves the start where it is; opened the same way from the start of a whole range, it chooses the start and keeps the
  end, unless the date is after the end or would break a length limit, in which case it starts a new range. Closing it
  without a choice changes nothing.
- A range needs both ends: once one end holds a date, the other is required in a form whether or not the pair is, so a
  half range cannot be submitted. An empty pair can be, unless `required`.
- Use `granularity="month"` for a period of whole months (a billing period, a report from March to June): each end is a
  month and a year, the panel is a grid of months, and the value is `["YYYY-MM", "YYYY-MM"]`. The length limits,
  `numberOfMonths` and `calendarProps` have no effect by month, and the grid does not show the months between the ends.
- A range chosen is said aloud ("Dates chosen: 10/05/2026 to 10/09/2026") through a status region that is in the page from
  the start.
- `onFocus` and `onBlur` are for the pair as a whole: they fire once on arriving and once on leaving, not as focus moves
  between the ends, the buttons and the calendar.
- Use `container` when the panel would be clipped or must live somewhere else (an element inside a dialog or a shadow
  root, or a box that scopes a demo).
- The clear button shows while either end shows anything, a half-typed segment included, and empties both ends.
- A preset's function is asked for its range only once today is known, so a server-rendered preset button starts disabled
  and is enabled after the first render in the browser.
- `rounded` draws the calendar's days (the chosen days, today's ring and the focus ring included) and its month buttons as
  circles, and the cells of the grid of months by month; the strip behind a range keeps its straight edges, and the fields'
  own corners do not change.
- In a table row or a toolbar, drop to `size="sm"` or `"xs"`; each end is as tall as an `Input` at the same step. The pair
  wraps, so on a narrow screen the end drops under the start.

## Accessibility

<Callout tone="info" title="A group of two groups of spinbuttons, with a dialog holding a range grid">

- The pair is a `role="group"` named by `aria-label` or `aria-labelledby` (a `FormField` supplies the label). Inside it are
  two groups, "Start date" and "End date", and each segment is an `<input role="spinbutton">` named for what it is (Day,
  Month, Year), with its range, current value and a text value announced.
- Each segment is its own tab stop, as in a native date field, then the clear button and the calendar button.
  `ArrowLeft`/`ArrowRight` move between segments of an end, `ArrowUp`/`ArrowDown` step the segment, `Home`/`End` go to its
  least and greatest, and `Backspace` clears it. `Alt`+`ArrowDown` in any segment opens the calendar.
- The calendar button is `aria-haspopup="dialog"` with `aria-expanded`, and `aria-controls` while the panel is open. It
  opens a `role="dialog"` holding a `Calendar` in range mode, which is a WAI-ARIA date grid: one tab stop, arrow keys by day
  and week, `Page Up`/`Page Down` by month. Focus goes to the chosen start (or today); choosing the end closes the panel,
  and `Escape` closes it, in both cases returning focus to where it was opened from (the segment, for `Alt`+`ArrowDown`;
  otherwise the button), except after a press elsewhere, which leaves focus wherever the person put it.
- A range's first and last days are named as such ("range start", "range end"), the days between them are marked, and an
  unavailable day keeps its place in the arrow-key order, is `aria-disabled`, and has its reason as part of its name.
- `hasError`, an out-of-range, unavailable or too-short or too-long end and an impossible date set `aria-invalid` on the
  segments of the end concerned (a group can't carry it); `required` sets `aria-required` on every segment.
- For a form, each end's value lives on a hidden `<input type="date">` that carries `required` and the validation messages,
  submitted as `name[]`; the browser's message points at the end, and focus goes to its first empty segment.
- Everything the pair says (end and segment names, "Empty", button names, form messages, the announcement) is in `labels`,
  and the digits it shows and announces go through `formatNumber`.
- The segments always read left to right, in a right-to-left page too, and the buttons and the calendar follow `dir`. In
  Windows high-contrast mode the focused segment is drawn in the system highlight colours.
- Every button is at least 24 × 24 pixels. A dev-mode console warning fires once per pair if it has no accessible name.

</Callout>

## Code examples

```tsx
<DateRangePicker aria-label="Stay" defaultValue={["2026-10-05", "2026-10-09"]} />

{/* Controlled, day first, a window, a length limit and no weekends */}
function Example() {
  const [range, setRange] = useState(["", ""]);
  return (
    <DateRangePicker
      aria-label="Booking"
      value={range}
      onValueChange={setRange}
      format="dmy"
      separator="."
      min="today"
      minRangeDays={2}
      maxRangeDays={14}
      isDateDisabled={(day) => new Date(day + "T00:00:00Z").getUTCDay() % 6 === 0}
    />
  );
}

{/* A form field with a visible label, helper text and an error */}
<FormField label="Stay" helperText="Check-in and check-out" error={error}>
  {(field) => <DateRangePicker {...field} />}
</FormField>

{/* Quick choices that are a function of today */}
<DateRangePicker
  aria-label="Report period"
  presets={[{ label: "Last 7 days", value: (today) => [daysAgo(today, 6), today] }]}
/>

{/* A native <div> attribute, passed straight through to the group */}
<DateRangePicker aria-label="Stay" title="Pick the dates of the stay" />

{/* Submitted with a form, as stay[]: start, then end */}
<form>
  <DateRangePicker aria-label="Stay" name="stay" required />
</form>
```
