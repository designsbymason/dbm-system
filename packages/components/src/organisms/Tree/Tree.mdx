<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Tree" tier="Organism" />

A tree shows a hierarchy as rows that open and close: a project's files, a set of categories, a permissions list. Give it
`nodes`, each with an `id`, a `label` and, when it has rows under it, `children`. A row with children has an arrow that opens
it; a row can have an icon, a quieter description and content at its end.

A tree can do more than show: `selectionMode` lets a person select one row or several, `checkable` gives every row a check box
(a row above others shows "indeterminate" when only some of the rows beneath it are checked), `hasChildren` marks a row whose
children you fetch when it is opened, and a long tree is drawn a window at a time (only the rows in view are on the page, so thousands
stay quick). It is one tab stop, the way a file browser is: `Tab` moves focus into the tree once and out of it again, and the arrow
keys move between the rows.

`Tree` is a read-out and a picker for data, not a navigation: a page's own links are `Sidebar`, whose groups are not a tree.
It does not sort, filter, fetch or reorder. The rows are drawn in the order you give them, and everything the person
changes (the open rows, the selection, the checks) is a list of ids that you may hold yourself. A chart of boxes and connectors
(an organisation chart) is a different kind of component.

## Properties

`ref` forwards to the element with `role="tree"`, with `id`, `data-testid` and the `aria-*` props. `className` and `style` go on the
outer box, the one that scrolls, so a margin or a width you set lands outside the tree in every mode. Also accepts any other native
`<div>` attribute beyond what's listed here (e.g. `onFocus`, `title`) — passed straight through to the `role="tree"` element.

A node is an object, not a component, so its fields have a table of their own, in the same style:

<FieldsTable rows={nodeFields} />

Row heights are fixed by `size` (`tree.row-height`), because a long tree is drawn a window at a time and so needs every row's
height without measuring it; a label that does not fit is cut with an ellipsis. `windowed="auto"` draws only the rows in
view from 200 visible rows, and only when `maxHeight` is set, since a window needs a box to scroll; `windowed` forces it on and
`windowed={false}` draws every row. Each row says its `aria-level`, `aria-posinset` and `aria-setsize`, so a window never
changes what a screen reader announces.

**Controlled and uncontrolled.** `expandedIds`, `value` and `checkedIds` each make that part controlled: a person's action
calls the matching `on…Change` and the tree changes only when the prop does. Without them the tree holds its own, from
`defaultExpandedIds` (or `defaultExpandAll`, which opens the rows that have rows to show and leaves a row still to be fetched closed), `defaultValue` and `defaultCheckedIds`. Switching one between the two warns in development. In `"single"` a `value` with more than one id warns, and only the first shows as selected.

**Checking.** `checkedIds` lists only the leaves (rows with nothing under them); a row with children is worked out from them, so
its own id is ignored. Checking a row checks every leaf under it that is not disabled, and checking it again clears them. A row waiting for its
children (`hasChildren`) counts as a leaf until they arrive.

**Lazy children.** Opening a `hasChildren` row calls `onExpandedChange`. Put its id in `loadingIds` while you fetch (a spinner
replaces the arrow and the row is `aria-busy`), then put the result in the row's `children`; the tree says how many arrived.
If the fetch finds nothing, give `children: []` and the open row shows a quiet, disabled "Empty" row under it (`labels.emptyFolder`),
so it does not look broken. If the fetch fails, put the id in `errorIds`: the arrow gives way to a warning mark, the row says
"Couldn't load. Press Enter to try again." (`labels.loadFailed`, part of its name) and a screen reader is told. Asking to open the
row again, from the mark, with Right or with Enter, calls `onRetry(id)`; take the id out of `errorIds` and into `loadingIds` as you
try again. A closed row that failed opens the ordinary way, through `onExpandedChange`.

**Loading the rows.** `loading` draws placeholder rows and marks the tree `aria-busy`. With no rows yet the placeholders stand in for the
tree (and for the empty message) and a screen reader hears `labels.loading`; with rows they follow the last one (in a long tree, the last
window). `loadingCount` (default 3) is held between 0 and 20. This is the tree's own first load: `loadingIds` is for one row's children.

**Searching.** The tree never filters. `filterTree(nodes, { query })` keeps the rows that match and the rows above them, and says which rows
to open (`expandedIds`) so a match is not hidden under a closed folder; pass its `nodes` as `nodes`, its `expandedIds` into `expandedIds`, and
the query as `highlightQuery`. With `keepDescendants` (the default) a folder that matches still shows what is in it. `match` takes a function
in place of the query. It never changes the nodes it is given, and a row whose children are all kept is the same object.

**A row's menu.** `onItemContextMenu` says which row a right-click, the context-menu key or Shift+F10 was for, and where (`point`, `element`,
`via`). The tree draws no menu and holds back nothing of the browser's: put it inside a `ContextMenu` (a `ContextMenu.Trigger asChild` round a `div`,
so a right-click and a long press open it natively), build the items from the `id`, and turn a key into a menu with the controller's
`openAt(point)`. Focus goes back to the row when the menu closes. A disabled row and the Empty row ask for nothing.

**Renaming.** With `renamable`, F2 on a row (or `controllerRef`'s `rename(id)`, for a "Rename" menu item) turns its label into a field with the text
selected. Enter commits, Escape cancels, and leaving the field commits, unless the text is refused, when it is dropped. An empty name and anything
`validateRename` returns a message for stay in the field with the message shown and `aria-invalid` set. The tree changes no label itself: `onRename(id, label)`
asks with the trimmed text, and the new label appears when you change `nodes` (leave it alone and the old one stays). While the field is open the
tree's keys (arrows, Space, letters) are the field's, and the row cannot be selected, opened or activated by a click in it.

**A picker, and a navigation pane.** `selectable: false` on a node makes a row that only holds others, so a tree of files lets a person open
folders but choose files. `expandOnClick` makes a plain click on a row with rows under it open or close it (a click with Ctrl, ⌘, Shift or Alt only
selects, and a double click does not undo it). `selectOnFocus`, in `"single"` mode, selects the row that focus lands on from the keys, so moving
through the tree changes the current item the way a navigation pane does; a row that cannot be selected leaves the selection alone. After a change
of selection in `"multiple"` a screen reader hears how many rows are selected (`labels.selectedCount`).

## Usage guidelines

<div style={{ display: "grid", gridTemplateColumns: "repeat(auto-fit, minmax(16rem, 1fr))", gap: "var(--dbm-space-4)" }}>
<Callout tone="success" title="Do">

- Use it for data that is genuinely nested and that a person browses or picks from: files, categories, permissions.
- Give every node a stable, unique `id` from your data, not its position.
- Name the tree with `aria-label` or `aria-labelledby`.
- Set `maxHeight` for a long tree, so it scrolls inside its own box and can be drawn a window at a time.
- Use `hasChildren` and `loadingIds` for a hierarchy too large to send at once.
- Filter `nodes` yourself for a search, and add `highlightQuery` to show why a row matched.
- Say with a node's `description` or `trailing` what a colour or an icon alone would say.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a page's navigation links — that is `Sidebar`, whose groups are links and ordinary tab stops.
- Don't put a button, link or field in `trailing`: a tree item is one focus stop, and a control inside it is a second.
- Don't use it for a table with expandable rows — that is `DataTable`.
- Don't nest more levels than a person can follow; deep trees are better searched than browsed.
- Don't repeat an `id`: selection, checks and the open rows are all lists of ids.
- Don't expect it to reorder rows or move them between parents; it asks nothing of the order you give it.

</Callout>
</div>

## Best practices

- `nodes` is often data on its way: a value that is not a list draws as an empty tree, a node that is not an object with a string `id` is left out, a `label` that is not text is written as text, and `children` that are not a list are ignored, each with one warning in development, never a crash.
- `Tree` owns no data. Hold the hierarchy in your own state, give it as `nodes`, and change the array to add, remove or rename rows; the open rows, the selection and the checks are separate lists of ids, so they survive.
- Use `selectionMode` to choose what a click does and `checkable` for a decision that applies to many rows at once (which folders to export). Both can be on: a click on the label selects, and a click on the box checks.
- `checkedIds` holds leaves only. To know which folders are fully checked, work them out from the leaves in your own code, or read each row's state in `renderLabel`.
- Hold `expandedIds` yourself when other parts of the page need to know (a breadcrumb, a saved layout), and leave it to the tree when they do not.
- For a very large tree, fetch a folder's children when it is opened (`hasChildren`) instead of sending everything, and keep the row's id the same when its children arrive.
- A label is one line and is cut with an ellipsis; put a long path in `description`, which is cut too, or give the tree room.
- Use `selectable: false` for a row that only holds others, so a picker offers files and not folders; add `expandOnClick` so a click opens it.
- A row's `renderLabel` replaces only the text. It is told the row's level and state so it can draw a count or a badge, but it must not hold a control.
- Use `loading` for the first fetch of the rows themselves, and `loadingIds` for one folder's children.
- Use `filterTree` for a search rather than filtering by hand: it keeps the rows above a match and tells you which to open.
- Give a row a menu with a `ContextMenu` of your own and `onItemContextMenu`, so a menu stays a menu (a button in a row is a second focus stop).
- Use `controllerRef` for an "Expand all" button or to reveal a row found by a search (`scrollToNode`).
- Activation (`onItemActivate`, from Enter or a double click) is for opening the thing a row stands for; selection is for choosing it.

## Accessibility

<Callout tone="info" title="The WAI-ARIA tree pattern: one tab stop, then arrow keys">

The tree is an element with `role="tree"` holding a flat list of `role="treeitem"` rows, each saying its `aria-level`,
`aria-posinset` and `aria-setsize`, so a screen reader announces "level 2, 3 of 5" however many rows are drawn. A row with children
has `aria-expanded`. With a `selectionMode` every row has `aria-selected`, and the tree is `aria-multiselectable` in `"multiple"`.
With `checkable` every row has `aria-checked` (`"mixed"` for a row some of whose leaves are checked). A disabled row has
`aria-disabled` and stays focusable and in the arrow-key order. A row whose children are loading is `aria-busy`. An open row that loaded nothing has one disabled "Empty" row under it, which is in the arrow-key order and is not selectable or checkable. The arrow and the
check box are decorative and hidden from assistive technology; the row's label is its name, and a description or trailing text is read after it.

Name the tree with `aria-label` or `aria-labelledby` (a warning in development when neither is given). When the children of a
row you were loading arrive, a polite live region says how many.

The tree is one tab stop, on the selected row (or the first). The arrow keys move focus, and the tab stop moves with it. When the row
that holds the stop is outside the drawn window of a long tree, the tree itself is the stop and hands focus to that row.

| Key | Behaviour |
|---|---|
| `Tab` | Moves focus into the tree (to the row that holds the stop), and out of it. |
| `ArrowDown` / `ArrowUp` | Moves to the next or previous visible row. |
| `ArrowRight` | Opens a closed row; on an open row, moves to its first child, or asks to try again when it failed to load. (`ArrowLeft` in `dir="rtl"`.) |
| `ArrowLeft` | Closes an open row; otherwise moves to the row's parent. (`ArrowRight` in `dir="rtl"`.) |
| `Home` / `End` | Moves to the first or last visible row. |
| `PageDown` / `PageUp` | Moves down or up by the rows that fit in the box that scrolls, less one (ten when the tree does not scroll). With `Shift` in `"multiple"`, extends the selection. |
| `Enter` | Activates the row (`onItemActivate`), or opens or closes it when there is no handler. On an open row that failed to load, asks to try again (`onRetry`). |
| `Space` | Checks the row when `checkable`, otherwise selects it (adds or removes it in `"multiple"`). |
| `Shift` + `Space` | When the tree is `checkable` and has a `selectionMode`, selects the row (adds or removes it in `"multiple"`), so a tree that does both can be driven by the keyboard alone. |
| `Shift` + `ArrowDown` / `ArrowUp` | In `"multiple"`, extends the selection from where it began. |
| `Ctrl` or `⌘` + `A` | In `"multiple"`, selects every row that is not disabled. |
| `F2` | With `renamable`, turns the focused row's label into a field. In the field: `Enter` commits, `Escape` cancels. |
| Context-menu key, `Shift` + `F10` | Asks for the focused row's menu (`onItemContextMenu`). |
| `*` | Opens every closed row beside the focused one. |
| A letter | Moves to the next visible row whose label starts with the letters typed within a moment; a repeated letter cycles through the rows that start with it. |

With the pointer, a click on the arrow opens or closes the row, a click on the check box checks it, a click on the row selects
it (with `Ctrl` or `⌘` to add or remove, `Shift` to extend), and a double click activates it. The arrow and the check box are hit on a box at least 24 pixels tall
at every size, reaching sideways halfway to their neighbour. The focus ring is drawn inside the row so the box that scrolls cannot clip it.

A selected row is told apart by a coloured bar at its start and a bolder label as well as its fill, so it survives forced colours,
where the bar is drawn in `Highlight` and a check box in `Highlight`. The arrow is mirrored, and turns the other way, when `dir="rtl"`.
The arrow turns with a short transition that is removed when the person prefers reduced motion.

</Callout>

## Code examples

```tsx
{/* A file browser: open a file on activation, remember what is open. onFocus is a native <div> attribute, passed straight
    through to the element with role="tree"; so is title */}
<Tree
  aria-label="Project files"
  nodes={files}
  selectionMode="single"
  value={[currentFile]}
  onValueChange={([id]) => id && setCurrentFile(id)}
  onItemActivate={(id) => openInEditor(id)}
  onFocus={() => setBrowserFocused(true)}
  title="Project files"
  maxHeight={480}
/>
```

```tsx
{/* A picker for what to export: only the leaves are stored, and a folder shows what is under it.
    Space checks a row, Shift+Space selects it. */}
<Tree
  aria-label="Choose what to export"
  nodes={folders}
  checkable
  checkedIds={exportIds}
  onCheckedChange={setExportIds}
  defaultExpandAll
/>
```

```tsx
{/* A picker of files: a folder is opened by a click and never chosen */}
<Tree
  aria-label="Choose files"
  selectionMode="multiple"
  expandOnClick
  nodes={[{ id: "src", label: "src", selectable: false, children: [{ id: "app", label: "App.tsx" }] }]}
/>
```

```tsx
{/* Fetch a folder when it is opened: its row has hasChildren, and is opened with onExpandedChange.
    loading holds its id while you fetch, failed holds it if the fetch fails (opening it again calls onRetry) */}
<Tree
  aria-label="Cloud files"
  nodes={folders}
  loadingIds={loading}
  errorIds={failed}
  onExpandedChange={(open) => fetchMissingChildren(open)}
  onRetry={(id) => fetchChildren(id)}
/>
```

```tsx
{/* A search: filterTree keeps the matches and the rows above them, and says which rows to open */}
const result = filterTree(files, { query });
<Tree
  aria-label="Project files"
  nodes={result.nodes}
  expandedIds={query ? result.expandedIds : open}
  onExpandedChange={setOpen}
  highlightQuery={query}
/>
```

```tsx
{/* Rename a row with F2: the tree asks, you change nodes */}
<Tree
  aria-label="Project files"
  nodes={files}
  renamable
  onRename={(id, label) => setFiles((current) => renameNode(current, id, label))}
  validateRename={(id, label) => (nameTaken(label) ? "That name is taken" : undefined)}
/>
```

```tsx
{/* A menu for a row: wrap the tree in a ContextMenu and open it for the row the tree names.
    const menu = useRef<ContextMenuController>(null) */}
<ContextMenu controllerRef={menu}>

    <div>
      <Tree
        aria-label="Project files"

        onItemContextMenu={({ id, via, point }) => {
          setTarget(id);
          if (via === "keyboard") menu.current?.openAt(point);

    </div>
  </ContextMenu.Trigger>
  <ContextMenu.Content>
    <ContextMenu.Item onSelect={() => removeFile(target)} tone="danger">Delete</ContextMenu.Item>
  </ContextMenu.Content>
</ContextMenu>
```

```tsx
{/* The first fetch of the rows: placeholders until they arrive */}
<Tree aria-label="Project files" nodes={files} loading={isLoading} />
```
