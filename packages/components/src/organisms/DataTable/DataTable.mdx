<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="DataTable" tier="Organism" />

A table of data you give it as `columns` and `data`, with the behaviour an app needs around the rows: sorting by one
column or several, choosing rows (including every row of every page), paging, a long list drawn a window at a time, a loading
state, an empty state, a menu of actions per row, a menu to show and hide columns, and columns that can be resized and pinned. It
draws a real `Table`, so it is a native `<table>` in its own scroll frame, and it composes `TableToolbar`, `Pagination`,
`Checkbox`, `Select` and `Menu` rather than redrawing them.

It holds the state of the interaction and nothing else. Your data stays yours: it sorts and pages the rows you pass in the
browser, or, with `sortMode="manual"`, draws the rows you pass and asks you for new ones. Every piece of state (the sort, the
choice, the page, the page size, the hidden columns, the column widths) is controlled with a value and a change callback, or uncontrolled with a
default.

### Import

```tsx
import { DataTable } from "@dbm-system/components";
```

Its parts are `DataTable.Toolbar`, `DataTable.Selection`, `DataTable.ColumnMenu` and `DataTable.Pagination`, placed as direct children (the toolbar and the menu above the table, the pagination below it). `useDataTable()`
reads and changes the table's state from your own parts inside it.

## Properties

`DataTable` also accepts any other native `<table>` attribute beyond what's listed here (e.g. `onFocus`, `title`) — passed
straight through to the table element. `ref`, `id`, `data-testid` and the `aria-*` props reach the `<table>`, where assistive
technology expects them; `className` and `style` go on the box that holds the toolbar, the table and the pagination.

A `TableToolbar` drawn above the table; it takes its parts (`TableToolbar.Row`, `.Search`, `.Filter`, `.ActiveFilters`,

### DataTable.Selection properties

The bulk-action row of the toolbar, read from the table's own selection: it says how many rows are chosen, offers **Clear

### DataTable.ColumnMenu properties

A button that opens a menu with one checkbox item per column, which shows or hides it. It reads and sets the table's hidden columns,

<PropertiesTable of={ColumnMenuStories} order={columnMenuPropOrder} />

The footer: the page controls, "1–10 of 47" and a page size select, read from the table's own page. Its presence turns paging
on. It takes `Pagination`'s presentation props; the page, the page count and the change handler come from the table.

## Variants

### Sorting

A sortable column's heading is a button that cycles ascending, descending and none. The sorted column carries `aria-sort`, and
a live region says "Sorted by Salary, descending". A press with Shift held (Shift and Enter from the keyboard) adds the column to
the sort instead of replacing it, so "Department, then Salary" is two presses; the columns then show their order, a screen reader
hears "sort order 2" after the heading, and the announcement lists them all. `multiSort={false}` turns it off. Rows that tie keep their order, and an empty value goes last in either
direction. Sorting happens before paging, so it orders the whole set.

<Canvas of={DataTableStories.Sorting} />

### Selection

`selectionMode="multiple"` adds a column of checkboxes and a header checkbox that is checked, mixed or clear for the rows on the
page; a shift-click chooses a range. `"single"` replaces the choice. The chosen ids are kept across sorting and pages, and
`isRowSelectable` says which rows can't be chosen. A chosen row has three marks, since a fill alone is quiet: the checked
checkbox, a marker on the start edge of its checkbox cell (in `border.brand`, held transparent in every row so choosing one moves
nothing), and a fill one step stronger than the `brand` tone's stripe, so a chosen row isn't mistaken for a striped one.

<Canvas of={DataTableStories.Selection} />

### Select all across pages

A table that holds one page of its rows (`sortMode="manual"` with a `totalCount`) can't list the ids of the rest, so
"Select all 137" in `DataTable.Selection` chooses *all* of them as a state of its own (`allSelected`, controlled with
`onAllSelectedChange`): every row shows as chosen, on every page, and the count is the `totalCount`. Unchecking a row goes
back to a list of ids, the page's rows but that one; clearing goes back to none. Reset it when the filter changes, since "all"
meant the rows matching the old one. A `client` table lists the ids as before.

<Canvas of={DataTableStories.ServerSide} />

### Expandable rows

`renderExpandedRow` draws the detail of a row under it, in one cell as wide as the table, and adds a column of expand buttons after
the checkboxes. Each button is named for its row ("Expand Ada Lovelace"), carries `aria-expanded`, and points at the detail with
`aria-controls` while it is open. `expanded` and `onExpandedChange` keep which rows are open (by row id, across pages),
`defaultExpanded` starts some open, `expandMode="single"` closes the open row when another opens, and `isRowExpandable` leaves a row's
cell empty. Rows of different heights can't be drawn a window at a time, so such a table is never windowed, and it sets no
`aria-rowcount` or `aria-rowindex`.

<Canvas of={DataTableStories.ExpandableRows} />

### Pagination

`DataTable.Pagination` turns paging on. Changing the page size goes back to the first page. A page that is past the end is held
to the last one.

<Canvas of={DataTableStories.Pagination} />

### With a toolbar and paging

The toolbar goes above the table and the pagination below it, wherever they are among the children. Here the app holds the search
text and the filtered rows; the table holds the selection, the sort and the page.

<Canvas of={DataTableStories.WithToolbar} />

### Row actions

`rowActions` draws a trailing column, usually an `IconButton` that opens a `Menu`. Its heading is read by a screen reader and not
drawn.

<Canvas of={DataTableStories.RowActions} />

### A row's context menu

`rowContextMenu` opens a menu on a right-click, a long press or the context-menu key, and returns its `ContextMenu` items. It is told
the row and the rows it acts on: a press on a row that isn't chosen chooses it alone first, and a press on a chosen row keeps the
selection, so `rows` is everything marked. The row stays outlined while its menu is open. A context menu is a shortcut and is not the
only way to an action, so offer the same items in `rowActions` or the toolbar; `rowContextMenuKeys` names keys for a platform with no
context-menu key (macOS).

<Canvas of={DataTableStories.RowContextMenu} />

### A long table, drawn a window at a time

Above 100 rows, an unpaged table with a `maxHeight` draws only the rows in view, so five thousand rows cost about what fifty do.
Every row is one line of a fixed height from a token, `aria-rowcount` and `aria-rowindex` tell a screen reader the real size, and
a cell with a `width` is cut with an ellipsis. `virtualize` decides it by hand.

<Canvas of={DataTableStories.LongTable} />

### Sorting and paging on a server

With `sortMode="manual"` the table draws `data` as given and reports `onSortChange` and `onPageChange`; you answer with new rows
and say how many there are in all with `totalCount`. `loading` draws placeholder rows while you wait.

<Canvas of={DataTableStories.ServerSide} />

### Column menu

`DataTable.ColumnMenu` is a button that opens a menu of the columns, each a checkbox item. `hiddenColumns` and
`onHiddenColumnsChange` make the list controlled (to keep it in the URL, say); `useDataTable()` reads and sets the same list from
inside the table for a menu of your own.

<Canvas of={DataTableStories.ColumnVisibility} />

### Loading and empty

A loading table shows placeholder rows and is `aria-busy`. An empty one says `emptyState`, or "No results".

<Canvas of={DataTableStories.LoadingAndEmpty} />

### All sizes

`size` sets the type, the padding and the fixed height of a row (`data-table.row-height.*`) together.

<Canvas of={DataTableStories.AllSizes} />

### Density toggle (a recipe)

Density isn't a prop of its own: `size` already sets the type, the padding and the height of a row together, so a toggle is a piece of
your state handed to it, from a `ToggleGroup` in the toolbar or a setting in the person's profile. Keep the choice wherever the
person's other settings live.

<Canvas of={DataTableStories.DensityToggle} />

### Saved views (a recipe)

A view is a plain object of the table's own controlled state, so there is nothing to add to the table: hold the `sort`,
`hiddenColumns`, `columnWidths` and `pageSize` (and `size`, and the filters you keep beside the table) yourself; saving a view copies
them and choosing one hands them back. Where views live (state, storage, a server) is yours to decide, which is also why the table
doesn't store them. A view of `selection`, `page` or `expanded` is rarely wanted: they describe what a person did, not how they like to
look.

<Canvas of={DataTableStories.SavedViews} />

### Column sizes and resizing

`resizable` puts a handle at the end of every heading. Drag it, or focus it and use the arrow keys (Shift for larger steps, Home and
End for the limits, Enter to reset); a double press resets it too. A column begins at its `width` (or what its content asks for)
and stops at its `minWidth` and `maxWidth`; a resized column is a fixed width and a long cell is cut with an ellipsis.
`columnWidths` and `onColumnWidthsChange` keep the widths wherever you want them. `selectionColumnWidth` and `actionsColumnWidth`
size the two columns the table adds. Each handle is a tab stop, so turn resizing on where it is wanted.

<Canvas of={DataTableStories.ResizableColumns} />

### Pinned first and last columns

`stickyFirstColumn` and `stickyLastColumn` are `Table`'s, as a count: `true` pins one data column, a number pins that many, and
the checkbox column (at the start) and the actions column (at the end) are pinned beside them, up to four columns at an edge in
all. Each pinned column sits against the one before it.

<Canvas of={DataTableStories.PinnedColumns} />

### Tones

`tone` is `Table`'s, with `brand` as the default: a header in the brand's solid colour, with the stripes and the hover tinted to
match. `neutral` leaves the header and the caption unfilled, and `info`, `success`, `warning` and `danger` are fixed status
colours.

<Canvas of={DataTableStories.Tones} />

### Right to left

Alignment and pinning are logical, so a page with `dir="rtl"` mirrors the table. The page size select opens a Radix list that
doesn't read the page's direction, so give `DataTable.Pagination` `dir="rtl"` as well; the range's numbers are isolated, so
"1–10 of 47" reads in order.

<Canvas of={DataTableStories.RightToLeft} />

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Name the table with a `caption`, an `aria-label` or an `aria-labelledby`; a dev-mode warning fires if it has none.
- Give each row an `id` (or `getRowId`) that is stable, so the choice survives a reload of the data.
- Give the column that names each row `rowHeader`, and `getRowLabel` the same words, so a row's checkbox says whose it is.
- Make the `accessor` of a sortable column return a number, a date or text; use `compare` for anything else, including text
  that must be ordered by another language's rules: the default orders text in English, whatever the visitor's browser language, so
  a server and a browser agree.
- Hold the sort, the page and the choice yourself (controlled) when they belong in the URL or on a server.
- Use `sortMode="manual"` with `totalCount` when the rows don't fit in the browser.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a handful of static rows with nothing to do: that is `Table`.
- Don't make `onRowClick` the only way to reach what a row opens: it adds a tab stop per row and is not announced as a link. Put a
  link in the row too.
- Don't pass a new `columns` array on every render of a large table: it sorts again each time. Define it once, or `useMemo` it.
  (A `getRowId` or `isRowSelectable` written inline is fine: they don't sort again.)
- Don't put a long, wrapping paragraph in a cell of a table you want to be windowed: a row there is one line.
- Don't use `virtualize` with pagination: pages already bound the rows drawn.

</Callout>
</div>

## Best practices

- Right-align numbers (`numeric`) so figures line up, and put a unit in the heading rather than in every cell.
- Keep the default sort in `defaultSort` (or the controlled `sort`) so the first view is the order you mean.
- Put the bulk actions that are safe first and the destructive one last, and name each for what it does.
- For a server, show `loading` during the request and keep the old rows' count in `totalCount`, so the footer doesn't jump.
- A table inside a `Card` uses `variant="ghost"`.
- Put `DataTable.ColumnMenu` in the toolbar's last row, after a `Spacer`, with the same `size` as the toolbar's other controls.
- Turn `resizable` on only where people will use it: each handle is a tab stop. Keep the widths with `onColumnWidthsChange`, and
  give a column a `minWidth` that keeps its heading readable.
- Pin the column that names each row (`stickyFirstColumn`), and with a selection the checkbox stays beside it; pin as few as
  fit, since pinned columns take room from the scrolling ones.
- For a server's "select all", reset `allSelected` when the filter changes, and send `allSelected` with the filter, not a list.
- Pair the toolbar's `Summary` with the footer's range so the two agree about how many rows there are.

## Accessibility

<Callout tone="info" title="A native table with real buttons and checkboxes in it">

- It is a `<table>` with `scope="col"` headers and, for a `rowHeader` column, `scope="row"` headers. It is not a `grid`: there is
  no cell-by-cell arrow-key model to learn, and every control in it is an ordinary tab stop in reading order.
- A sortable heading is a `<button>` whose name is the heading's own text. The sorted column carries `aria-sort`; the other
  columns carry none. Sorting is announced ("Sorted by Name, ascending") in a live region that is in the page before it speaks.
- Row checkboxes are named for the row ("Select Ada Lovelace"), and the header checkbox is "Select all rows" and exposes the mixed
  state. A chosen row sets `data-selected` and no `aria-selected`, which a plain table row doesn't support.
- A paged or windowed table sets `aria-rowcount` and each row's `aria-rowindex` across the whole set, so a screen reader hears the
  real size and position. The page controls announce the page and the footer's size select announces the new count.
- `onRowClick` makes each row a tab stop, activated by Enter or Space on the row itself; a press on a control inside the row is
  that control's.
- `rowContextMenu` opens a menu named "Actions for" and the row's label on a right-click, a long press, and the context-menu key
  (or the keys of `rowContextMenuKeys`) on the element that has focus in the row, which needs no extra tab stop: a row's checkbox
  or button is enough. Focus goes back to it on Escape. It is a shortcut, so the same actions belong in `rowActions` or the toolbar.
- Every interactive target is at least 24 × 24px at every size (the sort button, the checkbox, the row menu's button).
- The sort button's focus ring is drawn inside it, since a header cell and the scroll frame clip what is outside. On a solid
  tone's header it takes the text's colour.
- A chosen row's fill is `bg.brand-subtle-hover` with `text.primary` over it, and it is quiet (1.14:1 against the surface in Purple
  light), so it is never the only mark: the checked checkbox and a 4px marker in `border.brand` on the edge of its checkbox cell
  say it too. Forced colours drops the fill and draws the marker in the system's highlight colour.
- A resize handle is a focusable `separator` (the window-splitter pattern) named "Resize Name column", with `aria-valuenow`,
  `aria-valuemin` and, when there is one, `aria-valuemax` in pixels, and a hidden hint about its keys. The arrow keys follow the
  page's direction (right is wider in a left-to-right page and narrower in a right-to-left one), the hit area is 24px wide, and a drag
  ends however the pointer ends.
- An expand button is a native button named for its row, with `aria-expanded` and (while open) `aria-controls` pointing at the detail
  row; Enter and Space work, focus stays on it, and the detail's own controls come after it in the Tab order. A hidden row after an
  open one keeps the stripes in step. The caret of a closed row points toward the end edge, so it turns round in right-to-left.
- A sort by several columns says its order: the digit beside a column's arrow is hidden from assistive technology, which hears
  "sort order 2" after the heading, and the live region lists every column in the announcement.
- An arrow on a column that isn't sorted, and the line of a resize handle, are drawn at `opacity.80` and keep 3:1 against their header
  (brand or neutral) in all four themes, which a real-browser check measures.
- A cell cut with an ellipsis (a column with a `width`) carries its whole text as its `title`; a screen reader reads the full text
  from the cell anyway.

</Callout>

## Code examples

```tsx
const columns: DataTableColumn<Employee>[] = [
  { id: "name", header: "Name", accessor: (row) => row.name, sortable: true, rowHeader: true },
  { id: "salary", header: "Salary", accessor: (row) => row.salary, cell: (row) => money(row.salary), sortable: true, numeric: true },
];

<DataTable
  aria-label="Team"
  columns={columns}
  data={employees}
  selectionMode="multiple"
  getRowLabel={(row) => row.name}
  onSelectionChange={setChosen}
>
  <DataTable.Toolbar aria-label="Team table tools">
    <TableToolbar.Row>
      <TableToolbar.Search>
        <SearchInput aria-label="Search the team" onSearch={setQuery} />
      </TableToolbar.Search>
    </TableToolbar.Row>
    <DataTable.Selection>
      <Toolbar aria-label="Bulk actions" variant="secondary">
        <Toolbar.Button>Delete</Toolbar.Button>
      </Toolbar>
    </DataTable.Selection>
  </DataTable.Toolbar>
  <DataTable.Pagination />
</DataTable>

{/* Sort by several columns with Shift; show and hide columns; resize; pin the name beside its checkbox */}
<DataTable
  aria-label="Team"
  columns={columns}
  data={employees}
  selectionMode="multiple"
  getRowLabel={(row) => row.name}
  resizable
  stickyFirstColumn={1}
  onColumnWidthsChange={saveWidths}
>
  <DataTable.Toolbar aria-label="Team table tools">
    <TableToolbar.Row>
      <Spacer />
      <DataTable.ColumnMenu />
    </TableToolbar.Row>
  </DataTable.Toolbar>
</DataTable>

{/* A server's page of rows: "Select all 137" chooses every row of every page (allSelected) */}
<DataTable
  aria-label="Team"
  columns={columns}
  data={pageOfRows}
  sortMode="manual"
  totalCount={137}
  selectionMode="multiple"
  onAllSelectedChange={setAllSelected}
>
  <DataTable.Toolbar aria-label="Team table tools">
    <DataTable.Selection />
  </DataTable.Toolbar>
</DataTable>

{/* Words the table writes are a labels object; numbers go through formatNumber */}
<DataTable aria-label="Équipe" columns={columns} data={employees} labels={{ selectAll: "Tout sélectionner", empty: "Aucun résultat" }} />

{/* Native props reach the table element */}
<DataTable aria-label="Team" columns={columns} data={employees} onFocus={() => trackFocus("team")} title="Team members" />
```
