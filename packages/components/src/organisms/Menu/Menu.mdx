<ComponentHeader title="Menu" tier="Organism" />

A floating list of actions opened from a trigger, built on Radix DropdownMenu. Arrow keys, typeahead,
Home/End, Escape and focus return come with it, as do checkbox and radio items, labelled groups and
submenus. A compound component: put `Menu.Trigger` and `Menu.Content` inside `Menu`, and the items,
labels, groups and separators inside the content.

### Import

```tsx
import { Menu } from "@dbm-system/components";
```

## Properties

`Menu` itself renders no DOM element of its own: it is a plain context provider around its sub-parts,
so it has no `className`/`style`/`id`/`data-testid`/`ref` of its own to accept.

<PropertiesTable of={MenuRootStories} order={propOrder} />

### Menu.Trigger properties

The element that opens the menu. Also accepts any other native `<button>` attribute beyond what's
listed here (e.g. `onFocus`, `name`), passed straight through. `aria-haspopup` and `aria-expanded` are
kept by the menu and can't be replaced.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use a `Menu` for actions on one thing (Edit, Duplicate, Delete) or a few choices that act at once (a
  sort order, a view option), when there isn't room to show every action as a button.
- Put the destructive action last, after a `Menu.Separator`, with `tone="danger"`, so it reads as
  different before it is read.
- Give an icon-only trigger an `aria-label`. The menu is named after its trigger, so the trigger's
  name is what a screen reader announces when the menu opens.
- Keep the labels short and start them with the verb or the thing, so typeahead finds them from their
  first letters.
- Let a checkbox or radio item leave the menu open (it does by default), so the person can flip several
  options before they are done; set `closeOnSelect` on an action that should keep the menu open too.
- Return a promise from `onSelect` for an action that takes time (an export, a save): the item shows a
  spinner and ignores further presses, and the menu closes when it resolves.
- Give a disabled item a `disabledReason` when the person can do something about it (ask for a role, finish a
  step), so they can reach it, see why, and hear it.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use a `Menu` to choose a value for a form field: that is a `Select`, which is named, submitted
  and announced as a field. A menu's items act when chosen.
- Don't put a form, a heading with paragraphs or other arbitrary content in a menu. A `Popover` holds
  that, and a menu holds `menuitem`s only.
- Don't nest submenus more than one deep without a reason: each level is another hover and another key
  press to reach an action.
- Don't rely on a `shortcut` hint to make a key work. It only displays the key; bind it yourself.
- Don't put the `Dialog` an item opens inside the menu's content: it unmounts with the menu. Keep it beside the
  menu, opened from state (see Code examples).
- Don't use a `description` for text a person must read to choose: it is read as a description, not as part
  of the name, and it makes every row taller.

</Callout>
</div>

## Best practices

- On a phone, draw it as a sheet: `presentation={{ base: "sheet", md: "menu" }}` is a panel across the bottom of the screen with
  48px rows and the page dimmed behind it, and the floating menu from `md` up. It is the same menu, with the same keys and parts. A
  submenu covers it under a "Back" row (set the text with `labels`), so keep a sheet's menus shallow. A sheet has no swipe to dismiss:
  it closes on a press on the dimmed page, Escape, or choosing an item.

- Order the items by how often they are used, and keep a menu to about seven items before grouping them
  with `Menu.Label` and `Menu.Separator`.
- A leading `icon` helps recognition when most items have one; give every item in a set one, or none.
- For a link, pass `asChild` and put the anchor (or your router's `Link`) inside, so it navigates as a
  real link and is announced as one in the menu.
- Open a menu from `Menu.Trigger asChild` over a `Button` or an `IconButton`: the built-in fallback has
  no chrome of its own.
- `align="end"` suits a trigger at the end of a row or a toolbar, so the panel doesn't run off the page.
- A menu taller than the room there is scrolls inside its panel, with a fade at each end that has more behind it
  (and none where the list fits). Keep a long list searchable elsewhere (`Combobox`) rather than relying on it.

## Accessibility

<Callout tone="info" title="Keyboard and ARIA state come from Radix's menu primitive">

- The panel is `role="menu"`, named after its trigger, and holds `menuitem`, `menuitemcheckbox` and
  `menuitemradio` elements. The trigger carries `aria-haspopup="menu"` and `aria-expanded`.
- `Enter`, `Space` and `ArrowDown` on the trigger open the menu with focus on the first item; `ArrowUp`
  opens it with focus on the last.
- `ArrowDown` and `ArrowUp` move between items, skipping disabled ones; `Home` and `End` jump to the first
  and last; typing letters moves to the item that starts with them. Arrow keys stop at the ends unless
  `loop` is set.
- `ArrowRight` opens a submenu and `ArrowLeft` closes it, swapped in right-to-left text (`dir="rtl"`).
- `Enter` and `Space` choose the focused item. `Escape` closes the menu (one level of submenu at a time)
  and returns focus to the trigger. `Tab` is not used inside an open menu: the arrow keys are how it is
  navigated.
- A `description` is announced as the item's description, not as part of its name. A `disabledReason`
  keeps the item focusable and `aria-disabled`, shows the reason in a tooltip and announces it as the
  description. An item with a pending action is `aria-busy` and `aria-disabled`, and ignores presses until it
  settles.
- A `Menu.Label` inside a `Menu.Group` or `Menu.RadioGroup` names that group through
  `aria-labelledby`, wired automatically; an explicit `aria-label` or `aria-labelledby` on the group
  replaces it.
- The focused item is highlighted with a quiet fill and, for the keyboard, a ring in the focus colour
  drawn inside it. In forced-colours mode the highlighted item is drawn with an outline in a system
  colour, since backgrounds are not drawn.
- Every item is at least 24 × 24 CSS pixels at every size, and 48px tall in a sheet.
- A sheet is the same `role="menu"`: the keys, typeahead and focus handling are the floating menu's. A submenu in a sheet is drawn over
  the menu it opened from and starts on its "Back" row; the menu under it stays in the page, hidden from view, so focus isn't lost.
- The menu is modal by default: the rest of the page is hidden from assistive technology and can't be
  pressed while it is open. Set `modal={false}` for a menu that coexists with the page.

</Callout>

## Code examples

```tsx
<Menu>
  <Menu.Trigger asChild>
    <Button variant="secondary">Actions</Button>
  </Menu.Trigger>
  <Menu.Content>
    <Menu.Item onSelect={edit}>Edit</Menu.Item>
    <Menu.Item onSelect={duplicate}>Duplicate</Menu.Item>
    <Menu.Separator />
    <Menu.Item tone="danger" onSelect={remove}>Delete</Menu.Item>
  </Menu.Content>
</Menu>

{/* Controlled open state */}
function Example() {
  const [open, setOpen] = useState(false);
  return (
    <Menu open={open} onOpenChange={setOpen}>
      <Menu.Trigger asChild>
        <IconButton icon={DotsThreeIcon} aria-label="Row actions" variant="ghost" />
      </Menu.Trigger>
      <Menu.Content align="end">
        <Menu.Item>Edit</Menu.Item>
      </Menu.Content>
    </Menu>
  );
}

{/* A checkbox item leaves the menu open, and a radio group does too */}
<Menu.CheckboxItem checked={showGrid} onCheckedChange={setShowGrid}>
  Show grid
</Menu.CheckboxItem>
<Menu.RadioGroup value={sort} onValueChange={setSort} aria-label="Sort by">
  <Menu.RadioItem value="name">Name</Menu.RadioItem>
  <Menu.RadioItem value="date">Date</Menu.RadioItem>
</Menu.RadioGroup>

{/* A link, with a router's Link */}
<Menu.Item asChild>
  <RouterLink to="/docs">Documentation</RouterLink>
</Menu.Item>

{/* An action that takes time: a spinner shows and the menu closes when the promise resolves */}
<Menu.Item onSelect={() => exportRows()} onSelectError={(error) => showError(error)}>
  Export as CSV
</Menu.Item>

{/* A disabled item that says why, and an item with a second line and a badge */}
<Menu.Item disabled disabledReason="You need the admin role to delete">Delete</Menu.Item>
<Menu.Item description="Plan and invoices" trailing={<Badge tone="info">New</Badge>}>Billing</Menu.Item>

{/* An item that opens a confirmation: the dialog sits beside the menu, opened from state, and focus goes back to the trigger when it closes */}
function Row() {
  const [confirming, setConfirming] = useState(false);
  return (
    <>
      <Menu>
        <Menu.Trigger asChild>
          <Button>Actions</Button>
        </Menu.Trigger>
        <Menu.Content>
          <Menu.Item tone="danger" onSelect={() => setConfirming(true)}>Delete</Menu.Item>
        </Menu.Content>
      </Menu>
      <ConfirmDialog
        open={confirming}
        onOpenChange={setConfirming}
        title="Delete this row?"
        onConfirm={deleteRow}
      />
    </>
  );
}

{/* A native <div> attribute on an item, passed straight through */}
<Menu.Item title="Duplicates the row and its children">Duplicate</Menu.Item>

{/* A responsive side: below the trigger on a phone, beside it from lg up */}
<Menu.Content side={{ base: "bottom", lg: "right" }}>
  <Menu.Item>Edit</Menu.Item>
</Menu.Content>
```
