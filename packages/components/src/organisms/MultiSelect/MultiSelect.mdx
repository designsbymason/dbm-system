<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="MultiSelect" tier="Organism" />

A text field for choosing several options from a list. The chosen options are removable chips inside the field, and the
list floats beneath it: type to narrow it, then choose with the arrow keys and Enter, a mouse or a finger. The list stays
open after a choice, so several can be chosen in a row, and choosing a chosen option takes it out again. The value is an
array of the chosen options' `value`s. Use it where a person picks any number of items from a list too long to scan: a
set of countries, the people on a task, the labels on a record. "Multi-select" and "tag select" are the same control. It
differs from `Combobox`, which chooses one; from `TagsInput`, which makes chips out of whatever is typed and has no list;
and from `CheckboxGroup`, which shows a short list in full. Focus stays in the field the whole time; the highlighted
option is pointed at rather than focused (a *combobox* in the WAI-ARIA sense, whose list allows several choices).

### Import

```tsx
import { MultiSelect } from "@dbm-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use it to choose any number of items from a list long enough that scanning it is slow: countries, people, labels.
- Give it a name with `aria-label` or a `FormField`, so the field and its list both say what is being chosen.
- Pass `filter={false}` and fetch the options yourself when the list lives on a server, and show `loading` while you wait.
- Give each option a short, distinct `label`, since it is also the chip's text; put the detail in `description`, and the words people also search by in `keywords`.
- Say why an option can't be chosen with `disabled="reason"`, rather than leaving it dimmed and unexplained.
- Set `maxSelected` when the number is limited: the options left over say why they can't be chosen.
- Add `selectAll` when a person often wants most of the list, or all of what a search found.
- Use `overflow="collapse"` where the field sits in a toolbar or a table row and must stay one line.
- Use `presentation={{ base: "full-width", sm: "anchored" }}` in a form people fill in on a phone.
- Use `onCreate` when a person may add an item the list doesn't hold yet (a label, a person); return the new option so it is chosen.
- Use `allowCustomValue` when the list is only suggestions and a person may type any value (an email address, a tag), and `validate` to refuse the ones that aren't.
- Use `reorderable` when the order is part of the value: columns to show, steps, an assignee priority.
- Use `selectGroups` for a long grouped list where a person often wants a whole group, and `onSelectAll` when "all" is more than the page has loaded.
- Give an option a `tone` and a `chipIcon` when the chip should say what kind of thing it is (a status, a category), and `renderValue` when a name needs an avatar beside it.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a handful of options: a `CheckboxGroup` shows them all at once, with no list to open.
- Don't use it to choose one item: that is `Combobox`, or `Select` for a short list. Don't use it to collect free text: that is `TagsInput`.
- Don't fetch on every change of text: search only on `reason === "input"`, since a choice, a clear and a reset write text that isn't a query.
- Don't put interactive controls inside a row: a row is chosen as a whole, and focus never enters it.
- Don't rely on a placeholder as the name; it goes as soon as there is a chip.

</Callout>
</div>

## Best practices

- The value is an array of option values, a new array on every change. Keep just `value` in your state in the usual
  case. A value with no matching option (a saved id whose option has not loaded) shows the value as its chip, and the
  chip keeps an option's label once it has seen it, so a list fetched for new text doesn't rename what is chosen.
- A choice clears the text that narrowed the list, and leaves the highlight where it was, so the next option can be
  chosen without the list jumping. `closeOnSelect` closes the list on each choice instead.
- Chosen options stay in the list, marked with a check, so the same row that adds an option also takes it away. They are
  not hidden, because hiding them moves the rows under the pointer.
- `maxSelected` disables the options not chosen once it is reached; chosen ones stay available to remove. `minSelected`
  only affects a form: a person can still remove chips below it, and the form says how many it needs.
- "Select all" covers the options that match what is typed (every enabled option when nothing is), and stops at
  `maxSelected`. With every one of them chosen, the row reads "Deselect all" and removes just those.
- Rows have a fixed height, set by `size` (and taller for an option with a `description`), so a list of thousands draws
  only the rows in view. A custom `renderOption` must fit its row; long text is cut with an ellipsis.
- The chips share `TagsInput`'s box, sizes, tones and variants, so the two fields look the same side by side. A chip's
  text is cut with an ellipsis when it is wider than the box, and the whole label shows in a tooltip while it is cut.
- `overflow="collapse"` keeps an idle field to one line: as many chips as fit, then a "+N more" button whose count
  follows the width. While the field is in use (the typing area or a chip has focus) every chip is shown, so a chip you
  are on never disappears. `maxVisible` caps the number shown while idle; the hidden ones are still submitted.
- Inside a `Form`, each chosen value is submitted as its own entry under `name`, and `required` and `minSelected` are
  rules on the typing field itself, so the form shows its message in the field's own slot and focuses it. With nothing
  chosen, a disabled hidden input keeps the name in the form's controls without submitting anything.
- Once a list holds more than a hundred rows, group headings are drawn as plain rows rather than as grouped regions, and
  each option is read with its group's name after its own.
- `presentation="full-width"` measures the part of the page the person can see (the visual viewport), so an on-screen
  keyboard that covers the bottom of the screen is counted: the list goes above the field when there is little room
  below, and its height is what is left. `align` has no effect there, and `side` is only its first choice.
- Typed text matches an option when its label and `keywords` together hold every word of it, in any order. Only the
  label is marked (in bold, and in colour with `highlightTone`), and every matching stretch of it.
- `onCreate` adds a last row, "Create …", while the typed text names no option. It is highlighted only when nothing
  else matches, so Enter still chooses a real match first. Add the new option to `options` yourself: until you do, its
  chip still shows its label, and the value is kept.
- An option can carry its chip's `tone` and `chipIcon`, which replace the field's `tone` for that chip and add an icon the
  list doesn't show (the option's own `icon` is for the list). `renderValue` replaces a chip's text with your own content: it
  receives the option (or `undefined` for a value with no option), the chip's tooltip, remove button and announcements keep the
  `label`, and the chip must stay one line tall.
- `reorderable` lets chips be moved by dragging with a pointer or a finger, or with the keyboard (see the table). The value
  changes order and `onValueChange` reports `source: "reorder"`; the order is also what a form submits. Chips take no touch
  gestures of their own while it is on, so a finger drags them instead of scrolling the page, and a press on a chip never opens
  the list. A chip being dragged is dimmed and a bar shows where it will land, beside the nearest chip, so a row that wraps onto
  several lines works the same.
- `selectGroups` adds a row under each group's heading that chooses every enabled option of that group the list shows (the
  matches, while text is typed), and removes them again once all are chosen. It stops at `maxSelected`. A group with nothing
  that can be chosen has none.
- `onSelectAll` answers the "Select all" row for a list the page doesn't hold all of. It receives the typed text and the
  options loaded now, and returns options or just their values (or a promise of them); the row waits meanwhile, the result is
  added up to `maxSelected`, and the chips keep the labels of the options it returned. The row only adds: remove with the clear
  button or the chips. It is offered once there is something to search or load.
- With `allowCustomValue` typed text is a value of its own when it names no option. Enter with no option highlighted, a
  separator (a comma by default; `separators` changes them), a paste of several (split at separators and line breaks) or leaving
  the field makes chips; the first match is not highlighted while typing, so Enter commits what was typed, and an arrow key
  moves to an option when that is what is meant. Text that is exactly an option's label (ignoring case and accents) chooses that
  option instead. A value already chosen, one `validate` refuses, the text of a disabled option and one past `maxSelected` are
  refused with a message under the field, which is announced and cleared by the next keystroke.
- `controllerRef` hands your code an object with `open`, `close`, `clear` and `focus`, each returning whether it had
  anything to do. Use it for a "Clear filters" button that lives elsewhere on the page.

## Accessibility

<Callout tone="info" title="A combobox whose list allows several choices, and whose focus never leaves the text field">

- The typing field is a native text input with `role="combobox"`, `aria-expanded`, `aria-controls` (while open),
  `aria-autocomplete="list"` and `aria-haspopup="listbox"`. Focus stays in it while the list is open; the highlighted
  option is named by `aria-activedescendant`, so a screen reader reads each option as the arrow keys reach it.
- The list is a `listbox` with `aria-multiselectable`, named like the field (from `aria-label`, `aria-labelledby` or the
  field's visible label). Each row is an `option` with `aria-selected`; one that can't be chosen has `aria-disabled`,
  and its reason is read after its name. Groups are `group`s named by their heading; in a list long enough to be
  windowed, each option is read with its group's name instead.
- The chosen options are a list named "Selected options" (`labels.selected`), each chip with a remove button named
  "Remove" and the option's label. Once something is chosen, the typing field is described by a hint on how to reach the
  chips. The chips are not tab stops: the field is one stop, and the arrow keys move among the chips.
- A choice, a removal and a clear are announced with how many are now chosen, in a status region that was already in
  the page. The number of matches is announced only as the person types and the count changes, never when the list
  merely opens. A refused choice at the limit, and an error, are announced.
- "No results", "Type to search" and "Loading…" are rows in the list that can't be chosen, so a list is never empty to
  assistive technology. A loading list is `aria-busy`.
- The caret and clear buttons are for the pointer and are not tab stops; the keyboard has the arrow keys, Escape and
  Alt+Down. Each is at least 24 × 24 pixels at every size, and so is a chip's remove button's hit area.
- Enter while an input method is composing a character does nothing. Pressing a row never moves focus, so a touch
  keyboard stays up.
- In a form, `required` and `minSelected` are a custom validity on the typing field, so the browser and `Form` focus the
  field you can see and read its message.
- With `reorderable` a chip that is picked up, moved, dropped or put back is announced with its place ("Uruguay moved to
  position 2 of 3"), and the pick-up says which keys to use. A chip keeps its element when it moves, so keyboard focus stays on
  it. Space picks up rather than removes while it is on; Enter and Delete still remove. A chip that is picked up has a ring in the
  focus colour, and a drop marker is a bar in the same colour (a system colour in Windows high contrast).
- With `allowCustomValue` a refused value is shown under the field, announced, and named in the field's description, and the
  field is marked invalid until the next keystroke.
- The matched text in a label is drawn bold, and with `highlightTone` also in `Highlight`'s colours (a `<mark>`). Neither
  is the only cue to what matched: the list is already narrowed to the options that do.
- In Windows high contrast, the highlighted row is outlined and the list and the box keep their borders.

</Callout>

| Key | Behaviour |
|---|---|
| Down arrow | Opens the list and highlights the first option; when open, highlights the next option and wraps. |
| Up arrow | Opens the list and highlights the last option; when open, the previous one, wrapping. |
| Alt + Down, Alt + Up | Opens or closes the list without moving the highlight. |
| Page Down, Page Up | Move the highlight ten options (while open). |
| Enter | Chooses the highlighted option, or removes it if it is already chosen, and keeps the list open (`closeOnSelect` closes it). With nothing highlighted it closes the list. With the list closed it does what Enter does in any field. |
| Escape | Closes the list. With the list closed, clears the typed text. |
| Left arrow (right, in a right-to-left page) | At the start of the typing field, moves to the last chip. Between chips it moves to the previous one; Right goes the other way, and from the last chip back to the typing field. |
| Home, End | On a chip, move to the first or last chip. In the typing field they move the caret. |
| Backspace | In an empty typing field, moves to the last chip; a second press there removes it and keeps your place along the row. With text, deletes a character. |
| Delete | On a chip, removes it. |
| Space (`reorderable`) | On a chip, picks it up. Arrow keys (flipped in a right-to-left page), Home and End then move it, Space or Enter drops it, Escape puts it back. Leaving the chip drops it where it is. |
| Alt + arrow (`reorderable`) | On a chip, moves it one place without picking it up. |
| Tab | Leaves the field. The typed text is dropped. |
| Typing | Opens the list and narrows it; the first match is highlighted. With `onCreate`, a "Create …" row comes last. |

## Code examples

```tsx
{/* countries: [{ value: "ca", label: "Canada" }, { value: "mx", label: "Mexico" }, …] */}
<MultiSelect aria-label="Countries" options={countries} onValueChange={(values) => setCountries(values)} />

{/* Native props pass through to the outer box: a title, a lang, a handler */}
<MultiSelect aria-label="Countries" options={countries} title="Where the order ships" lang="fr" />

{/* At most three, with a row that chooses every match */}
<MultiSelect aria-label="Labels" options={labels} maxSelected={3} selectAll />

{/* One line while idle, the rest behind "+N more" */}
<MultiSelect aria-label="Assignees" options={people} overflow="collapse" />

{/* Options fetched as the person types: search only for typing, and drop stale replies */}
<MultiSelect
  aria-label="Search countries"
  options={results}
  filter={false}
  loading={isFetching}
  onInputValueChange={(text, reason) => reason === "input" && search(text)}
/>

{/* Let a person add an item the list doesn't hold; return it so it is chosen */}
<MultiSelect aria-label="Labels" options={labels} onCreate={(text) => addLabel(text)} />

{/* Clear a filter field from a button elsewhere on the page */}
{/* const controllerRef = useRef<MultiSelectController>(null); */}
<MultiSelect aria-label="Countries" options={countries} controllerRef={controllerRef} />
<Button onClick={() => controllerRef.current?.clear()}>Clear filters</Button>

{/* Typed values as chips: an email field with suggestions */}
<MultiSelect
  aria-label="Recipients"
  options={contacts}
  allowCustomValue
  validate={(text) => (text.includes("@") ? undefined : "Not an email address")}
/>

{/* Chips that move, with the new order reported and submitted */}
<MultiSelect aria-label="Columns" options={columns} reorderable onValueChange={(values) => saveOrder(values)} />

{/* A row for each group, and a Select all the page answers */}
<MultiSelect aria-label="Ingredients" options={ingredients} selectGroups />
<MultiSelect
  aria-label="Search countries"
  options={results}
  filter={false}
  selectAll
  onSelectAll={async ({ text }) => (await fetchEveryMatch(text)).map((country) => country.id)}
/>

{/* A chip's colour and icon from its option, and its content drawn yourself */}
<MultiSelect
  aria-label="Status"
  options={[{ value: "done", label: "Done", tone: "success", chipIcon: CheckCircleIcon }]}
  renderValue={(option) => <span>{option?.label}</span>}
/>

{/* Choosing in a Dialog: the list sits above the dialog, takes the mouse, and leaves the dialog open */}
<Dialog>
  <Dialog.Trigger asChild>
    <Button>Ship to…</Button>
  </Dialog.Trigger>
  <Dialog.Content aria-label="Ship to">
    <Dialog.Body>
      <MultiSelect aria-label="Countries" options={countries} />
    </Dialog.Body>
  </Dialog.Content>
</Dialog>

{/* Words in another language, and numerals that differ */}
<MultiSelect
  aria-label="Países"
  options={paises}
  formatNumber={new Intl.NumberFormat("ar-EG").format}
  labels={{ noResults: "Sin resultados", clear: "Borrar todo", remove: (label) => `Quitar ${label}` }}
/>

{/* With a label, helper text and a minimum; the wiring is done for you */}
<FormField label="Countries" helperText="Where the order ships" required>
  {(fieldProps) => <MultiSelect {...fieldProps} name="countries" options={countries} minSelected={2} />}
</FormField>
```
