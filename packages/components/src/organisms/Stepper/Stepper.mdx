<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Stepper" tier="Organism" />

A stepper shows where a person is in a flow that happens in a fixed order — a checkout, an onboarding,
a setup wizard — as a row (or column) of steps, each with an indicator and a title. A compound
component: put one `Stepper.Step` per step inside `Stepper`, and say which one is current with `value`.
Steps before it show as finished, steps after it as not started (with `interactive="completed"`, after going
back, the steps passed stay finished and the furthest one reached, if it was not completed, is started), and any
step can say otherwise with its own `status` (an error, a warning, a skipped step, one finished out of order, one started and not finished),
and a step can be `busy` while its check or save runs.

`Stepper` draws the indicator and nothing else. The current step's content — usually a form — and the
buttons that move between steps are yours, and so is deciding whether a step may be left. It renders a
`<nav>` around an ordered list, so it reads as a list of steps to a screen reader, and it is a read-out
of progress by default; `interactive` lets a person click to a step they have reached, or to any step.

Every step needs a `title`, but the text need not be shown: `showLabels={false}` draws indicators alone, with the titles
still read by a screen reader and shown in a tooltip on hover or focus. Choose how big it is with `size`, how the indicators look with `variant` and `rounded`, the colour of the
progress with `tone` (or `colorful`, to make a finished step success), the line between steps with `connector`, and which
way it runs with `orientation` (which can change with the width). `compact` swaps the steps for a one-line summary
("Step 2 of 4 — Shipping") on a phone, with Back and Next when `interactive`, and `controllerRef` hands Next, Back and
go-to-step to a button of your own.

### Import

```tsx
import { Stepper } from "@dbm-system/components";
```

## Properties

Every step reads `size`, `variant`, `rounded`, `tone`, `colorful`, `connector`, `showLabels`, `labelPlacement` and
`orientation` from `Stepper`, so they are set once, on the root. `ref` forwards to the `<nav>`. Also accepts any other native `<nav>` attribute beyond what's
listed here (e.g. `onFocus`, `title`) — passed straight through to the root element.

<PropertiesTable of={StepperStories} order={rootPropOrder} />

Only `Stepper.Step` elements are drawn: a fragment, or plain text, placed among the children is ignored
(with a warning in development), so build the list from steps directly. Give each step a unique `value`;
a `value` that matches no step shows every step as not started, with a warning in development. To show a
finished flow, set the last step's `status="complete"`.

`controllerRef` receives `{ value, next(), back(), goTo(value) }`: the same object for the stepper's life,
whose methods ask for a change the way a click on a step does (through `onValueChange` when the stepper is
controlled) and return whether there was a step to ask for. There is no hook for it, since the only parts
inside a stepper are its steps' titles.

### Stepper.Step properties

One step — the `<li>`. Its indicator and text are drawn inside it, in a button when the step can be
entered. Also accepts any other native `<li>` attribute beyond what's listed here (e.g. `title`) —
passed straight through to the underlying element.

## Usage guidelines

<div style={{ display: "grid", gridTemplateColumns: "repeat(auto-fit, minmax(16rem, 1fr))", gap: "var(--dbm-space-4)" }}>
<Callout tone="success" title="Do">

- Use it for a flow with a fixed order that a person works through: a checkout, a setup wizard, an onboarding.
- Keep the titles short — one or two words — and put detail in `description`.
- Set `status="error"` on a step whose content has a problem, so a person who has moved on can see where to go back; with `interactive="completed"` every step the person has reached can be entered, whatever it shows.
- Keep `interactive="none"` for a strictly linear flow, and `"completed"` where going back is safe: the person can then return to a step they came back from, but never jump past the furthest one they reached. To close the steps ahead again (their content must be redone), remount the stepper with a new `key`.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for peer views a person switches between in any order — that is `Tabs`.
- Don't use it for a page's place in a site — that is `Breadcrumb`.
- Don't use it for one number moving towards a target — that is `ProgressBar`.
- Don't put more than about seven steps in one stepper; group them, or use `compact`.

</Callout>
</div>

## Best practices

- `Stepper` owns no content and no navigation logic. Keep the current step in your own state (or the
  router), pass it as `value`, and let a Back/Next button or a form's submit change it.
- Decide whether a step may be left in your own code (validate before calling the setter) and show the
  result with `status="error"`; `Stepper` does not read a `Form`.
- Move focus to the new step's content when the step changes, then leave `announce` on only if you do not:
  a screen reader should hear the step change once, not twice.
- A horizontal stepper with many steps scrolls sideways inside its own width instead of squeezing them.
  For more than a handful on a phone, use `compact="auto"`.
- The compact summary has no steps to enter. With `interactive` set it always shows a Back and a Next button (to the
  nearest step either side of the current one that `interactive` lets a person enter), and one with nowhere to go is
  disabled, not hidden, so nothing moves as a person goes along.
- Horizontally the compact buttons sit side by side after the text (or, with `labelAlignment="center"`, Back at the
  start of the row, the text in the middle and Next at the end; with `showLabels={false}`, at the two ends of the bars).
  Vertically the summary is one column — an up arrow, the bars, a down arrow, then the step's place as numbers
  ("3/4"), with the full words and the title kept for a screen reader — and in a container with a set height it fills
  it: the bars share the room between the arrows, so the down arrow and the place sit at the bottom.
- The bars are a picture of progress, not controls: each is a few pixels tall, far under a usable target. With
  `interactive="completed"` Next is enabled only for a step ahead that was reached before going back, and is
  disabled at the furthest step: use your own button, or `controllerRef.next()`, to move on.
- With `interactive="completed"`, after going back the steps passed on the way stay finished, and the furthest step the
  person reached, if it was not completed, is drawn as started: a dashed ring in the tone's colour. When that step is
  completed, give it `status="complete"` so it is drawn finished. Set `colorful` to colour a finished step
  success instead of the `tone`; the current step and a started step keep the tone.
- Set `status="started"` yourself on a step you know was begun and not finished, such as a saved draft when a person
  returns to a flow: it is drawn dashed, announced as "started, not completed", and, with `interactive="completed"`,
  can be returned to. Without it, `started` is only worked out after going back under `interactive="completed"`.
- Show a running check with `busy` on the step, not by changing its status, and set `status="warning"` for a
  step that can be continued from but needs another look; keep `"error"` for one that must be fixed.
- Use `orientation={{ base: "vertical", md: "horizontal" }}` to stack the steps on a phone and keep each of them;
  use `compact` to replace them with a summary instead.
- Every piece of text the component writes itself is in `labels`, so a translated flow replaces the whole
  set in one place; `formatNumber` writes the digits. Three of the labels are whole sentences — `summary`
  (the compact text), `announcement` (what a screen reader hears when the step changes) and `statusText` (what
  it hears after each step's title) — so a translation chooses its own punctuation and word order. By default
  they build on `stepOf`, so translating `stepOf` alone reaches all of them.

## Accessibility

<Callout tone="info" title="A named navigation landmark holding an ordered list, with the current step marked">

The stepper is a `<nav>` — a navigation landmark, named "Progress" (or your own name, through
`labels.navigation` or `aria-label`) — around an ordered list, so a screen reader announces how many
steps there are and which one it is on. The list and its items state their `list` and `listitem` roles
outright, because Safari with VoiceOver otherwise stops treating a list with its markers removed as one.
The current step's list item carries `aria-current="step"`. Each step's text is its title, followed by a visually
hidden "(Step 2 of 4, current)", so its place and status are heard without relying on colour; the number
or check inside the indicator is hidden. When the current step changes, a polite live region announces
"Step 3 of 4: Payment" — only a change, never the first render.

A step that can be entered is a real `<button>` (or your link), so it has a focus stop; every other step
has none. A step that was started and left before it was completed is announced as "started, not completed" (`labels.started`) and drawn with a dashed ring, so the dash is never the only cue. A step that is `disabled` is a disabled button, announced as unavailable and not a tab stop. A step that is `busy` is `aria-busy` and its status text adds "in progress"; a step with a warning
adds "has a warning". A strip too narrow for its steps (or, compact and vertical, too short for them) scrolls, brings the current and the focused
step into view, and is itself a tab stop only while it scrolls and has no step to focus. With `showLabels={false}` the text is
hidden from the eye but read in full, and a step's title shows in a tooltip on hover or focus. With the default `interactive="none"`, the stepper has no keyboard interaction at all.

| Key | Behaviour |
|---|---|
| `Tab` | Moves to the next step that can be entered, in order — one stop each, nothing roving |
| `Shift+Tab` | Moves to the previous one |
| `Enter` / `Space` | Chooses the focused step, or the compact summary's Back or Next (asks through `onValueChange`) |
| `Escape` | Closes the tooltip shown for a step when `showLabels` is off |

The compact form hides the steps with `display: none` and shows a visible summary (one line, cut with an ellipsis if the title is long, so the row never changes height), so a screen reader
hears one line, not a list; use `"never"` where a phone reader should hear every step. When the width
crosses the `"auto"` breakpoint with focus inside the stepper, focus moves to the other form (the summary's
back or forward button that is enabled, or the first step that can be entered) instead of being lost. A button that is pressed and then becomes
disabled (back at the first step, forward at the last) hands its focus to the other one, or the summary. In forced-colours
mode a finished or current step is told by a thicker `Highlight` border, a started one by a thicker dashed one, an unreached one by `GrayText`,
and the line between steps is drawn in system colours.

</Callout>

## Code examples

```tsx
{/* A checkout: your own state decides the step; Stepper shows it */}
const [step, setStep] = useState("shipping");

<Stepper value={step} onValueChange={setStep} interactive="completed">
  <Stepper.Step value="account" title="Account" />
  <Stepper.Step value="shipping" title="Shipping" description="Where it goes" />
  <Stepper.Step value="payment" title="Payment" />
</Stepper>

{/* A Next button outside the stepper, through the controller */}
const controller = useRef<StepperController>(null);
<Stepper controllerRef={controller} value={step} onValueChange={setStep}>{/* ... */}</Stepper>
<Button onClick={() => controller.current?.next()}>Next</Button>

{/* A step whose check is running */}
<Stepper.Step value="payment" title="Payment" busy />

{/* A saved draft: this step was begun and not finished */}
<Stepper.Step value="shipping" title="Shipping" status="started" />

{/* Finished steps in success, indicators only, and a centred compact summary */}
<Stepper colorful showLabels={false} compact="auto" labelAlignment="center" interactive="completed">
  {/* ... */}
</Stepper>

{/* An error set from your own validation */}
<Stepper.Step value="shipping" title="Shipping" status="error" />

{/* Vertical, with the text beside each indicator */}
<Stepper orientation="vertical" defaultValue="payment" size="lg">
  {/* ... */}
</Stepper>

{/* With a router: the router's own link carries the navigation */}
<Stepper.Step value="account" title="Account" asChild>
  <RouterLink to="/checkout/account">Account</RouterLink>
</Stepper.Step>

{/* Translated */}
<Stepper
  labels={{ navigation: "Progression", stepOf: (n, total) => `Étape ${n} sur ${total}` }}
>
  {/* ... */}
</Stepper>

{/* A native <nav> attribute, passed straight through */}
<Stepper title="Checkout progress" onFocus={() => track("stepper-focus")}>
  {/* ... */}
</Stepper>
```
