<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="ColorPicker" tier="Organism" />

A color field: a swatch button that opens a panel, and a text entry that shows the color as text and takes a typed
or pasted one. The panel holds an area for saturation and brightness (drag in it, or use the arrow keys), a hue
slider, an optional opacity slider, a list of swatches you provide and, in browsers that have one, an eyedropper that
picks a color from the screen. The value is a string — `"#5548a4"` by default — written in the `format` you choose
(`hex`, `rgb`, `hsl` or `oklch`), and an empty string when no color is chosen, so it can be stored and submitted as it
is. Typed text is read in any of those spellings whatever the format is.

### Import

```tsx
import { ColorPicker } from "@dbm-system/components";
```

## Properties

`ColorPicker` also accepts any other native `<div>` attribute beyond what's listed here (e.g. `title`,
`onKeyDown`) — passed straight through to the group element that holds the swatch button and the text entry. `ref`
forwards to that group, `className` and `style` go on the outermost box, and the `id` goes on the text entry, which is
what a `FieldLabel`'s `htmlFor` should point at.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `ColorPicker` when a person chooses any color: a brand color, a label, a chart series, a highlight. For a
  small fixed set, a row of `swatches` with the text entry hidden by its own layout is often all they need.
- Pass `swatches` for the colors people reach for most (the brand colors, the last few used); the arrow keys move
  between them and Enter or Space chooses one.
- Pick the `format` your data uses. The field writes it, and the value, `onValueChange`, `onValueCommit` and a form's
  `name` all carry it.
- Turn on `showFormatSwitch` for a field where people think in more than one spelling (a design tool, a theme editor); leave it off where the value must always be one format, since using it changes the string you get. Hold the format yourself with `format` and `onFormatChange` to remember it.
- Turn on `showChannelInputs` where people need an exact number (a theme editor); `noneSwatch` where empty is a real choice; `copyButton` where the color is pasted somewhere else.
- Turn on `alpha` only when a color's opacity is part of what you store; without it the value is always opaque.
- Use `onValueCommit` to save or to do anything expensive: `onValueChange` fires on every step of a drag.
- Use `inline` where the panel is the content (a settings page); keep the floating form for a field in a form.
- Use `presentation={{ base: "full-width", sm: "anchored" }}` where the field is used on a phone.
- Put it in a `FormField` for a visible label, helper text and error text wired together.

</Callout>
<Callout tone="danger" title="Don't">

- Don't compare the typed text with the value: the value is always written in `format`, whatever was typed.
- Don't use it to show a color that cannot be changed. Draw a swatch of your own instead; there is no point in an
  editable field.
- Don't rely on the eyedropper: it exists only in some browsers and the button is left out elsewhere.
- Don't use a color alone to carry meaning in what you build with the result; pair it with text or an icon.
- Don't expect `display-p3`, `lab()` or `color()` to be read: hex, a CSS color name, `rgb()`, `hsl()` and `oklch()` are, and the value is always sRGB.

</Callout>
</div>

## Best practices

- The picker keeps hue, saturation, brightness and opacity itself, so a gray you drag through keeps its hue and the
  thumb doesn't wobble from rounding to eight bits. A `value` set from outside that isn't what those numbers already
  write to replaces them.
- The field is as wide as the text it shows. While the panel is open it keeps the widest text it has shown, so dragging does not move its edge, and it narrows again when the panel closes.
- `format` and `alpha` can change while the picker is mounted: an uncontrolled value is held as it was last written and is re-spelled in the new format (turning `alpha` off hides opacity without losing it, and turning it back on restores it).
- Text is committed with `Enter` or by leaving the field. Text that isn't a color is kept as typed, flagged
  (`aria-invalid`, a danger border) and never replaces the value; the form's message (`labels.invalid`) refuses a
  submit until it is fixed or emptied.
- Emptying the text and committing it clears the color, the same as the clear button.
- `oklch` colors outside what a screen can show lose chroma until they fit, keeping their lightness and hue; the value
  you get back is the color that is actually shown.
- When the owner controls `value`, a change it doesn't apply is undone: the field shows what `value` says. With
  `commitOn="commit"` the field keeps a drag until the owner's value changes.
- The format switch reports the color in the new format through `onValueChange` and `onValueCommit` at the moment it is used (when a color is chosen), and `onFormatChange` with the format. With no color chosen only the format changes. A controlled `format` does not change until `onFormatChange` is wired to state.
- `onFocus` and `onBlur` are for the field as a whole, panel included: they fire once on arriving and once on leaving.
- Typed text is read as hex (with or without `#`), a CSS color name (`rebeccapurple`, `transparent`), `rgb()`, `hsl()` or `oklch()`, and written back in `format`.
- `controllerRef` gives code `open()`, `close()`, `focus()` and `isOpen()`; each says whether it had anything to do (`false` while disabled, read only, inline or already in that state). `Alt`+`ArrowDown` in the text entry opens the panel.
- The saturation and brightness area never mirrors in a right-to-left page, since a color space isn't text; the
  sliders and the swatches do.
- The colors drawn in the area, the sliders and the swatches are the chosen color itself, not the system's tokens, so
  they are the same in every theme; the chrome around them (surface, borders, focus rings) follows the theme.
- Use `container` when the panel would be clipped or must live somewhere else (an element inside a dialog or a shadow
  root).

## Accessibility

<Callout tone="info" title="A group of a button and a text entry, with a dialog holding the controls">

- The field is a `role="group"` named by `aria-label` or `aria-labelledby` (a `FormField` supplies the label). The
  text entry is a labelled text input with `aria-invalid` and `aria-required`; the group carries neither, since a group
  can't.
- The swatch button has `aria-haspopup="dialog"`, `aria-expanded` and, while open, `aria-controls`. Opening moves focus
  to the area; `Escape` closes the panel and gives focus back to the button, except after a press elsewhere, which
  leaves focus where the person put it.
- The area is two real range inputs under the pointer surface, named Saturation and Brightness, each read as a
  percentage. Either takes all four arrow keys: Left and Right change saturation (never mirrored), Up and Down change
  brightness; `Shift` moves by ten, `Page Up`/`Page Down` change brightness by ten, `Home`/`End` set the focused axis
  to its least and greatest. A screen reader's own adjustment works too.
- The hue slider (read in degrees) and the opacity slider (read as a percentage) are `role="slider"` with the arrow,
  `Page` and `Home`/`End` keys; in a right-to-left page the keys follow the direction.
- The format switch is a named `radiogroup` of Hex, RGB, HSL and OKLCH (one tab stop, arrow keys between them), drawn with `ToggleGroup`; every button's name is its visible text.
- The channel fields are number inputs named Red, Green, Blue (or Hue, Saturation, Lightness; Lightness, Chroma, Hue; Opacity) with a letter drawn under each as decoration, and they are detached from a surrounding form so a half-typed number never blocks a submit.
- `Alt`+`ArrowDown` in the text entry opens the panel, as in a combobox or date field.
- The copy button says "Color copied" (or that the browser refused) through the status region.
- Swatches are buttons in a named group with `aria-pressed`, one tab stop (the optional "no color" swatch is the first), each with a tooltip of its name, moved between with the arrow keys (flipped in
  right-to-left), `Home` and `End`.
- A color chosen from a swatch, the screen or typed text is said aloud ("Color chosen: #5548a4") through a status
  region that is in the page from the start. Dragging says nothing extra: the sliders already speak.
- The thumbs are a white ring inside a black one, so one of the two is at least 3:1 against any color under it, and the
  focused thumb gets a third ring. Every control is at least 24 × 24 pixels. In Windows high-contrast mode the thumbs and
  the selected swatch are drawn in system colors.
- The color itself is never the only cue: the text entry always shows it as words and digits.
- For a form, the value lives on a hidden text input that carries `required` and the validation message; the browser's
  message points at the field, and focus goes to the text entry.
- A dev-mode console warning fires once per field if it has no accessible name.

</Callout>

## Code examples

```tsx
<ColorPicker aria-label="Brand color" defaultValue="#5548a4" />

{/* Controlled, with swatches, saved when the person is done */}
function Example() {
  const [color, setColor] = useState("#5548a4");
  return (
    <ColorPicker
      aria-label="Brand color"
      value={color}
      onValueChange={setColor}
      onValueCommit={save}
      swatches={["#5548a4", "#2e8a7d", { value: "oklch(0.7 0.15 60)", label: "Amber" }]}
    />
  );
}

{/* With opacity, written as oklch */}
<ColorPicker aria-label="Overlay" format="oklch" alpha defaultValue="#5548a480" />

{/* A form field with a visible label and helper text */}
<FormField label="Brand color" helperText="Used for buttons and links.">
  {(field) => <ColorPicker {...field} />}
</FormField>

{/* A native <div> attribute, passed straight through to the group */}
<ColorPicker aria-label="Brand color" title="Pick the brand color" />

{/* Submitted with a form, under a name, in the format */}
<form>
  <ColorPicker aria-label="Brand color" name="brand" required />
</form>
```
