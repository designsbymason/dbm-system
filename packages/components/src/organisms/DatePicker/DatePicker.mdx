<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="DatePicker" tier="Organism" />

A date field: separate day, month and year segments you type into or step with the arrow keys, and a button that
opens a calendar to pick from with a pointer or a finger. The value is a `"YYYY-MM-DD"` string — a calendar day
with no time of day and no timezone — whichever order the segments are written in, so there is nothing to parse
and it submits as it is. The order is chosen with `format`, never read from the browser's locale, so a
server-rendered page and the client agree. For a time of day, use `TimePicker`.

### Import

```tsx
import { DatePicker } from "@dbm-system/components";
```

and the `id` goes on the first segment, which is what a `FieldLabel`'s `htmlFor` should point at.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `DatePicker` for one calendar day: a birthday, a due date, a booking. For a start and an end, use a date range
  picker; for a time of day, `TimePicker`; for a date and a time, put the two side by side.
- Choose `format` for your users and say so explicitly; the field never guesses it from the locale. The same goes
  for `weekStartsOn`.
- Use `min` and `max` for a window and `isDateDisabled` for gaps in it (weekends, holidays, booked days); the
  calendar disables what cannot be reached.
- Use `min="today"` for "not in the past" and `max="today"` for "not in the future", instead of working out today's
  date yourself.
- Use `unavailableReason` when people will wonder why a day is greyed out ("Fully booked", "Closed"): it is read out,
  shown under the calendar and used as the form's message, which `isDateDisabled` alone cannot do.
- Use `presets` for the choices people make most ("Today", "In a week"), and `granularity="month"` for a month and year
  (a card's expiry, a billing month).
- Use `presentation={{ base: "full-width", sm: "anchored" }}` where the field is used on a phone: the panel spans the
  screen instead of floating beside a narrow field.
- Pass `today` when the page should not depend on the visitor's clock (a demo, a test, a booking made for a fixed
  day).
- Put it in a `FormField` for a visible label, helper text and error text wired together.
- Pass `labels` and `formatNumber` for a language that isn't English or digits that aren't 0–9, and the calendar's
  own `labels` through `calendarProps` for its month and weekday names.

</Callout>
<Callout tone="danger" title="Don't">

- Don't store or compare the displayed text. The value is `"YYYY-MM-DD"`, and it is `""` while the field is only
  partly filled or holds numbers that are not a real date (the 31st of February).
- Don't treat a `min`/`max` violation as refused input: the field flags it and still reports it, so your own
  validation decides what to do.
- Don't build your own "is it filled in?" check for a plain form: `required`, a half-filled field, an impossible date
  and a date the field flags are real form constraints, so the browser blocks the submit. Use a `FormField`'s
  `error` for rules of your own (an end before a start).
- Don't convert the value through `new Date("2026-10-03")` and then read it in local time: that string is read as
  UTC midnight and can show the day before. Split the string, or use a UTC formatter.
- Don't use it for a date range or several dates; the calendar inside is a single-day calendar.

</Callout>
</div>

## Best practices

- Typing works the way a native date field does: a digit that can't start a two-digit number is the whole number
  and moves on (a 4 in the day), one that can waits for a second, and the year takes four. A separator key
  (`/`, `.`, `-`, a space or the `separator` you chose) finishes the segment. `Backspace` clears a segment.
- A year typed one digit at a time passes through real dates (`"0002-10-03"`, `"0020-10-03"`…), so by default
  `onValueChange` is called for each. Treat each call as the current date — or set `commitOn="complete"` to hear only
  about a finished date, or `"blur"` to hear once, when the person is done. A day chosen in the calendar and the
  clear button are always reported at once.
- Held modes catch up on blur, `Enter`, the calendar closing and the clear button, and the segments always show the
  latest edit; only the report is held. A `value` set from outside while one is held wins over it.
- A date the field cannot make is `""`, and the field flags it: `31` in a February, or a month and day with no
  year yet. The form message says which (`labels.invalid`, `labels.incomplete`, `labels.unavailable`).
- `onFocus` and `onBlur` are for the field as a whole: they fire once on arriving and once on leaving, not as focus
  moves between the segments, the buttons and the calendar, so `onBlur` is the place for validate-on-blur.
- When the owner controls `value`, a change it doesn't apply is undone: the field shows what `value` says.
- The calendar opens on the month of the chosen date, or on today's month when the field is empty. For a field that
  should open somewhere else, pass `calendarProps`'s `defaultMonth`.
- Pressing the day that is already chosen is a choice too: it closes the calendar and reports nothing, since nothing
  changed.
- Use `container` when the panel would be clipped or must live somewhere else (an element inside a dialog or a
  shadow root, or a box that scopes a demo); the other layer settings are not exposed, since the field sets the
  collision padding and the side itself.
- The panel is anchored to the whole field (`align="start"` lines its edge up with the field's), flips to the other
  side when there is no room, and closes with the button, `Escape` or a press elsewhere; a press elsewhere leaves focus
  where the person put it.
- By month, the grid can only disable what `min` and `max` rule out: `isDateDisabled` and `unavailableReason` still
  flag a month that has been chosen, and are written as `"YYYY-MM"`, but the grid does not grey it out.
- A preset's function is asked for its date only once today is known, so a server-rendered preset button starts
  disabled and is enabled after the first render in the browser.
- `rounded` draws the calendar's days (the chosen day, today's ring and the focus ring included) and its month buttons as
  circles, and the cells of the grid of months by month; the field's own corners do not change. It replaces passing
  `rounded` through `calendarProps`.
- In a table row or a toolbar, drop to `size="sm"` or `"xs"`; each size is as tall as an `Input` at the
  same step, so a row of fields lines up.

## Accessibility

<Callout tone="info" title="A group of spinbuttons, with a dialog holding a date grid">

- The field is a `role="group"` named by `aria-label` or `aria-labelledby` (a `FormField` supplies the label), and
  each segment is an `<input role="spinbutton">` named for what it is (Day, Month, Year), with its range (the day's
  maximum follows its month and year), current value and a text value (`03`, or "Empty") announced.
- Each segment is its own tab stop, as in a native date field. `ArrowLeft`/`ArrowRight` move between segments
  (also a separator key), `ArrowUp`/`ArrowDown` step the segment (the day and month wrap, the year does not),
  `Home`/`End` go to its least and greatest, and `Backspace` clears it. `Alt`+`ArrowDown` opens the calendar.
- A phone's keyboard that doesn't report keys is handled through the text it inserts, and a pasted or autofilled date
  (`03/10/2026`) fills every segment, and the segments ask for a numeric keyboard.
- For a form, the value lives on a hidden `<input type="date">` that carries `required` and the validation messages;
  the browser's message points at the field, and focus goes to the first empty segment.
- The calendar button has an accessible name, and opens a `role="dialog"` holding the `Calendar`, which is a WAI-ARIA
  date grid: one tab stop, arrow keys by day and week, `Home`/`End` along the week, `Page Up`/`Page Down` by month.
  Focus goes to the chosen day (or today); choosing a day fills the segments and closes it, and `Escape` closes
  it, in both cases returning focus to the button. Unavailable days stay focusable and are `aria-disabled`.
- `hasError`, an out-of-range or unavailable date and an impossible date set `aria-invalid`, and `required` sets
  `aria-required`, on each segment (a group can't carry either); `disabled` sets `aria-disabled` and removes the
  segments from the tab order.
- A press on the box's padding or a separator goes to the nearest segment, as in a native date field. Every button
  is at least 24 × 24 pixels.
- The month segment is announced by name ("October") when it has a value; the digits are what is shown.
- A date that is unavailable keeps its place in the calendar's arrow-key order, is `aria-disabled`, and has its
  reason as part of its name ("Wednesday, October 21, 2026, Fully booked"); the same text is shown under the calendar
  (hidden from assistive technology, which has it already) and is the form message for a typed date.
- The calendar button is `aria-haspopup="dialog"` with `aria-expanded`, and `aria-controls` while the panel is open.
  Closing the panel gives focus back to where it was opened from (the segment, for `Alt`+`ArrowDown`; otherwise the
  button), except after a press elsewhere, which leaves focus wherever the person put it. The preset buttons are a
  named group.
- A date chosen in the calendar, the grid of months or a preset is said aloud ("Date chosen: 10/16/2026", from
  `labels.chosen`) through a status region that is in the page from the start, because focus goes back to a button
  whose name does not change. Typing says nothing extra: the segments already speak.
- Everything the field says (segment names, "Empty", button names, form messages) is in `labels`, and the digits it
  shows and announces go through `formatNumber`, so what a person sees is what a screen reader reads.
- The segments always read left to right, in a right-to-left page too, and the buttons and the calendar follow `dir`.
  In Windows high-contrast mode the focused segment is drawn in the system highlight colours.
- A dev-mode console warning fires once per field if it has no accessible name.

</Callout>

## Code examples

```tsx
<DatePicker aria-label="Start date" defaultValue="2026-10-03" />

{/* Controlled, day first, with a window and no weekends */}
function Example() {
  const [date, setDate] = useState("");
  return (
    <DatePicker
      aria-label="Delivery date"
      value={date}
      onValueChange={setDate}
      format="dmy"
      separator="."
      min="2026-10-01"
      isDateDisabled={(day) => new Date(day + "T00:00:00Z").getUTCDay() % 6 === 0}
    />
  );
}

{/* A form field with a visible label, helper text and an error */}
<FormField label="Birthday" helperText="Month, day, year" error={error}>
  {(field) => <DatePicker {...field} format="mdy" />}
</FormField>

{/* Not in the past, with presets and a reason for the days that are taken */}
<DatePicker
  aria-label="Booking date"
  min="today"
  presets={[{ label: "Tomorrow", value: (today) => nextDay(today) }]}
  unavailableReason={(date) => (booked.has(date) ? "Fully booked" : undefined)}
/>

{/* A card's expiry: a month and year only, as "YYYY-MM" */}
<DatePicker aria-label="Expires" granularity="month" min="today" />

{/* A native <div> attribute, passed straight through to the group */}
<DatePicker aria-label="Start date" title="Pick a start date" />

{/* Submitted with a form, under a name, as "YYYY-MM-DD" */}
<form>
  <DatePicker aria-label="Check-in" name="checkIn" required />
</form>
```
