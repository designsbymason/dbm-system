<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="CommandPalette" tier="Organism" />

A window for finding and running things by typing. Press <Kbd>Ctrl</Kbd> + <Kbd>K</Kbd> (<Kbd aria-label="Command">⌘</Kbd> + <Kbd>K</Kbd> on a Mac)
from anywhere on the page, type a few letters, and choose a command with the arrow keys and Enter, a mouse or a finger.
It suits an application with more places and actions than a menu can hold: go to a page, switch a setting, run a report.
It is a *modal* `Dialog` (the page behind is dimmed and can't be reached while it is open) with a search field and a
list inline in it. Focus never leaves the search field; the highlighted command is *pointed at* rather than focused,
which is how a *combobox* (a text field that controls a list) works in assistive technology.

It is not a `Menu`, which is a short list of actions beside the thing that opened it, and not a `Combobox`, which
chooses a value for a form field. Nothing is chosen here: a command runs.

### Import

```tsx
import { CommandPalette } from "@dbm-system/components";
```

## Properties

`CommandPalette` also accepts any other native `<div>` attribute beyond what is listed here (e.g. `title`, `lang`,
`onKeyDown`) — passed straight through to the dialog panel, as are `ref`, `className`, `style`, `id` and `data-testid`.
It is drawn with `Dialog`, so what `Dialog.Content` does with a prop it does here.

### The shape of a command

A command is an object in the `commands` array.

| Field | What it does |
|---|---|
| `value` | A unique id within its list. It is how `recent` names a command and how rows are keyed. |
| `label` | The text shown and searched. |
| `textValue` | The text to search instead of `label`, when the label is not what someone would type. |
| `description` | A second, smaller line under the label. |
| `icon` | An icon before the label, a component from `@dbm-system/icons`. |
| `group` | The heading to list it under. Commands with the same group are listed together. |
| `keywords` | Words the search matches but the row never shows ("preferences" for "Settings"). |
| `shortcut` | The keys to show at the row's end, as one string (`"⌘N"`) or one string per key (`["Ctrl", "N"]`). The names `mod`, `cmd`, `ctrl`, `alt` and `shift` are drawn for the platform: `["mod", "N"]` is ⌘N on a Mac and Ctrl N elsewhere. It displays a hint and binds nothing. |
| `disabled` | `true`, or a string giving the reason, shown as the row's tooltip and read out after its name. |
| `onSelect` | Runs when it is chosen; may return a promise. |
| `closeOnSelect` | `false` keeps the palette open after it runs. |
| `items` | Commands it opens as a list of its own. |
| `argument` | Asks for a value before it runs: `{ placeholder, initialValue, validate }`. |
| `placeholder`, `emptyContent` | For a command with `items`: the search field's placeholder and the note for no results while its list is open. |

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use it as the quick way to anything: a page, a record, an action. Keep the commands people reach for most near the top, and put the rest behind `keywords`.
- Give every command a short, distinct `label` and put detail in `description`, so the row reads at a glance.
- Group commands (`group`) when there are more than about eight, so the empty search is a map and not a wall.
- Show a `shortcut` for a command that has a key, and bind that key yourself: the hint is only a label.
- Say why a command can't run with `disabled="reason"`, rather than leaving it dimmed and unexplained.
- Return a promise from `onSelect` for work that takes a moment, so the palette waits and shows progress instead of closing on something that then fails.
- List recently used commands first with `recent` once someone has a history to show.
- Offer a visible way in (`trigger`) beside the hotkey: not everyone knows the key, and a touch screen has none.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it as the only way to reach a function: it is a shortcut, and every command should exist somewhere on the page too.
- Don't use it to choose a value for a form field: that is `Combobox` or `Select`.
- Don't put controls inside a row: a row is chosen as a whole, and focus never enters it.
- Don't nest lists more than one level: `items` of a command inside a list are ignored. Flatten, or use `group`.
- Don't fetch on every key without `filter={false}` and `loading`: the built-in search only narrows the commands you have given it.
- Don't rely on the placeholder alone to say what the palette does; give it a `labels.title` that names it in your words.

</Callout>
</div>

## Best practices

- **The hotkey is the palette's own.** `hotkey` defaults to `mod+k`, where `mod` is ⌘ on an Apple platform and Ctrl elsewhere. It works from anywhere, including from inside a text field, and the press is kept from the browser, which takes the combination from the few that reserve it (Ctrl+K focuses the address bar's search in some). Choose another combination with `hotkey="mod+shift+p"`, or turn it off with `hotkey={false}` and open the palette yourself.
- **Write shortcut hints as words when a symbol is unclear.** `["Ctrl", "N"]` is read as two keys; a glyph like `⌘` may not be read at all. The hint is display only and binds nothing.
- **Search matches every word, in any order,** in a command's label (or `textValue`) and its `keywords`, ignoring case and accents. A label that starts with a word ranks above one that has it inside, and a match in `keywords` ranks last. Commands keep their group's place, so a heading never jumps as someone types, and equal matches keep the order you gave.
- **A search at the top level also finds the commands inside lists.** Typing "dark" lists "Dark" under the heading "Change theme", and choosing it runs it without opening the list. The parent's label is searched too, so "theme dark" finds it. A disabled parent's commands are left out, and `searchNested={false}` turns the behaviour off. Inside a list the search covers that list alone.
- **A row says why it matched.** When a word is found only in a command's `keywords`, never in its label, the row ends with that keyword in quotes ("preferences" after typing "prefer"), so a match through a word the row never shows is not a mystery.
- **Try a choice before it is made.** `onHighlightChange` is called with the highlighted command as the keys or the pointer move it, and with `null` when none is highlighted or the palette closes. Use it to preview (a theme, a page) and put things back on `null`. The palette draws no preview of its own.
- **A command can ask for a value.** With an `argument`, choosing it turns the search field into the entry for it, under a Back button, and one row says what Enter will do: "Run with “name”". `validate` returns a message to refuse the text, which replaces that row's words and makes Enter do nothing; empty text is refused without asking. `onSelect` receives the text as `details.argument`. A command with both `items` and an `argument` opens its `items`.
- **Modes are reached by a prefix.** With `modes`, typing `>` at the start of the search lists that mode's commands and searches what follows; the prefix stays in the text, so deleting it leaves the mode, and the footer hints each one. Modes apply at the top level only, and `recent` and `suggested` name top-level commands. They are props: the palette keeps no store of commands.
- **Cut a long empty list with `maxPerGroup`.** Each group shows its first few while the search is empty, followed by a row ("Show 3 more") that shows the rest of that group; the row is reached with the arrow keys like any other. Searching lists every match, and the recent and suggested groups are never cut. `suggested` lists commands after `recent` under their own heading, and a command shows once, in the first group that names it.
- **The forward arrow opens a list.** With the caret at the end of the text, Right (Left in right-to-left) opens the highlighted command's list or asks for its value; Tab is not used for this, so it keeps moving focus as it does everywhere in the dialog. The highlighted row ends with an Enter key to say what runs it.
- **A list can speak for itself.** A command with `items` can set a `placeholder` ("Search themes…") and an `emptyContent` for its own list; the search field is then named after the list (`labels.searchIn`) and so is the listbox.
- **`recent` is a list of values you keep.** The palette remembers nothing between openings, because what counts as recent (per person, per workspace, after a round trip) is yours to say. A command shows once: under the Recent heading while the search is empty, and in its usual place once something is typed.
- **A command that returns a promise is busy until it settles.** The row shows a spinner, the palette ignores Escape and a press on the scrim, no other command runs, and it closes when the promise resolves unless `closeOnSelect` is `false`. A rejection keeps it open, announces `labels.failed` and calls `onSelectError`; with no handler the rejection is left unhandled so it is not lost silently.
- **A command that opens something else needs nothing special.** Open a `ConfirmDialog` or a `Dialog` from `onSelect` and focus goes to it, not back to where the palette was opened.
- **Search on a server with `filter={false}`.** Pass new `commands` as `onQueryChange` reports typing, and `loading` while they are on their way. The palette then lists exactly what you give it.
- **The palette starts afresh each time it opens:** the search, the open list and the highlight reset. Control `query` to keep what was typed.
- **A long list is drawn a window at a time.** Rows have a fixed height, so a thousand commands cost no more than twenty.
- **Phone-sized presentation is opt-in.** `fullScreen={{ base: true, sm: false }}` with `showCloseButton` fills the screen on a phone. It is off by default.

## Accessibility

<Callout tone="info" title="A modal dialog holding a combobox whose focus never leaves the search field">

- The panel is a `dialog` with `aria-modal`, named by `labels.title` ("Command palette"), `aria-label` or `aria-labelledby`. The page behind it is hidden from assistive technology and can't be scrolled or reached, and focus returns to what opened it when it closes.
- The search field is a native text input with `role="combobox"`, `aria-expanded="true"`, `aria-controls`, `aria-autocomplete="list"` and `aria-haspopup="listbox"`. The highlighted command is named by `aria-activedescendant`, so a screen reader reads each one as the arrow keys reach it.
- The list is a `listbox`; each command is an `option`. Inside a list opened from a command, the search field and the list are named after that command. A keyword shown on a row because it made the row match is part of the row's name. One that can't run has `aria-disabled`, and its reason is read after its name. Groups are named by their heading; in a list long enough to be windowed, each command is read with its group's name instead.
- "No results" and "Loading…" are rows that can't be chosen, so the list is never empty to assistive technology. A loading list is `aria-busy`, and a palette waiting on a command is `aria-busy` too.
- The number of results is announced in a status region that was already in the page, only when it changes as someone types or opens a list, never when the palette merely opens. A failed command and an error are announced when they appear.
- The Back button has an accessible name (`labels.back`) and is at least 24 × 24 pixels, as is every row. Enter while an input method is composing a character does nothing.
- The Enter key drawn at the end of the highlighted row is hidden from assistive technology, so a row's name does not change as the highlight moves. A shortcut's modifier symbols (⌘ ⌃ ⌥ ⇧) have plain-language names.
- The footer's key hints are decoration and are hidden from assistive technology; they are also not drawn on a touch screen. A shortcut on a row is part of the row's name.
- The search row's focus ring is drawn inside its own edge. In Windows high contrast the highlighted row is outlined and the lines between the sections are kept.

</Callout>

| Key | Behaviour |
|---|---|
| Ctrl + K (⌘K), or `hotkey` | Opens the palette; pressed again, closes it. Works from inside a text field. |
| Right arrow (Left in right-to-left) | With the caret at the end of the text, opens the highlighted command's list, or asks for its value. |
| Down arrow, Up arrow | Highlights the next or previous command that can run, wrapping at the ends. |
| Page Down, Page Up | Move the highlight ten commands. |
| Enter | Runs the highlighted command, opens its list, asks for its value, or shows the rest of a capped group. |
| Backspace | In a list opened from a command, with an empty search, goes back one level. |
| Escape | Closes the palette, from any level. Does nothing while a command is running. |
| Tab | Moves to the Back button when there is one; otherwise it stays in the dialog. |
| Home, End, Left, Right | Move the caret in the search text, as in any field. |

## Code examples

```tsx
{/* The smallest palette: Ctrl+K (⌘K) opens it, a trigger is optional */}
<CommandPalette
  commands={[
    { value: "new-file", label: "New file", group: "File", shortcut: ["Ctrl", "N"], onSelect: newFile },
    { value: "settings", label: "Open settings", group: "App", keywords: ["preferences"], onSelect: openSettings },
  ]}
/>

{/* A visible way in beside the hotkey, and a different key */}
<CommandPalette hotkey="mod+shift+p" trigger={<Button variant="secondary">Search…</Button>} commands={commands} />

{/* Work that takes a moment: the palette waits, and a failure keeps it open */}
<CommandPalette
  commands={[{ value: "sync", label: "Sync now", onSelect: () => api.sync() }]}
  onSelectError={(error, item) => toast.error(`${item.label} failed`)}
/>

{/* A command that opens a list of its own */}
<CommandPalette
  commands={[
    { value: "theme", label: "Change theme", items: [
      { value: "light", label: "Light", onSelect: () => setTheme("light") },
      { value: "dark", label: "Dark", onSelect: () => setTheme("dark") },
    ] },
  ]}
/>

{/* A list that speaks for itself; a search at the top level finds its commands too, under "Change theme" */}
<CommandPalette
  commands={[
    { value: "theme", label: "Change theme", placeholder: "Search themes…", emptyContent: "No such theme", items: themes },
  ]}
/>

{/* Ask for a value before running, and try a choice as it is highlighted */}
<CommandPalette
  commands={[{ value: "rename", label: "Rename file", argument: { placeholder: "New name…" }, onSelect: (item, { argument }) => rename(argument) }]}
  onHighlightChange={(item) => preview(item?.value ?? null)}
/>

{/* Several sets of commands by prefix, and a long empty list cut to a few per group */}
<CommandPalette commands={commands} modes={[{ prefix: ">", label: "Actions", commands: actions }]} maxPerGroup={3} suggested={["new-file"]} />

{/* A search done on a server: pass the commands as they arrive, and the search text back */}
<CommandPalette filter={false} query={query} onQueryChange={setQuery} loading={isFetching} commands={results} />

{/* Opened from your own code, and told why it opened or closed */}
<CommandPalette
  controllerRef={palette}
  hotkey={false}
  commands={commands}
  onOpenChange={(open, { reason }) => track(open, reason)}
/>
<Button onClick={() => palette.current?.toggle()}>Commands</Button>

{/* Native props pass through to the dialog panel: a language for assistive technology, a test id */}
<CommandPalette lang="fr" data-testid="palette" labels={{ title: "Palette de commandes", placeholder: "Tapez une commande…" }} commands={commands} />

{/* Words in another language, and numerals that differ */}
<CommandPalette
  dir="rtl"
  formatNumber={new Intl.NumberFormat("ar-EG").format}
  labels={{ noResults: "لا توجد نتائج", results: (count) => `${count} نتيجة` }}
  commands={commands}
/>
```
