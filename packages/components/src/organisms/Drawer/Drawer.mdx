<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Drawer" tier="Organism" />

A panel attached to one edge of the screen that slides in over the page, for work that belongs beside
the page and not in a window over it: a set of filters, a settings or detail panel, a navigation menu on
a phone, a form that doesn't deserve a dialog. Like a `Dialog`, the page behind it is dimmed by a
**scrim** (a translucent layer over the page), can't be scrolled or clicked, and keyboard focus is held
inside until it closes. A compound component, meaning it is made of named sub-parts you compose
together: `Drawer.Trigger`, then `Drawer.Content` holding a `Header`, a `Body` that scrolls and a
`Footer`. `side` says which edge it is attached to, and can change with the screen.

### Import

```tsx
import { Drawer } from "@dbm-system/components";
```

## Properties

`Drawer` itself renders no DOM element of its own: it is a plain context provider around its
sub-parts, so it has no `className`/`style`/`id`/`data-testid`/`ref` of its own to accept.

<PropertiesTable of={DrawerRootStories} order={propOrder} />

### Drawer.Trigger properties

The element that opens the drawer on click. Also accepts any other native `<button>` attribute beyond
what's listed here (e.g. `onFocus`, `disabled`), passed straight through.

<PropertiesTable of={DrawerTriggerStories} order={triggerPropOrder} />

### Drawer.Content properties

The drawer panel itself, with its scrim. Also accepts any other native `<div>` attribute beyond what's
listed here (e.g. `onKeyDown`, `dir`), passed straight through to the panel. `role`, `aria-modal` and
`data-state` are set by the drawer and can't be replaced.

<PropertiesTable of={DrawerContentStories} order={contentPropOrder} />

### Drawer.Header properties

The top section: usually a `Drawer.Title` and optionally a `Drawer.Description`. Also accepts any other
native `<div>` attribute beyond what's listed here.

<PropertiesTable of={DrawerHeaderStories} order={headerPropOrder} />

### Drawer.Title properties

The drawer's name, rendered as a heading. Takes no `id`: the drawer generates one and points its
`aria-labelledby` at it. Also accepts any other native heading attribute beyond what's listed here.

<PropertiesTable of={DrawerTitleStories} order={titlePropOrder} />

### Drawer.Description properties

A sentence or two on what the drawer is for. Takes no `id`, for the same reason as the title. Also
accepts any other native `<p>` attribute beyond what's listed here.

<PropertiesTable of={DrawerDescriptionStories} order={descriptionPropOrder} />

### Drawer.Body properties

The main content: a scroll region that takes the height left between the header and the footer.
`className`, `style` and `id` go on its outer frame. Also accepts any other native `<div>` attribute
beyond what's listed here.

<PropertiesTable of={DrawerBodyStories} order={bodyPropOrder} />

The bottom section: the drawer's actions. Also accepts any other native `<div>` attribute beyond what's
listed here.

<PropertiesTable of={DrawerFooterStories} order={footerPropOrder} />

### Drawer.Close properties

An element that closes the drawer on click, placed anywhere inside `Drawer.Content`. Also accepts any

## Variants

### Sides

`side` is `end` by default. `start` and `end` are logical: the left and right edges in left-to-right
text, and swapped in right-to-left, so a menu opens from the side a reader expects.

### A size the scale doesn't have

`size` takes a step of the scale. For the one drawer that needs another width, pass a CSS length or a
number of pixels; it is the same extent on the same axis, with the same strip of the page left showing
on a smaller screen.

<Canvas of={DrawerStories.CustomSize} />

### A sheet you can swipe away

On a touch screen, drag the handle or the header toward the edge: a short drag settles back and a long
or quick one closes it, with the reason `"swipe"`. A mouse can drag the handle too (and only the
handle, so a drag on the title still selects it). This demo is drawn inside a box; the close button,
Escape and the scrim still work, so nothing needs the gesture.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use a `Drawer` for work that belongs beside the page: filters, a detail or settings panel, a
  navigation menu on a phone, an inspector the person works next to.
- Pick the edge by what it holds: `end` for details and settings, `start` for navigation, `bottom`
  for a short sheet of actions on a phone.
- Use a responsive `side` for something that is a sheet on a phone and a panel on a desktop
  (`{ base: "bottom", md: "end" }`), rather than two components.
- Give it a title, and a footer with the one primary action, so what it is for and how to finish it
  are clear.
- Keep long content in `Drawer.Body`, which scrolls while the header and footer stay put.
- Leave `swipeToDismiss` on for a sheet on a phone: it is what people try first. It never replaces the
  close button, which stays.
- Use a step of `size` where one fits, so every drawer in an app shares its widths, and a length only
  for the odd one out.
- Use `modal={false}` for a panel the person works beside (an inspector), and leave it modal for
  anything that should take over their attention.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use a `Drawer` for a short question that must be answered: that is an `AlertDialog` or a
  `ConfirmDialog`.
- Don't use it for a form that deserves the centre of the screen and the person's full attention:
  that is a `Dialog`.
- Don't open a drawer from a drawer. Replace its content instead, or use a `Dialog` for the second step.
- Don't turn `closeOnOutsideClick` off to keep people in: the close button stays, and work that would
  be lost should be confirmed before it is.
- Don't use it as a permanent navigation column. A `Sidebar` is that; it uses a drawer only for its
  phone layout.

</Callout>
</div>

## Best practices

- In a right-to-left app wrap the app in a `DirectionProvider` (or use `AppShell`, which provides its direction). The whole panel,
  header, body and footer, then reads right to left, in a drawer opened from anywhere. The system does not read the page's `dir`: an
  app with neither the provider nor a `dir` on `Drawer.Content` gets a left-to-right panel unless the page sets `dir` itself.
- On a phone a side panel leaves a strip of the page showing, so there is always something to press to
  close it. Keep its content within what fits the remaining width.
- A `bottom` sheet is as tall as its content, up to the `size` step, and its body scrolls past that.
- Use `onOpenChangeComplete` to reset a form or release something heavy once the drawer is gone;
  `onOpenChange` fires when it starts closing, with the exit still to play.
- On a phone, Back usually should close an open drawer. That is the app's router's to decide, so it is a
  recipe (below) rather than a prop.
- While a drawer saves (`busy`), keep it open and show your own progress; the close button stays
  focusable but does nothing until it is done.
- Use `onOpenChange`'s `reason` to tell the person pressing outside from their pressing Cancel, so a
  half-filled form can be confirmed on one and not the other.
- `keepMounted` keeps a filter panel's state while it is closed, so reopening it picks up where the
  person left off.
- Open a `ConfirmDialog` from a drawer freely, and lighten its scrim (`scrimOpacity={40}`), since the
  two scrims stack.

## Accessibility

<Callout tone="info" title="The dialog pattern: named, described, modal, with focus held inside">

- The panel is `role="dialog"` with `aria-modal="true"` while modal. `Drawer.Title` names it and
  `Drawer.Description` describes it, wired with `aria-labelledby` and `aria-describedby`
  automatically.
- Focus moves into the drawer when it opens and returns to the trigger when it closes. `Tab` and
  `Shift+Tab` loop inside while it is modal, and the rest of the page is hidden from assistive
  technology and can't be scrolled or clicked.
- `Escape`, a press on the scrim and the close button all close it; each can be turned off, and none of
  them works while `busy`. A non-modal drawer takes none of the page: no scrim, no scroll lock, no
  trap.
- The close button is a real, labelled button in the corner, at least 24 by 24 pixels. While busy it is
  `aria-disabled` and dimmed but still focusable, so focus isn't dropped from it.
- `start` and `end` follow the text direction, so in right-to-left text a `start` drawer is on the
  right and slides in from there.
- Swipe-to-dismiss is an extra way to close it, for a touch or a pen from the handle and the header and
  for a mouse from the handle alone, and is never the only one: the close button, Escape and the scrim all work. The handle is decorative
  (`aria-hidden`), and the gesture is off while the drawer is `busy`.
- Under `prefers-reduced-motion` the panel fades instead of sliding. A device's notch and home
  indicator are kept clear on the edges the panel touches.
- In forced-colours mode a shadow isn't drawn, so the panel is told apart by the border on its inner
  edge.

</Callout>

## Code examples

```tsx
<Drawer>
  <Drawer.Trigger asChild>
    <Button>Filters</Button>
  </Drawer.Trigger>
  <Drawer.Content>
    <Drawer.Header>
      <Drawer.Title>Filters</Drawer.Title>
      <Drawer.Description>Narrow the list of results.</Drawer.Description>
    </Drawer.Header>
    <Drawer.Body>
      <Checkbox>In stock</Checkbox>
    </Drawer.Body>
    <Drawer.Footer>
      <Drawer.Close asChild>
        <Button variant="secondary">Cancel</Button>
      </Drawer.Close>
      <Button>Apply</Button>
    </Drawer.Footer>
  </Drawer.Content>
</Drawer>

{/* A bottom sheet on a phone, a side panel from md up */}
<Drawer.Content side={{ base: "bottom", md: "end" }} size="lg">
  …
</Drawer.Content>

{/* Open it from your own state, and say why it closed */}
<Drawer
  open={open}
  onOpenChange={(next, { reason }) => {
    if (!next && reason === "outside") confirmDiscard();
    else setOpen(next);
  }}
>
  <Drawer.Content keepMounted busy={saving}>
    …
  </Drawer.Content>
</Drawer>

{/* A width the scale doesn't have */}
<Drawer.Content size="min(90vw, 40rem)" side="end">
  …
</Drawer.Content>

{/* Do something once it is gone, not when it starts to go */}
<Drawer onOpenChangeComplete={(open) => !open && resetFilters()}>
  …
</Drawer>

{/* Let the browser's Back button close it on a phone: open it from your own state and keep one history
    entry while it is open. Use your router's own API instead if you have one. */}
const [open, setOpen] = useState(false);
useEffect(() => {
  if (!open) return undefined;
  window.history.pushState({ drawer: true }, "");
  const close = () => setOpen(false);
  window.addEventListener("popstate", close);
  return () => {
    window.removeEventListener("popstate", close);
    // closed some other way: take the entry back out so Back doesn't land on an empty step
    if (window.history.state?.drawer) window.history.back();
  };
}, [open]);
<Drawer open={open} onOpenChange={setOpen}>…</Drawer>

{/* A native <div> attribute, passed straight through to the panel */}
<Drawer.Content aria-describedby="what-this-filters" dir="rtl" side="start">
  …
</Drawer.Content>
```
