<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="NavigationMenu" tier="Organism" />

The navigation of a site's header when some of its items open a **panel** of links under them: a row of
triggers, each opening a panel of grouped links with descriptions and icons (a mega menu), beside plain
links that go straight to a page. A compound component, meaning it is made of named sub-parts you compose
together: `NavigationMenu.List` of `NavigationMenu.Item`s, each holding a `NavigationMenu.Trigger` with its
`NavigationMenu.Content`, or a `NavigationMenu.Link`; a panel holds `NavigationMenu.Group`s of links.

It is a navigation, not a menu of actions: it follows the disclosure pattern (buttons that show and hide
links), not `role="menu"`. A short dropdown of links is a `Navbar.Group`; a list of actions is a `Menu`.
Drawn inside a `Navbar` it follows the bar, and in the bar's phone menu it becomes a stacked list.

### Import

```tsx
import { NavigationMenu } from "@dbm-system/components";
```

## Properties

`NavigationMenu` is the `<nav>` element (or, inside a `Navbar`, a list item in the bar's own navigation), so it also
accepts any other native `<nav>` attribute beyond what's listed here (e.g. `onFocus`, `title`), passed straight through.
`dir` is set by the menu and can't be replaced by a same-named attribute.

<PropertiesTable of={NavigationMenuListStories} order={listPropOrder} />

## Variants

### Panels under their own items

By default every panel is drawn in one shared area that resizes between them as you move from trigger to
trigger. `viewport={false}` hangs each panel from its own item instead, centred under it with `panelAlign="center"`.

<Canvas of={NavigationMenuStories.OwnPanels} />

### Stacked

`presentation="stacked"` draws a vertical list in which each trigger is a disclosure button and its links nest beneath
it, for a phone or a side panel. One item is open at a time. A width map chooses by screen:
`presentation={{ base: "stacked", md: "mega" }}`.

<Canvas of={NavigationMenuStories.Stacked} />

### Marking the current page

`current` on a link, or on the trigger of the item whose panel holds the page, marks it. `aria-current="page"` is set on a link
whichever look is chosen. Inside a `Navbar` the bar's choice applies.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use it when a few items each lead to several pages worth grouping, with a line of description each.
- Keep a panel to a handful of links in one to three groups, and head each group with a short `label`.
- Give a trigger a name that says what is behind it ("Products"), and the menu a name (`aria-label`) when the page has more than one navigation.
- Mark the current page with `current`, from your router, so it is right on a server-rendered page.
- Put a link that is a destination on its own (Pricing) beside the triggers as a `NavigationMenu.Link`.
- Use `asChild` with your router's link so navigation stays client-side.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a short dropdown of links: that is `Navbar.Group`. Don't use it for actions (Edit, Delete): that is a `Menu`.
- Don't put a form, a dialog trigger or anything that is not navigation in a panel.
- Don't nest a menu in a panel, or open a panel from anything but its trigger.
- Don't make a trigger that is also a link: a trigger opens a panel; give the destination its own link inside it.
- Don't rely on hover alone: a phone has none, and a trigger opens on a press too.

</Callout>
</div>

## Best practices

- **A panel is a list of destinations, not a page.** If you need more than three columns, the site's structure wants a landing page, which the trigger's neighbour can link to.
- **Say it once.** Put a link to the section's own page first in its panel (an "Overview" row), so the person who wants the section as a whole has somewhere to go.
- **Let it follow the bar.** Inside a `Navbar` the current-page look, rounding and direction come from the bar, so there is one set of choices to make and the phone menu is written for you.
- **Descriptions earn their line.** A description is part of the link's name, so write it as a short phrase that helps someone choose, not a repeat of the title.
- **Test with the keyboard first.** Every panel must be reachable without a pointer; `Tab` goes into an open panel and `Escape` returns to its trigger.

## Accessibility

<Callout tone="info" title="A named navigation of a list, with disclosure buttons that say whether their panel is open">

- The root is a `<nav>` named by `aria-label` (`labels.navigation`, "Main", otherwise), holding a `role="list"` list whose items are `role="listitem"`, which keeps list semantics under Safari with VoiceOver, where a list without markers loses them. Inside a `Navbar` the bar's own navigation is the landmark and the menu is one of its list items.
- A trigger is a `<button>` with `aria-expanded` and `aria-controls` pointing at its panel. It is not `role="menu"` or `aria-haspopup`: the panel is links, not menu items.
- The current page is `aria-current="page"`. A trigger with `current` is only drawn as current: it has no `aria-current`, since a button is not a page. A disabled link is `aria-disabled` and stays focusable, with its click blocked; a disabled trigger is a native disabled button and leaves the tab order.
- A link's description and badge are part of its name, and an external link's new tab is announced by a visually hidden "(opens in a new tab)".
- Keys: `Tab` and `Shift+Tab` move through the triggers and links in order, and `Tab` from an open trigger goes into its panel. `Enter`, `Space` or `ArrowDown` opens a panel; `ArrowLeft` and `ArrowRight` move between the triggers and links of the bar; `Escape` closes the panel and returns focus to its trigger; `Enter` follows a link.
- The primitive keeps a hidden, focusable stop beside an open trigger to hand focus into the panel. An accessibility checker that runs while a panel is open reports it (`aria-hidden-focus`); the stop is how `Tab` gets into the panel and is gone when the panel closes.
- A link in an exiting panel stays in the page until its exit animation ends, a fraction of a second, as for any animated panel.
- In the stacked form there is no primitive: a trigger is a disclosure button with `aria-expanded` and `aria-controls`, its links are plain tab stops, and a collapsed panel is `hidden`, so its links leave the tab order and the accessibility tree.
- Every trigger and link is at least 24 by 24 CSS pixels at every size. The current-page marks keep an outline in forced colours, and an open panel keeps its border and loses its shadow.
- With a reduced-motion preference a panel fades in and out and does not slide.

</Callout>

## Code examples

```tsx
<NavigationMenu aria-label="Primary">
  <NavigationMenu.List>
    <NavigationMenu.Item value="products">
      <NavigationMenu.Trigger>Products</NavigationMenu.Trigger>
      <NavigationMenu.Content>
        <NavigationMenu.Group label="Platform" columns={2}>
          <NavigationMenu.Link href="/analytics" icon={ChartBarIcon} description="Dashboards for every team">
            Analytics
          </NavigationMenu.Link>
          <NavigationMenu.Link href="/automation" icon={LightningIcon} description="Workflows that run themselves">
            Automation
          </NavigationMenu.Link>
        </NavigationMenu.Group>
      </NavigationMenu.Content>
    </NavigationMenu.Item>
    <NavigationMenu.Item>
      <NavigationMenu.Link href="/pricing" current>
        Pricing
      </NavigationMenu.Link>
    </NavigationMenu.Item>
  </NavigationMenu.List>
</NavigationMenu>

{/* A native <nav> attribute (title), a link that opens a new tab, and a router's link */}
<NavigationMenu aria-label="Primary" title="Site navigation">
  <NavigationMenu.List>
    <NavigationMenu.Item>
      <NavigationMenu.Link href="https://example.com/docs" target="_blank" rel="noopener noreferrer">
        Docs
      </NavigationMenu.Link>
    </NavigationMenu.Item>
    <NavigationMenu.Item>
      <NavigationMenu.Link asChild>
        <RouterLink to="/blog">Blog</RouterLink>
      </NavigationMenu.Link>
    </NavigationMenu.Item>
  </NavigationMenu.List>
</NavigationMenu>

{/* In a Navbar: a mega menu in the bar, a stacked list in the phone menu */}
<Navbar>
  <Navbar.Brand>dbM</Navbar.Brand>
  <Navbar.Links aria-label="Primary">
    <NavigationMenu>
      <NavigationMenu.List>{/* items */}</NavigationMenu.List>
    </NavigationMenu>
  </Navbar.Links>
</Navbar>

{/* const [open, setOpen] = useState("");  control the open item, "" for none */}
<NavigationMenu value={open} onValueChange={setOpen}>{/* … */}</NavigationMenu>
```
