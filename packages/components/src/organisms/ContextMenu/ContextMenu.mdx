<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="ContextMenu" tier="Organism" />

A menu of actions that opens where the pointer is pressed: a right-click, a long press on a touch screen, or
the context-menu key on a focused element. Built on Radix ContextMenu, so arrow keys, typeahead, Home/End,
Escape and focus return come with it, as do checkbox and radio items, labelled groups and submenus. Its items
are `Menu`'s, drawn the same. A compound component: put `ContextMenu.Trigger` (the area) and
`ContextMenu.Content` inside `ContextMenu`, and the items, labels, groups and separators inside the content.

A context menu is a shortcut, never the only way to an action. Nothing on the page says it is there, a touch
screen needs a long press, and some people never right-click, so every action in it should also be reachable
from a visible control (a button on the row, a toolbar).

### Import

```tsx
import { ContextMenu, useContextMenuController } from "@dbm-system/components";
```

## Properties

`ContextMenu` itself renders no DOM element of its own: it is a plain context provider around its sub-parts,
so it has no `className`/`style`/`id`/`data-testid`/`ref` of its own to accept. The item, label, group and
separator parts below are `Menu`'s own parts, so their properties are the same.

<PropertiesTable of={ContextMenuRootStories} order={propOrder} />

### ContextMenu.Trigger properties

The area a right-click opens the menu from. Also accepts any other native `<span>` attribute beyond what's
listed here (e.g. `onFocus`, `title`), passed straight through. While the menu is open it carries
`data-state="open"`. A focusable area (`tabIndex`) is how a person without a mouse reaches the menu.

<PropertiesTable of={ContextMenuTriggerStories} order={triggerPropOrder} />

### ContextMenu.Content properties

The floating panel, rendered in a portal on the page and placed at the point that was pressed. Also accepts any
other native `<div>` attribute beyond what's listed here (e.g. `onFocus`, `title`), passed straight through to
the panel. The reading direction is set on `ContextMenu`, not here. `role` and `aria-orientation` are set by
the menu and can't be replaced.

<PropertiesTable of={ContextMenuContentStories} order={contentPropOrder} />

### ContextMenu.Item properties

An action. Also accepts any other native `<div>` attribute beyond what's listed here (e.g. `onFocus`,
`title`), passed straight through. `role` and `aria-disabled` are set by the menu and can't be replaced.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use a `ContextMenu` for actions on the thing under the pointer (a file, a table row, a card, a point on a
  canvas), as a shortcut beside the same actions in a visible control.
- Make the area focusable (`tabIndex={0}` on the trigger, or `asChild` onto a link, a button or a row that already
  is) so the context-menu key and Shift+F10 open it for someone using only a keyboard. If the area is just a box,
  give it a role and a name that say what it is, since a focusable element with neither is announced as plain text.
- Put the destructive action last, after a `ContextMenu.Separator`, with `tone="danger"`.
- Keep the labels short and start them with the verb, so typeahead finds them from their first letters.
- Style the area from `[data-state="open"]` so the thing the menu is about stays marked while it is open.
- Keep a dialog an item opens beside the menu, opened from state; focus goes back to the row when it closes.
- Name a key with `openOnKeys` where the platform has none (macOS has no context-menu key), and keep a visible
  button for the same actions: `controllerRef` or `useContextMenuController()` opens the menu from one.

</Callout>
<Callout tone="danger" title="Don't">

- Don't make a context menu the only way to do something. It is invisible until used, needs a long press on a
  touch screen, and is unreachable from an area that can't take focus.
- Don't use it for a menu opened from a button: that is a `Menu`, which is named after its trigger and opens on a
  press or a key.
- Don't put a form or arbitrary content in it. A context menu holds `menuitem`s only.
- Don't rely on a `shortcut` hint to make a key work. It only displays the key; bind it yourself.
- Don't set `open` to open it from code: with no press to place it, it is drawn at the top-left corner of the page.
  Use the controller's `openAt` or `openFrom`, which open it where you say. `open` is for following and closing it.
- Don't turn off the browser's menu on a whole page. Wrap only the thing that has actions.

</Callout>
</div>

## Best practices

- On a phone, draw it as a sheet: `presentation={{ base: "sheet", md: "menu" }}` is a panel across the bottom of the screen with
  48px rows and the page dimmed behind it, and the floating menu from `md` up. It is the same menu, with the same keys and parts. A
  submenu covers it under a "Back" row (set the text with `labels`), so keep a sheet's menus shallow. A sheet has no swipe to dismiss:
  it closes on a press on the dimmed page, Escape, or choosing an item.

- Order the items by how often they are used, and keep a menu to about seven items before grouping them with
  `ContextMenu.Label` and `ContextMenu.Separator`.
- A leading `icon` helps recognition when most items have one; give every item in a set one, or none.
- For a row, put the trigger on the row with `asChild` and keep its "more" button (a `Menu`) beside the text: the
  two hold the same actions, and the button is the discoverable one. They work together in one row.
- Name the panel with `aria-label` when the area's own text would not say what the menu is for. A context menu has
  no trigger button to be named after.
- A menu taller than the room there is scrolls inside its panel, with a fade at each end that has more behind it.
- The panel is placed at the pointer and flips to stay inside the viewport; give it `collisionPadding` where a
  fixed header or footer covers the edge.

## Accessibility

<Callout tone="info" title="Keyboard and ARIA state come from Radix's menu primitive">

- The panel is `role="menu"` and holds `menuitem`, `menuitemcheckbox` and `menuitemradio` elements. It has no
  trigger button to be named after, so give it an `aria-label` when its purpose isn't clear.
- A right-click, a long press of 700 milliseconds with a finger, and the context-menu key or Shift+F10 on a
  focused area open the menu. An area that can't take focus can't be opened from the keyboard. macOS has no
  context-menu key, so `openOnKeys` names the keys an app wants there; the menu then opens under the focused element.
- `ArrowDown` and `ArrowUp` move between items, skipping disabled ones; `Home` and `End` jump to the first and
  last; typing letters moves to the item that starts with them. Arrow keys stop at the ends unless `loop` is set.
- `ArrowRight` opens a submenu and `ArrowLeft` closes it, swapped in right-to-left text (`dir="rtl"`).
- `Enter` and `Space` choose the focused item. `Escape` closes the menu (one level of submenu at a time) and
  returns focus to the element that had it. `Tab` is not used inside an open menu.
- A `description` is announced as the item's description, not as part of its name. A `disabledReason` keeps the
  item focusable and `aria-disabled`, shows the reason in a tooltip and announces it as the description. An item
  with a pending action is `aria-busy` and `aria-disabled`, and ignores presses until it settles.
- A `ContextMenu.Label` inside a `ContextMenu.Group` or `ContextMenu.RadioGroup` names that group through
  `aria-labelledby`, wired automatically.
- The focused item is highlighted with a quiet fill and, for the keyboard, a ring in the focus colour drawn inside
  it. In forced-colours mode the highlighted item is drawn with an outline in a system colour.
- Every item is at least 24 × 24 CSS pixels at every size, and 48px tall in a sheet.
- A sheet is the same `role="menu"`: the keys, typeahead and focus handling are the floating menu's. A submenu in a sheet is drawn over
  the menu it opened from and starts on its "Back" row; the menu under it is inert while the submenu is open, so neither Tab nor a screen
  reader reaches it, and focus returns to its trigger when the submenu closes.
- The menu is modal by default: the rest of the page is hidden from assistive technology and can't be pressed
  while it is open, and a press outside only closes it. Set `modal={false}` for a menu that coexists with the page.
- Focus goes back to the element that had it when the menu opened. When the menu was opened on an area that
  can't take focus, there is nothing to return to.

</Callout>

## Code examples

```tsx
{/* A file list: each row is a focusable trigger with the same actions on its own button */}
<ContextMenu>
  <ContextMenu.Trigger asChild tabIndex={0}>
    <li>quarterly-report.pdf</li>
  </ContextMenu.Trigger>
  <ContextMenu.Content aria-label="File actions">
    <ContextMenu.Item icon={PencilSimpleIcon} shortcut="F2" onSelect={rename}>Rename</ContextMenu.Item>
    <ContextMenu.Item icon={CopyIcon} onSelect={duplicate}>Duplicate</ContextMenu.Item>
    <ContextMenu.Separator />
    <ContextMenu.Item icon={TrashIcon} tone="danger" onSelect={remove}>Delete</ContextMenu.Item>
  </ContextMenu.Content>
</ContextMenu>

{/* Mark the row while its menu is open */}
{/* li[data-state="open"] { background: var(--dbm-bg-brand-subtle); } */}

{/* Controlled open state, to follow or close the menu: a press on the trigger is what opens it */}
function Example() {
  const [open, setOpen] = useState(false);
  return (
    <ContextMenu open={open} onOpenChange={setOpen}>
      <ContextMenu.Trigger tabIndex={0}>Right-click here</ContextMenu.Trigger>
      <ContextMenu.Content>
        <ContextMenu.Item>Rename</ContextMenu.Item>
      </ContextMenu.Content>
    </ContextMenu>
  );
}

{/* A checkbox item leaves the menu open, and a radio group does too */}
<ContextMenu.CheckboxItem checked={showGrid} onCheckedChange={setShowGrid}>
  Show grid
</ContextMenu.CheckboxItem>
<ContextMenu.RadioGroup value={sort} onValueChange={setSort} aria-label="Sort by">
  <ContextMenu.RadioItem value="name">Name</ContextMenu.RadioItem>
  <ContextMenu.RadioItem value="date">Date</ContextMenu.RadioItem>
</ContextMenu.RadioGroup>

{/* An action that takes time: a spinner shows and the menu closes when the promise resolves */}
<ContextMenu.Item onSelect={() => exportRows()} onSelectError={(error) => showError(error)}>
  Export as CSV
</ContextMenu.Item>

{/* An item that opens a confirmation: the dialog sits beside the menu, opened from state */}
function Row() {
  const [confirming, setConfirming] = useState(false);
  return (
    <>
      <ContextMenu>
        <ContextMenu.Trigger asChild tabIndex={0}>
          <li>quarterly-report.pdf</li>
        </ContextMenu.Trigger>
        <ContextMenu.Content>
          <ContextMenu.Item tone="danger" onSelect={() => setConfirming(true)}>Delete</ContextMenu.Item>
        </ContextMenu.Content>
      </ContextMenu>
      <ConfirmDialog open={confirming} onOpenChange={setConfirming} title="Delete this file?" onConfirm={deleteFile} />
    </>
  );
}

{/* Opened from code: a button, or a key of your own. The controller opens it where you say, as a right-click would */}
function Card() {
  const menu = useRef<ContextMenuController>(null);
  return (
    <>
      <ContextMenu controllerRef={menu}>
        <ContextMenu.Trigger tabIndex={0} openOnKeys={["Alt+ArrowDown"]}>Project card</ContextMenu.Trigger>
        <ContextMenu.Content>
          <ContextMenu.Item>Rename</ContextMenu.Item>
        </ContextMenu.Content>
      </ContextMenu>
      <Button onClick={(event) => menu.current?.openFrom(event.currentTarget)}>Actions</Button>
    </>
  );
}
{/* menu.current?.openAt({ x: 300, y: 200 }) opens it at a point; menu.current?.close() closes it */}

{/* A native <span> attribute on the area, passed straight through */}
<ContextMenu.Trigger title="Right-click for actions">Project card</ContextMenu.Trigger>
```
