<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="DirectionProvider" tier="Atom" />

Says which way the app reads, once, near the root. Every component that takes a `dir`, and every overlay that
opens in a portal without one (`Dialog`, `Popover`, `Tooltip` and the rest), uses the nearest provider's
direction when it is given none of its own, so a right-to-left app wraps its root instead of passing `dir` to
each part. A `dir` on the component itself still wins. The provider renders no element and changes no style: the
layout itself follows the `dir` attribute of the page, which `AppShell` sets for you. It does not set `lang`.

### Import

```tsx
import { DirectionProvider, useDirection } from "@dbm-system/components";
```

## Properties

`DirectionProvider` draws no element, so it accepts no native attributes and takes no `ref`, `className`, `style`, `id` or
`data-testid`: there is nothing to put them on.

<PropertiesTable of={DirectionProviderStories} order={propOrder} />

`useDirection(own?)` returns the direction a component should use: `own` when given, else the nearest
provider's, else `"ltr"`.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Wrap the app once, as high as the direction is known (the user's language setting).
- Also set `dir` on the page (`<html dir="rtl">`), or use `AppShell`, which sets both. Setting only the page's `dir` is not enough for a
  component with a portalled panel or a scrolling body (`Menu`, `Select`, `Dialog`, `Drawer`, `Popover`): they read the provider, not the page.
  The provider alone, without the page's `dir`, is enough for every component here.
- Content you put in the `Portal` atom yourself is outside the provider's reach: `Portal` draws no element of its own, so it sets no
  direction. Give that content a `dir` (or use `useDirection()` to set one).
- Give a component its own `dir` only for an island that reads the other way.

</Callout>
<Callout tone="danger" title="Don't">

- Don't expect the provider to flip the layout: it carries a value, not a style.
- Don't nest a provider to change the direction of a single component; give that component a `dir`.

</Callout>
</div>

## Best practices

- Read the direction in your own parts with `useDirection()` rather than checking the document.
- Nothing is detected: the provider says what the app tells it.
- Keep `lang` and `dir` together. The provider sets neither on the page, so put `lang` (which picks the fonts and the shaping for a script)
  and `dir` on the root element, as the Languages story does on each card.
- Give it `"ltr"` or `"rtl"` only. Any other value (from untyped configuration) is refused with a development warning and read as `"ltr"`.

## Accessibility

<Callout tone="info" title="The provider adds nothing to the accessibility tree">

It renders no element. The page's `dir` and `lang` are what assistive technology reads; keep them in step
with the provider's value.

</Callout>

## Code examples

```tsx
// Wrap the app once; every component that takes a dir, and every overlay, follows it
<DirectionProvider dir="rtl">
  <Navbar>
    <Navbar.Brand href="/">dbM</Navbar.Brand>
  </Navbar>
</DirectionProvider>
```

```tsx
// A dir on a component itself wins, for one island that reads the other way
<DirectionProvider dir="rtl">
  <Tabs dir="ltr" defaultValue="overview">
    <Tabs.List aria-label="Sections">
      <Tabs.Trigger value="overview">Overview</Tabs.Trigger>
    </Tabs.List>
    <Tabs.Content value="overview">Overview text</Tabs.Content>
  </Tabs>
</DirectionProvider>
```

```tsx
// Your own part follows the same rule: its own value, else the provider's, else "ltr"
function Price({ dir, children }: { dir?: "ltr" | "rtl"; children: ReactNode }) {
  const direction = useDirection(dir);
  return <span dir={direction}>{children}</span>;
}
```

```tsx
// Content you portal yourself is outside the provider, so give it the direction
function Note({ children }: { children: ReactNode }) {
  const dir = useDirection();
  return (
    <Portal>
      <div dir={dir}>{children}</div>
    </Portal>
  );
}
```

## Design tokens used

`DirectionProvider` references **no tokens**: it renders nothing of its own.
