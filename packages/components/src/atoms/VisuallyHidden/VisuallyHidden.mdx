<ComponentHeader title="VisuallyHidden" tier="Atom" />

Hides content visually while keeping it in the accessibility tree, so screen reader users still get
information sighted users would otherwise only infer from visual context — icon-only button labels,
supplemental instructions, skip links. Applies a fixed, well-established CSS technique (absolute
positioning clipped to a 1px box) rather than `display: none` or `visibility: hidden`, both of which
would also remove the content from the accessibility tree. `VisuallyHidden` is a thin wrapper around
Radix's own `VisuallyHidden` — used internally by this system's own Docs pages (the visually-hidden
"Intro" heading every page starts with, including this one), and usable directly anywhere sighted
users and screen reader users need genuinely different content.

### Import

```tsx
import { VisuallyHidden } from "@dbm-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `VisuallyHidden` to give an icon-only control (a close button, an icon-only `IconButton`) a
  real accessible name when the surrounding design has no room for visible text.
- Use `focusable` for a skip link or any other visually-hidden control a sighted keyboard user
  should be able to discover by tabbing — it stays invisible for mouse and screen-reader users, but
  reveals itself the instant it (or a descendant) receives focus.
- Use `asChild` when `children` is already the element that should own the hidden styling directly
  (an `<a>` skip link) — it avoids an extra, purely structural wrapper `<span>`.

</Callout>
<Callout tone="danger" title="Don't">

- Don't reach for `VisuallyHidden` when `aria-label`/`aria-labelledby` already covers the need (e.g.
  `IconButton`'s own required `aria-label`) — both approaches work, but a plain attribute is simpler
  when there's no reason to also expose the text as real, selectable DOM content.
- Don't use `display: none` or `visibility: hidden` for the same goal — both remove content from the
  accessibility tree entirely, which is the opposite of what `VisuallyHidden` is for.
- Don't put interactive content inside a non-`focusable` `VisuallyHidden` expecting a mouse user to
  reach it — it's permanently off-screen for them; only a keyboard/screen-reader user can ever
  interact with it in that mode.

</Callout>
</div>

## Best practices

- Keep visually-hidden text short and purely functional (a label, a cue like "(opens in a new
  tab)") — it's announced by assistive technology, not read as prose.
- Pair `focusable` with real, visible styling of your own once revealed — `VisuallyHidden` only
  restores normal layout flow on focus, it adds no background, border, or positioning to make the
  revealed state stand out.
- Prefer `asChild` over a wrapper `<span>` whenever the child is itself the element that needs the
  hidden treatment (a real `<a>` skip link, not `<VisuallyHidden><a>...</a></VisuallyHidden>`) — one
  fewer structural element in the accessibility tree to reason about.

## Accessibility

<Callout tone="info" title="This component exists entirely for accessibility — a few things to get right">

- **Content stays in the accessibility tree at all times.** Unlike `display: none`/`visibility:
  hidden`, screen readers still announce it — that's the whole point.
- **Don't duplicate an already-accessible name.** If a control already has a visible label, wrapping
  additional text in `VisuallyHidden` right next to it can make assistive technology announce the
  name twice — reserve it for content that has no other accessible name yet.
- **`focusable` content still needs a real, visible focus indicator once revealed** — `VisuallyHidden`
  restores normal layout on focus, but relies on the browser's/your own `:focus` styling for the
  indicator itself, same as any other focusable element.

</Callout>

## Code examples

```tsx
// Icon-only button — a real accessible name with no visible text
<button type="button">
  <TrashIcon />
  <VisuallyHidden>Delete item</VisuallyHidden>
</button>
```

```tsx
// A cue appended to visible text, announced but not shown
<a href="https://example.com">
  External link
  <VisuallyHidden> (opens in a new tab)</VisuallyHidden>
</a>
```

```tsx
// Skip link — hidden until a sighted keyboard user tabs to it
<VisuallyHidden asChild focusable>
  <a href="#main-content">Skip to main content</a>
</VisuallyHidden>
```

## Design tokens used

`VisuallyHidden` itself references **no tokens** — its hidden styling is a fixed, non-visual CSS
clipping technique (absolute positioning, zero-size box), not a themed surface. Any visual appearance
in the `focusable` revealed state comes entirely from `children`, which supplies its own token usage.
