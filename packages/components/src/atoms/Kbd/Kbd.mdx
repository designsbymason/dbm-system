<ComponentHeader title="Kbd" tier="Atom" />

A keyboard shortcut or key name, styled like a physical keycap — a raised, bordered box with a
subtle bottom-edge shadow, distinct from `Code`'s flat inline-reference pill. Renders a native
`<kbd>` (semantically "a single key or combination of keys from a keyboard"). Compose multiple
side by side for a chord, e.g. `⌘` + `K`.

### Import

```tsx
import { Kbd } from "@dbm-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `Kbd` for an actual keyboard key or shortcut — a single key (`Esc`), a symbol (`⌘`), or a
  chord composed from multiple `Kbd`s side by side (`⌘` + `K`).
- Pass `aria-label` on a symbol-only `Kbd` (`⌘`, `⇧`, `⌥`, `⌃`) so screen readers announce a
  plain-language name instead of the raw glyph.
- Let its font size stay fixed — a keycap should read as a consistent visual regardless of the
  surrounding text size, the same way a physical key doesn't resize with the sentence around it.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use `Kbd` for a literal code reference or identifier — use `Code` instead, which is
  visually similar (monospace, both compact) but reads as running text rather than a physical key.
- Don't rely on the raw glyph alone for a symbol key — without `aria-label`, `⌘` may be announced
  inconsistently (or not at all) across screen readers.
- Don't override the font size to match surrounding text — that defeats the fixed-size keycap
  design (see `Best practices` below).

</Callout>
</div>

## Best practices

- `Kbd` and `Code` are visually similar (both monospace, both compact) but serve different roles —
  `Kbd` represents a physical keyboard key, `Code` marks up a literal code reference. Don't use one
  for the other's job even though the visual difference is subtle.
- For a chord, compose multiple `Kbd`s with a plain `+` (or similar) between them, as running text
  — there's no dedicated chord-group sub-component, since a plain composition already reads clearly
  and doesn't force a fixed separator convention on every locale/platform.
- Keep the label short — a full word (`Esc`, `Enter`, `Tab`) or a single symbol reads well; a long
  phrase doesn't fit the keycap's compact, fixed-size treatment.

## Accessibility

<Callout tone="info" title="Symbol keys need an explicit label">

- Renders a native `<kbd>`, which already communicates "this is a keyboard key" to assistive
  technology with no ARIA required for text content like `"Esc"`.
- **Symbol-only content needs `aria-label`.** A Unicode glyph like `⌘` isn't reliably announced by
  screen readers on its own — pass `aria-label="Command"` (or the equivalent plain-language name)
  so it announces something meaningful.
- **`keys` names itself.** A combination drawn from `keys` is one `role="img"` group with a plain-language name ("Command Shift P", "Ctrl Shift P"), and each keycap inside it is hidden from assistive technology so the symbols are not read one by one. Pass `aria-label` to say it your own way.
- No keyboard interaction — `Kbd` is not an interactive element itself; it documents a shortcut,
  it doesn't trigger one.

</Callout>

## Code examples

```tsx
<Kbd>Esc</Kbd>
```

```tsx
// A chord, composed from multiple Kbd
<Text as="span">
  <Kbd aria-label="Command">⌘</Kbd> + <Kbd>K</Kbd> to open the command palette
</Text>
```

```tsx
// A combination drawn for the platform: ⌘ ⇧ P on a Mac, Ctrl + Shift + P elsewhere
<Kbd keys="mod+shift+p" />
```

```tsx
// A native <kbd> attribute (title) passed straight through
<Kbd title="Escape key">Esc</Kbd>
```
