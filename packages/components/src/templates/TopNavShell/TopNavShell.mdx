<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="TopNavShell" tier="Template" />

The page frame of an application with no sidebar: a skip link, an optional banner, a header that stays at the top of the window, the page's
one `<main>` and a footer. The page scrolls as a whole. It is **layout and wiring only**. You put your own
[`Navbar`](/docs/organisms-navigation-navbar--docs) in the header and keep every prop it has; the shell adds the sticky slot it sits in, an
optional second row of navigation that sticks with it, the page's one `<main>` landmark, the skip link's target, and a footer that sits at the
bottom of the window on a page too short to fill it.

The shell keeps the header in view itself, so leave the `Navbar` without its own `sticky`. While the page is scrolled the header casts a shadow on
it (a line in forced colours), and a notch or a home indicator never covers the header or the footer. Given the router's page, the shell moves focus to
the new page and announces it. Below the `Navbar`'s own `collapseBelow` width its links move into a menu behind a button, which the `Navbar` draws;
the sub-navigation scrolls sideways when it does not fit. On this page the live examples sit in a framed box 36rem tall, which is wider than a phone;
open a story from the sidebar on its own and narrow the window to see the phone layout, and scroll to see the header stay at the top.

### Import

```tsx
import { Navbar, TopNavShell } from "@dbm-system/components";
```

## Variants

### A second row of navigation

`TopNavShell.SubNav` is a row inside the header, under the `Navbar`, so it sticks with it. Give it a `label` and it draws a named `nav` around its
`TopNavShell.SubNavLink`s (round ghost buttons, the current one in the subtle tint the `Navbar` gives its own current link); or leave the label out and
put a `nav` of your own in it. The links are centred while they all fit. When they do not, the row scrolls sideways, fades at the edge that has more
links beyond it, and brings the current link into view. `bordered={false}` drops the line under it, and `align="start"` puts the links at the start.

<Canvas of={TopNavShellStories.WithSubNav} />

### A sub-navigation that scrolls away

`sticky={false}` on the row keeps only the bar at the top of the window; the row scrolls away with the page. The bar must be the header's first
child (a `Navbar` is). The shadow and, with `stickyHeader="auto"`, the sliding move to the bar.

<Canvas of={TopNavShellStories.SubNavScrollsAway} />

### A header that hides on scroll

`stickyHeader="auto"` slides the header out of view while the reader scrolls down and brings it back on the first scroll up, at the top of the page,
and whenever focus or an open menu is inside it, so the keyboard never loses the bar. With reduced motion it appears and disappears without sliding.

<Canvas of={TopNavShellStories.AutoHide} />

### A footer of actions

`variant="actions"` on `TopNavShell.Footer` makes it a bar that stays at the bottom of the window until the page's own end: the Save and Cancel of a long
form. `variant="compact"` pads the ordinary footer tighter. For a footer of several columns, put a `Grid` of link lists in `TopNavShell.Content` inside it.

<Canvas of={TopNavShellStories.ActionsFooter} />

### A banner above the header

`TopNavShell.Banner` is a notice above the header. It scrolls away with the page and does not stick.

<Canvas of={TopNavShellStories.WithBanner} />

### A short page

On a page too short to fill the window the footer sits at the bottom of the window, not under the content.

<Canvas of={TopNavShellStories.ShortPage} />

### A page that is loading

`busy` on `TopNavShell.Main` puts a thin bar along the top of the main area, sets `aria-busy` and announces "Loading" politely. The page stays where it is.

<Canvas of={TopNavShellStories.Busy} />

### A page with nothing to show

An `EmptyState` in the content, with the next step. Its title is the page's `h1`.

<Canvas of={TopNavShellStories.EmptyPage} />

### A page that failed to load

`tone="danger"` and `announce` on the `EmptyState`: the message is read out once, when it appears.

<Canvas of={TopNavShellStories.ErrorPage} />

### A header that scrolls away

With `stickyHeader={false}` the header scrolls away with the page, and there is no shadow, since the shadow belongs to a header that sticks.

<Canvas of={TopNavShellStories.StaticHeader} />

### Moving to another page

Press a link in the bar: its page goes to the shell as `pageKey` and `pageTitle`, which moves focus to the main area and announces the new title.

<Canvas of={TopNavShellStories.PageChange} />

### Content kept to a narrower width

`TopNavShell.Content` centres the page and limits its width on the `Container` steps; the default is `xl`.

<Canvas of={TopNavShellStories.ContentWidth} />

`width` on `TopNavShell.Content` picks the width by what the page is: `reading` for text, `dashboard` for cards and tables, `full` for a page that fills
the window. `size` takes the steps of `Container` directly and replaces it.

### The head of a page

`TopNavShell.PageHeader` is the head of a page: the title as its `h1`, an optional trail of breadcrumbs above it, a description under it and the
page's actions at the end of the row, under the title on a phone. The demo pages on this page use it.

### The tab's title

`documentTitle` keeps the browser tab's title in step with `pageTitle`, so the router does not have to: `true` sets it to `pageTitle`, and a function
builds the whole title (`(title) => title + " · dbM"`). The title the document had comes back when the shell unmounts.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Put `TopNavShell.SkipLink` first and `TopNavShell.Header` after it. The shell draws the parts in the order you write them, which is the keyboard's
  tab order, so the skip link is the first stop.
- Put a `Navbar` in `TopNavShell.Header`, and leave it without its own `sticky`: the shell keeps the whole slot (the bar and the sub-navigation) in
  view. Use `Navbar.SkipLink` inside a `Navbar`, and `TopNavShell.SkipLink` when the header is not a `Navbar`: both go to `#main`, which is
  `TopNavShell.Main`'s `id`.
- Give the sub-navigation a `label` (or its own named `nav`), so the page's navigation landmarks are told apart from the bar's.
- Pass `pageKey` (the router's pathname) and `pageTitle`, so a screen-reader user and a keyboard user are told about a page change that no browser
  navigation announces.
- Keep a wide table or a long code block in a component that scrolls on its own (`Table`, `CodeBlock`): the page scrolls vertically and never
  scrolls sideways.
- Use `BackToTop` on a long page, and pass it the box that scrolls (`scrollContainerRef`) when the shell is drawn inside one.
- Give a page with nothing to show its own `EmptyState`, and a failed one `tone="danger"` with `announce`.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use `TopNavShell` for an app with a sidebar: [`AppShell`](/docs/templates-application-shells-appshell--docs) has the sidebar, the rail and
  the aside. Don't use it for a page with no header of its own either: a plain
  [`Container`](/docs/atoms-layout-container--docs) with `as="main"` is the page there.
- Don't put a second `<main>` inside it, and don't wrap a `Navbar` in `TopNavShell.Header as="header"`: a `Navbar` draws its own `<header>`, and the
  two would nest.
- Don't set `overflow` on an element around the shell, or give it a height: it makes that element the box the header sticks to, so the header stops
  following the window. The shell is as tall as the window already (and taller when the page is).
- Don't keep a tall banner above the header and expect it to stay: it scrolls away with the page.
- Don't put important navigation only in the sub-navigation of a phone: it scrolls sideways, so keep the few places everyone needs in the bar's menu.

</Callout>
</div>

## Best practices

- Choose `size` on `TopNavShell.Content` for the page's reading width: `xl` (the default) suits a page of cards, `md` suits a form or an article. A
  full-bleed section is a page's own element outside the content.
- Let the footer be small. It holds the links people look for at the end of a page (help, privacy, terms), and it sits at the bottom of the window on a
  short page, so it is always reachable.
- Printing prints the page, not the chrome: the skip link and the loading bar are left out, the banner, header and footer are ordinary rows and nothing
  sticks. Put your own page breaks in the page's own CSS.
- Name each `Navbar.Links` and each sub-navigation, so a screen reader's list of navigation landmarks tells them apart.
- Use `busy` for a page that is reloading its content: it keeps what is on screen and says so, where an `EmptyState` replaces it.
- The shell's shadow under the header marks that the page has scrolled. Keep it on a page that scrolls and turn it off with `scrolledEdge={false}`
  for a flat look, where the header is already separated from the page by its own surface.

## Accessibility

<Callout tone="info" title="Who provides which landmark">

The shell supplies `TopNavShell.Main` (the one `main`) and `TopNavShell.Footer` (the `contentinfo`). The banner `<header>` comes from the `Navbar` in the
header slot, or from `TopNavShell.Header as="header"` for a header built without one; each `Navbar.Links` and your sub-navigation's `nav` is a named
`navigation`. All of them are real elements, not roles on divs. The shell's own header slot is a plain `div` by default so that a `Navbar` is never
wrapped in a second banner.

</Callout>

| Key | Behaviour |
|---|---|
| `Tab` | Moves through the skip link, then the header (the bar, then the sub-navigation), then the main area's content, then the footer, in markup order. |
| `Tab` into a hidden header | Slides the header back into view (`stickyHeader="auto"`). |
| `Enter` on a skip link | Moves focus to `TopNavShell.Main`, past the header. |
| `Escape` in the bar's menu panel | Closes it and returns focus to the menu button (the `Navbar`'s own behaviour below its `collapseBelow` width). |

- `TopNavShell.Main` takes focus from the skip link and when the page changes (`tabindex="-1"`). A focus ring is drawn just inside its edge whenever
  the keyboard has focused it. The page scrolls as a whole, so the main area is not itself a tab stop.
- When `pageKey` changes, focus moves to `TopNavShell.Main` and, with `pageTitle`, the new title is announced politely. Neither happens on the first
  render, so the page's own load is not announced twice, and nothing happens while `pageKey` is left out. The shell does not scroll the window: that
  is the router's.
- While `busy` is set the main area has `aria-busy="true"` and a polite status region says "Loading"; when it clears the region empties, so nothing more
  is read out. The bar is decoration and hidden from assistive technology.
- The sticky header, the sub-navigation and the page's own sticky parts keep a fixed order of layers, so a bar of yours never paints over the header: the
  page's content on the system's `sticky` step, the header one step above it, the skip link on the `fixed` step, and every menu, popover and dialog above those.
- The scrolled-edge shadow is not the only way to tell that a page scrolls, and forced colours, which drop shadows, get a line instead. Motion on it
  respects `prefers-reduced-motion`.
- A header that hides on scroll (`stickyHeader="auto"`) never hides while focus is inside it or one of its menus is open, so a keyboard user does not
  lose the bar; with reduced motion it jumps instead of sliding. The sub-navigation's links are ordinary links in a named `nav`, the current one has
  `aria-current="page"` and, in forced colours, an underline besides its tint. The edge fades are decoration and never take a click.
- A notch or a home indicator never covers the shell: the header keeps the top inset clear, the frame the sides and the bottom, and the skip link is drawn
  below it.
- The shell adds no colour pairing of its own: the page background is the surface colour, and text inside uses the primary text colour (at least 4.5:1
  on it in every theme).
- The reading direction is the shell's (`dir`, else the nearest `DirectionProvider`'s), and the `Navbar` inside takes it from the shell. Set `lang` beside it.

## Code examples

```tsx
<TopNavShell pageKey={pathname} pageTitle={title}>
  <TopNavShell.SkipLink />
  <TopNavShell.Header>
    <Navbar contained>
      <Navbar.Brand href="/">Acme</Navbar.Brand>
      <Navbar.Links aria-label="Main">
        <Navbar.Link href="/projects" current>Projects</Navbar.Link>
        <Navbar.Link href="/reports">Reports</Navbar.Link>
      </Navbar.Links>
    </Navbar>
    <TopNavShell.SubNav>
      <nav aria-label="Project sections">…</nav>
    </TopNavShell.SubNav>
  </TopNavShell.Header>
  <TopNavShell.Main>
    <TopNavShell.Content>
      <h1>Projects</h1>
    </TopNavShell.Content>
  </TopNavShell.Main>
  <TopNavShell.Footer>© Acme</TopNavShell.Footer>
</TopNavShell>
```

```tsx
// A native attribute in use: name the main landmark by the page's own heading
<TopNavShell.Main aria-labelledby="page-title">
  <TopNavShell.Content>
    <h1 id="page-title">Projects</h1>
  </TopNavShell.Content>
</TopNavShell.Main>
```

```tsx
// With a router: the router's page goes to the shell, which moves focus and announces the title after each change
const { pathname } = useLocation();
return (
  <TopNavShell pageKey={pathname} pageTitle={titles[pathname]}>
    …
  </TopNavShell>
);
```

```tsx
// A banner, a header that scrolls away and a flat look
<TopNavShell stickyHeader={false} scrolledEdge={false}>
  <TopNavShell.Banner>
    <Alert banner tone="info"><Alert.Description>Maintenance tonight at 22:00 UTC.</Alert.Description></Alert>
  </TopNavShell.Banner>
  …
</TopNavShell>
```
