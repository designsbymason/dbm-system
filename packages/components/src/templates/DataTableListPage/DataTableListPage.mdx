<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Data Table List Page" tier="Template" />

A page that lists records in a table: a people directory with a search box, filters, sorting, paging, chosen
rows with bulk actions, a menu on each row and a confirmed removal. It is an **example page, not a component**.
Nothing here is exported from the package: you copy the page into your app and replace the data, the columns
and the words. What the page shows you is the part that is hard to get right, which is where the state lives
and how it reaches the table. The search, the filters, the sort, the page, the page size and the chosen rows
belong to your page; a request answers with one page of rows; and the table is driven entirely through its
controlled props.

It sits inside an [`AppShell`](/docs/templates-shells-appshell--docs), so the sidebar, the header
and the page's one `<main>` come from the shell. On this page the live examples sit in a framed box 36rem tall;
open a story from the sidebar on its own, and narrow the window, to see the phone layout.

## Variants

### With filters in force

Filters show as chips under the toolbar, and the count says how many people match. A chip's remove button, or
"Clear all", takes them off and goes back to page 1.

### With rows chosen

The toolbar shows how many rows are chosen, offers to choose every matching row across pages, and holds the

### Loading

The table keeps its height with placeholder rows, and the count says "Loading".

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Hold the filters, the sort, the page and the selection in your own state and give the table `sortMode="manual"`
  and a `totalCount` when the server does the work. The table never guesses at rows it was not given.
- Go back to page 1 and clear the selection whenever a filter changes. A page number or a chosen row that belonged to the
  old filter is wrong for the new one.
- Say which of the three empty cases you are in: no one yet (offer the first step), no one matching (offer to clear the
  filters) and a failed request (offer to try again).
- Ask before removing, say how many people, and name the person when it is one. Say what happened afterwards in a toast.
- Put focus somewhere sensible when the thing that had it is gone: the page's heading, after a removal.
- Use `Table`'s own scroll frame for a table that is wider than the window. The page never scrolls sideways.

</Callout>
<Callout tone="danger" title="Don't">

- Don't copy this page's simulated request. It stands in for your own: a fetch, a router's search parameters or a query
  library. Keep the page's state and replace where the rows come from.
- Don't put the whole list in the table when the server holds thousands of people. Page it, as here, or use the
  table's windowing for a long list that is not paged.
- Don't hide the selection's size. "Select all 137" means every row matching the filters on every page, and the
  confirmation has to say 137.
- Don't use a toast for a failed request. The table has nothing to show, so the page says so, in place.
- Don't remove straight away from a menu item. A removal that cannot be undone asks first.

</Callout>
</div>

## Best practices

- Lay the toolbar out in three columns: the count at the start, the search taking the room that is left, and the filters
  at the end. A filter is its name as plain text, then a button of a fixed width that shows only the choice, so choosing
  something never changes the button's size or moves what is beside it. Make the table's columns fixed shares of its
  width, so a longer value never moves one. On a phone, the toolbar is the search and a "Filters" button that opens both
  filters in a bottom sheet (with "Clear all" and "Done"), then the count; the button says how many filters are in force.
- Keep the toolbar's search, filters, count and bulk actions inside `DataTable.Toolbar`: the table places it above
  itself and hands it the table's state, so a count or a "select all" cannot disagree with the table. The footer here is
  drawn from the page's own state (`Select` and `Pagination`): a small rows-per-page button at the start, the page
  controls centred and the range ("1–10 of 137") right-aligned at the end. `DataTable.Pagination` is the same footer with
  the range before the select and the controls at the end, and needs no code of your own.
- Give every filter a chip. A person who has set three filters and sees an empty table needs to see why, and to take
  one off without opening a panel.
- Reserve the table's space while loading (`loadingRows` equal to the page size), so the pager and the footer do
  not jump when the rows arrive.
- Put the page's one `h1` in the main area, at the start. The shell already moves focus to it when the router's page
  changes (`pageKey`, `pageTitle`); give the heading `tabIndex={-1}` if your page also moves focus to it itself, as this
  one does after a removal.
- Give each toolbar its own name (`People table tools`, `Filters`, `Bulk actions`), so a screen reader's list of
  toolbars tells them apart.
- Keep the header's primary action (here "Add person") visible on a phone, and let the table scroll sideways inside its
  own frame rather than hiding columns.

## Accessibility

<Callout tone="info" title="One page, one main, one heading">

The shell supplies the page's one `main`, the `Navbar` the banner and the `Sidebar` a named navigation. The page adds
one `h1` and no other landmark. The table is named ("People"), the toolbars each have their own name, and the empty
and error states use `h2`, so the heading order never skips a level.

</Callout>

<ReferenceTable
  firstColumnWidth="20rem"
  columns={["Key", "Behaviour"]}
  rows={[
    ["`Tab`", "Moves through the header, the sidebar, the page's button, the search, the filters, the table's header buttons, the rows' controls and the pager, in that order."],
    ["`Enter` or `Space` on a filter", "Opens its panel. `Escape` closes it and returns focus to the button."],
    ["`Space` on a row's checkbox", "Chooses the row. The toolbar then shows how many are chosen."],
    ["`Enter` on a column heading's button", "Sorts by it; `Shift`+`Enter` adds it to the sort."],
    ["`Enter` on a row's menu button", "Opens the menu. `Escape` closes it."],
    ["`Escape` in the confirmation", "Cancels it and leaves everything as it was."],
  ]}
/>

- A chosen count, the filters in force and the number of results are announced politely as they change; a failed request is
  announced once, when it appears. Nothing is announced the first time the page loads.
- After a removal the row that had focus is gone, and so is the dialog's trigger, so focus goes to the page's heading, but
  only if it has fallen to the page: a person who has moved on keeps their place.
- Colour is never the only sign. A row is chosen when its checkbox is checked, a status is its word as well as its
  badge, and a filter is a chip with a name. In forced colours the same marks remain.
- The page adds no colour pairing of its own: every colour comes from the components it is built of.

## Code examples

```tsx
{/* Your own state: the filters, the sort, the page, the selection, and what the request answered with */}
<DataTable
  aria-label="People"
  columns={columns}
  data={rows}
  getRowId={(row) => row.id}
  getRowLabel={(row) => row.name}
  sortMode="manual"
  sort={sort}
  onSortChange={(next) => {
    setSort(next);
    setPage(1);
  }}
  page={page}
  onPageChange={setPage}
  pageSize={pageSize}
  onPageSizeChange={setPageSize}
  totalCount={matching}
  loading={loading}
  loadingRows={pageSize}
  selectionMode="multiple"
  selection={selection}
  onSelectionChange={setSelection}
  allSelected={allSelected}
  onAllSelectedChange={setAllSelected}
>
  <DataTable.Toolbar aria-label="People table tools">
    <TableToolbar.Row>
      <TableToolbar.Search>
        <SearchInput aria-label="Search people" onSearch={setQuery} />
      </TableToolbar.Search>
      <TableToolbar.Summary count={matching} loading={loading} />
    </TableToolbar.Row>
  </DataTable.Toolbar>
</DataTable>
{/* The footer under the table: Select for the rows per page, the range, and Pagination, from the same state */}
```
