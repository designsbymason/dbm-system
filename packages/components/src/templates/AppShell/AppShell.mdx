<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="AppShell" tier="Template" />

The page frame of an application: a navigation column on one side, a header across the top, a main
area for the page's content and an optional footer. It is **layout and wiring only**. You put your
own [`Sidebar`](/docs/organisms-navigation-sidebar--docs) and
[`Navbar`](/docs/organisms-navigation-navbar--docs) in its slots and keep every prop they have; the
shell adds the grid they sit in, the page's one `<main>` landmark, the skip link's target, and the
shared state that lets a menu button in the header open the sidebar's panel on a phone.

By default the frame is exactly as tall as the window and only the main area scrolls, so the
sidebar and the header never move. Below the sidebar's `collapseBelow` width the sidebar leaves the
page for a menu button and a slide-in panel, and its column disappears so the main area takes the
whole width. On this page the live examples sit in a framed box 36rem tall, which is wider than a
phone; open a story from the sidebar on its own and narrow the window to see the phone layout.

### Import

```tsx
import { AppShell, Navbar, Sidebar } from "@dbm-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Put `AppShell.Header` first in the markup. The shell places each slot in its own area, so the
  order does not change the layout, but it is the keyboard's tab order: a header first makes the
  skip link the first stop and the sidebar's links come after it.
- Put `Navbar.SkipLink` first in the `Navbar`. It links to `#main`, which is `AppShell.Main`'s `id`.
- Set the sidebar's own `side` to match `sidebarSide`, so its line and its phone panel are on the
  same edge, and pass the same `dir` to the shell, the `Sidebar` and the `Navbar` on a right-to-left
  page.
- Keep a wide table or a long code block inside `AppShell.Main` in a component that scrolls on its
  own (`Table`, `CodeBlock`); the main area scrolls vertically and never pushes the frame wider than
  the window.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use `AppShell` for a page with no navigation column or header of its own; a plain
  [`Container`](/docs/atoms-layout-container--docs) with `as="main"` is the page there.
- Don't put a second `<main>` or a second banner inside it. The shell owns the page's landmarks.
- Don't wrap the shell in an element with its own height: with `scroll="content"` it already fits
  the window, and a parent shorter than that clips it.
- Don't put an `AppShell` inside another `Sidebar.Provider` and expect the outer one to drive its
  sidebar. The shell renders its own provider, which replaces the outer one for everything inside it.
- Don't pass `collapsed`, `menuOpen` or their change handlers to the `Sidebar` itself. The shell's
  provider holds that state and the sidebar ignores the ones set on it, with a development warning.

</Callout>
</div>

## Best practices

- Choose `scroll="content"` for an application whose pages are long lists or tables, so the
  navigation is always in reach. Choose `scroll="page"` for a page that reads like a document: the
  page scrolls as a whole, and the shell keeps the header and the sidebar in view as it does.
- Put the collapse button (`Sidebar.Toggle`) in the sidebar's footer and the phone menu button
  (`Sidebar.MenuButton`) in the header: the shell's provider connects them to the same sidebar.
- Let the page set its own padding and maximum width inside `AppShell.Main`; the shell adds none, so
  a full-bleed table or a centred reading column are both possible.
- Give each `Sidebar.Nav` and each `Navbar.Links` its own name when there is more than one, so the
  navigation landmarks are told apart.
- Set the width of the sidebar on the `Sidebar` itself: `width` for the column on the page, and
  `panelWidth` for the drawer it becomes on a phone, if it should differ (`<Sidebar width="16rem"
  panelWidth="20rem">`). The shell has no width of its own to set. The drawer is never wider than the
  window less a sliver of the page that stays showing.

## Accessibility

<Callout tone="info" title="The shell owns the page's landmarks">

The `Navbar` is the page's `banner` (`<header>`), each `Sidebar.Nav` a named `navigation` (`<nav>`),
`AppShell.Main` the one `main` and `AppShell.Footer` the `contentinfo` (`<footer>`). All four are
real elements, not roles on divs.

</Callout>

| Key | Behaviour |
|---|---|
| `Tab` | Moves through the header first (the skip link is the first stop), then the sidebar, then the main area's content, in markup order. |
| `Enter` on the skip link | Moves focus to `AppShell.Main`, past the header and the sidebar. |

- `AppShell.Main` takes focus from the skip link (`tabindex="-1"`). While it scrolls
  (`scroll="content"` and more content than room) it is also a tab stop, so a keyboard user can scroll
  a page that has nothing focusable in it with the arrow and page keys; a page that fits, or one that
  scrolls as a whole, gets no extra stop. Whenever the keyboard has focused it, a focus ring is drawn
  just inside its edge.
- Below the `collapseBelow` width the sidebar's links are in a dialog opened from the menu button,
  with the focus handling `Drawer` provides, and are not on the page at all.
- The shell adds no colour pairing of its own: the page background is the surface colour, and text
  inside uses the primary text colour (at least 4.5:1 on it in every theme).
- With `scroll="page"` the header and the sidebar stay in view as the page scrolls. The shell measures
  the header's height once it is on the page, so on the server and for the first paint the header is an
  ordinary first row and scrolls away; it sticks from then on.

## Code examples

```tsx
<AppShell>
  <AppShell.Header>
    <Navbar>
      <Navbar.SkipLink />
      <Navbar.Brand href="/">Acme</Navbar.Brand>
      <Navbar.Actions>
        <Sidebar.MenuButton />
      </Navbar.Actions>
    </Navbar>
  </AppShell.Header>
  <AppShell.Sidebar>
    <Sidebar currentPath="/billing">
      <Sidebar.Content>
        <Sidebar.Nav>
          <Sidebar.Item href="/">Home</Sidebar.Item>
          <Sidebar.Item href="/billing">Billing</Sidebar.Item>
        </Sidebar.Nav>
      </Sidebar.Content>
      <Sidebar.Footer>
        <Sidebar.Toggle />
      </Sidebar.Footer>
    </Sidebar>
  </AppShell.Sidebar>
  <AppShell.Main>
    <h1>Billing</h1>
  </AppShell.Main>
</AppShell>
```

```tsx
// A native attribute in use: name the main landmark by the page's own heading
<AppShell.Main aria-labelledby="page-title">
  <h1 id="page-title">Billing</h1>
</AppShell.Main>
```

```tsx
// Controlled: keep the sidebar's collapsed state in your own store
<AppShell collapsed={collapsed} onCollapsedChange={setCollapsed}>
  …
</AppShell>
```
