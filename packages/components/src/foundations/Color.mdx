# Color

Use the **Brand** and **Mode** toolbar controls above to see every semantic swatch on this page
re-theme live — they're all driven by the same `var(--dbm-*)` custom properties the active
theme's stylesheet defines, the same mechanism every component uses.

## Primitive scales

Eight 11-step color scales (`50`–`950`), plus two fixed neutrals (pure white/black). These are
raw values with no assigned meaning — **components should never reference a primitive color
directly** (`var(--dbm-color-purple-600)`); always go through a semantic token (below), which is
what actually changes per brand/mode.

`purple-600` and `emerald-600` (marked ★) are the two brand-mandated anchor colors — every other
step in those two scales is generated from a shared perceptual lightness curve, shifted so it
passes exactly through the anchor's own lightness at step 600. The five status/neutral scales
(gray, red, amber, green, blue) have no anchor requirement and are shared, unmodified, across
both brand themes — status meaning (danger is red, success is green) doesn't change with brand.
Yellow is shared across both brands too; its semantic tokens are named `highlight`, for what it
is used for.

primitive step depending on the active brand/mode — that indirection is the entire point (see
[Foundations Overview](/docs/foundations-overview--docs) for why).

## Contrast verification

Every text/background pairing above has been checked against real WCAG contrast ratios, not
assumed — 4.5:1 for normal text, 3:1 for large text/non-text UI (icons, focus outlines). Several
real gaps were found and fixed this way rather than by eye — a genuinely useful reminder that
"looks readable" and "passes AA" aren't the same test:

<div style={{ display: "flex", flexDirection: "column", gap: "var(--dbm-space-4)" }}>
<Callout tone="info" title="Real gaps this process actually caught">

- `text.success` on `bg.success-subtle` measured **4.08:1**, failing AA, despite looking fine —
  green's steps weren't evenly spaced under the original HSL-derived color scales. Fixed by moving
  the token to a darker step (6.01:1).
- White text on `bg.brand` in dark mode measured **2.39:1** — badly failing. Fixed by switching
  `text.on-brand` to a dark color in that specific theme, rather than assuming white always works
  on a "dark enough" brand fill.
- `text.tertiary` was being reused for both non-text icons (3:1 floor) and literal placeholder
  text (4.5:1 floor) at a value that only cleared the lower bar. Split logic wasn't the fix —  the
  color itself was adjusted to clear both floors at once.

</Callout>

<Callout tone="danger" title="Don't">

- Don't introduce a new color pairing (new background behind existing text, or vice versa)
  without running an actual contrast check — "looks fine" is exactly how the gaps above shipped
  in the first place.
- Don't reference a primitive color (`--dbm-color-*`) directly in component code. If no existing
  semantic token fits, that's a sign a new semantic token is needed — add it to the token layer,
  don't reach around it.

</Callout>
