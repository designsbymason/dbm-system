# FAQ

Short answers to the questions people ask first.

## Is it free to use?

Yes. The code and these docs are MIT licensed, for personal and commercial work. The fonts it uses, Nunito and
Lora, are under the SIL Open Font License.

## Is it ready for production?

The packages are published and every component is reviewed and tested, but the API is pre-1.0: a release before
`1.0.0` can include breaking changes. When one does, the version's minor number goes up and its
[changelog](?path=/docs/resources-changelog--docs) says how to migrate.

## Which React versions does it support?

React 18 and later.

## Does it work with server rendering?

Yes. Every component renders on the server without touching browser-only APIs. The package's entry is marked
`"use client"`, so in the Next.js App Router a server component can import and render a component directly. A file
that reads a part (`Card.Header`), passes a function as a prop or calls a hook needs `"use client"` of its own.
[Frameworks](?path=/docs/getting-started-frameworks--docs) has the details.

## How big is it?

An app ships only the components it imports: each component is its own module, so a bundler leaves the rest out.
`Button` alone is about 3 KB of gzipped JavaScript, besides React. The stylesheet is one file for every component.

## Can I use my own brand?

Every component reads semantic tokens, so a brand is a set of token values. Two brands ship today, Purple and
Emerald, each in light and dark. A theme of your own is a file that sets the same semantic tokens; the
[Theming guide](?path=/docs/guides-theming--docs) covers what adding one takes.

## Do I have to use Tailwind or a CSS-in-JS library?

No. The components are styled with CSS Modules and CSS custom properties, and ship one stylesheet. Use whatever
you like for your own code, and read the tokens with `var(--dbm-…)`.

## Does it support right-to-left languages?

Yes. Every component works in both directions; set `dir="rtl"` on the page or a section, or use
`DirectionProvider`. See [Responsive and right-to-left](?path=/docs/guides-responsive-and-right-to-left--docs).

## What does "agentic" mean here?

That the library is made to be read by AI coding agents as well as people: a typed manifest of every component
and prop, and a guide for agents. See [AI agents](?path=/docs/getting-started-ai-agents--docs).

## Is there an MCP server?

Yes: `@dbm-system/mcp`, a read-only server that runs on your machine and answers a coding agent's questions about
components, props and tokens from the versions your project has installed. See the
[MCP server](?path=/docs/getting-started-mcp-server--docs) page.

## Where do I report a bug or ask for something?

On [GitHub Issues](https://github.com/designsbymason/dbm-system/issues). Security problems go through the private
reporting described in the repository's security policy.
