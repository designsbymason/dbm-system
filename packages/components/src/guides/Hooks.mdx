# Hooks and utilities

A few helpers are part of the public API: a consumer is meant to call them, and one install of
`@dbm-system/components` covers them. Everything else in the supporting `utils` package (the sortable,
windowing, scroll-edge and live-region hooks) is internal to the components and may change without
notice.

## usePersistentDismiss

Remembers that a message was dismissed so it stays gone. Pair it with `Alert`'s controlled `open`, or
with anything else a reader can close for good: a promotion, an announcement, a cookie notice.

```tsx
import { Alert, usePersistentDismiss } from "@dbm-system/components";

function SaleBanner() {
  const { ready, dismissed, dismiss } = usePersistentDismiss("summer-sale-2027", {
    expiresAfter: 7 * 24 * 60 * 60 * 1000, // show again after a week
  });
  return (
    <Alert banner dismissible open={ready && !dismissed} onOpenChange={(open) => !open && dismiss()}>
      Summer sale ends Sunday.
    </Alert>
  );
}
```

The first argument is a key that names the message. The second is an options object:

<FieldsTable
  rows={[
    {
      name: "storage",
      options: ["local", "session"],
      description: "Where to remember it: `local` survives closing the browser, `session` lasts for this tab only.",
      defaultValue: "local",
    },
    {
      name: "expiresAfter",
      description: "How long a dismissal lasts, in milliseconds; after that the message shows again. Left out, it lasts until `reset` is called or the browser's storage is cleared.",
    },
  ]}
/>

It returns:

<ReferenceTable
  columns={["Name", "Meaning"]}
  rows={[
    ["ready", "`false` on the server and on the first render while a server-rendered page hydrates; `true` once the browser has been asked."],
    ["dismissed", "Whether it has been dismissed, in this tab or, with `storage: \"local\"`, another one. `false` until `ready`."],
    ["dismiss", "Remembers the dismissal."],
    ["reset", "Forgets it, so the message shows again."],
  ]}
/>

- **Render nothing until `ready`.** Use `open={ready && !dismissed}`, or a message the reader already
  dismissed flashes on screen first. The cost is that it appears after the page loads, not in the
  server's HTML.
- **The key names the message.** Change it (`"summer-sale-2028"`) to show a new message to people who
  dismissed the last one.
- **What is stored** is only a timestamp under `dbm-dismissed:<key>`: no message text and nothing about
  the reader. Whether storing even that needs consent depends on where your readers are, and is yours
  to decide.
- If the browser's storage is blocked it falls back to memory, so a dismissal lasts until the page
  reloads.

## useRecentCommands

Remembers the commands a person ran most recently, for `CommandPalette`'s `recent` prop.

```tsx
import { CommandPalette, useRecentCommands } from "@dbm-system/components";

function Palette({ commands }) {
  const { recent, add } = useRecentCommands("app-palette", { max: 5 });
  return (
    <CommandPalette
      commands={commands}
      recent={recent}
      onSelect={(item) => {
        add(item.value);
        run(item);
      }}
    />
  );
}
```

The first argument is a key that names the list. Options:

    {
      name: "storage",
      options: ["local", "session"],
      description: "Where to remember the list: `local` survives closing the browser, `session` lasts for this tab only.",
      defaultValue: "local",
    },
    {
      name: "max",
      description: "The most values to keep. Adding past it drops the oldest.",
      defaultValue: "8",
    },
  ]}
/>

It returns:

<ReferenceTable
  columns={["Name", "Meaning"]}
  rows={[
    ["ready", "Whether the browser has been asked yet. `recent` is empty until it is."],
    ["recent", "The remembered values, most recent first. Pass it as `CommandPalette`'s `recent`."],
    ["add", "Puts a value first, moving it up if it was already there, and drops the oldest past `max`."],
    ["remove", "Forgets one value."],
    ["clear", "Forgets every value."],
  ]}
/>

Store ids, never text a person typed. The list is kept under `dbm-recent:<key>`.

## formatRelativeTime

Writes a date as a phrase relative to now.

```tsx
import { formatRelativeTime } from "@dbm-system/components";

formatRelativeTime(Date.now() - 2 * 60 * 60 * 1000); // "2 hours ago"
formatRelativeTime(tomorrow, { locale: "fr" }); // "demain"
```

- It returns an empty string (with a warning in development) for a value that is not a valid date.

## useToast and createToaster

`useToast()` gives a component the functions to raise and manage toasts. Call it anywhere under a
`Toast.Provider`. `createToaster()` makes the same set of functions for code that has no component to
call a hook from, such as an API client's error handler.

```tsx
const { toast } = useToast();
toast({ tone: "success", title: "Saved" });

// Outside React:
export const toaster = createToaster();
toaster.toast({ tone: "danger", title: "Could not reach the server" });
// Once, near the root: <Toast.Provider toaster={toaster}><App /></Toast.Provider>
```

<ReferenceTable
  columns={["Name", "Meaning"]}
  rows={[
    ["toast", "Shows a toast, or updates the one with the same `id`, and returns its id. A string is the same as `{ title }`. It is queued if the provider's `limit` are already showing."],
    ["toast.promise", "Shows a loading toast, then replaces it with the success or error toast when a promise settles, and returns the promise."],
    ["update", "Changes a toast that is showing or waiting."],
    ["dismiss", "Closes the toast with an id, with the exit animation."],
    ["dismissAll", "Closes every toast, and drops the ones still waiting."],
  ]}
/>

Give each toaster to one provider only. Toasts raised before the provider mounts wait in it and show then.

## useFormState and useFormController

Two hooks for a part of your own inside a `Form`. Outside a form, `useFormState` reports an idle form with no
errors, and `useFormController` does nothing and warns in development.

```tsx
function ErrorCount() {
  const { errors } = useFormState();
  return <Badge tone="danger">{Object.keys(errors).length}</Badge>;
}

function SaveShortcut() {
  const form = useFormController();
  // call form.submit() from your own shortcut handler
  return null;
}
```

## useDataTable

The state of the `DataTable` it is drawn inside: its selection, sort, page and hidden columns, and the
functions that change them. Use it to build your own parts, such as a column menu or a "clear sort" button. It
must be called inside the table's children (`DataTable.Toolbar`, `DataTable.Pagination`).

```tsx
function ColumnMenu() {
  const { columns, hiddenColumns, setHiddenColumns } = useDataTable();
  // one Menu.CheckboxItem per column, checked unless its id is in `hiddenColumns`
}
```

## useAppShell

The state of the nearest `AppShell`, for a part of your own (a bar that sticks below the header, a control that collapses the sidebar). It
throws outside a shell. The full list is on the [`AppShell` page](/docs/templates-application-shells-appshell--docs).

```tsx
import { useAppShell } from "@dbm-system/components";

function FilterBar() {
  const { headerHeight, scrolled } = useAppShell();
  return (
    <div style={{ position: "sticky", top: headerHeight }} data-scrolled={scrolled || undefined}>
      Filters
    </div>
  );
}
```

## useDirection

The direction a part of your own should read: the `dir` it was given, else the nearest `DirectionProvider`'s, else `"ltr"`. Every
component that takes a `dir` uses it the same way.

```tsx
import { useDirection } from "@dbm-system/components";

function Price({ dir, children }: { dir?: "ltr" | "rtl"; children: ReactNode }) {
  const direction = useDirection(dir);
  return <span dir={direction}>{children}</span>;
}
```

## Controller hooks

`CommandPalette`, `ContextMenu`, `Menubar` and `ImageViewer` each hand out a controller through a
`controllerRef` prop. The matching hook gives the same object to a part rendered inside the component. Outside
the component it controls nothing and warns in development.

## filterTree

Narrows a tree to what matches a search, for `Tree`'s `nodes`. It also says which rows to open, since a match
under a closed folder cannot be seen. It never changes the nodes it is given.

```tsx
const { nodes: shown, expandedIds } = filterTree(nodes, { query });
<Tree aria-label="Files" nodes={shown} expandedIds={query ? expandedIds : open} highlightQuery={query} />
```

## registerCodeLanguage

Teaches every `CodeBlock` a language, by its `name` and `aliases`, so `language="python"` then draws with it. A
registered language takes over from a built-in one of the same name, which is how a fuller grammar replaces the
approximate one. Call it once, when the app starts. It returns a function that undoes the registration, and a
block already on the page redraws when a language is registered, so a grammar loaded later colours blocks that
were drawn plain.

```ts
import { registerCodeLanguage } from "@dbm-system/components";

const unregister = registerCodeLanguage(myLanguage); // a CodeLanguage: name, aliases, label, tokenizer…
```

## Types

`Responsive<T>` is a single value or a mobile-first map keyed by `Breakpoint`. `SpaceValue` is a step of the
spacing scale, and `Breakpoint` is `base`, `sm`, `md`, `lg`, `xl`, `2xl` or `3xl`. Use them to give your own
components the same responsive props as the library's.

```tsx
import type { Responsive, SpaceValue } from "@dbm-system/components";

interface SectionProps {
  gap?: Responsive<SpaceValue>; // gap={4} or gap={{ base: 2, md: 6 }}
}
```
