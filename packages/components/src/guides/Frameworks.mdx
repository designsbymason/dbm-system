# Frameworks

The setup is the same everywhere: import the stylesheet and a theme once, set the theme on the root element, and
load the fonts ([Installation](?path=/docs/getting-started-installation--docs) has each step). What changes
between frameworks is where those lines go.

## Vite

Import the stylesheet and the theme at the top of `src/main.tsx`, and set `data-theme` and the font links in
`index.html`. The [quick start](?path=/docs/getting-started-quick-start--docs) walks through it.

## Next.js

### The App Router

Import the stylesheet and the theme in the root layout, and set the theme on `<html>` there:

```tsx
// app/layout.tsx
import "@dbm-system/components/styles.css";
import "@dbm-system/tokens/css/purple-light.bundled.css";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" data-theme="purple-light">
      <body>{children}</body>
    </html>
  );
}
```

The package marks its entry with `"use client"`, so a server component can import components from it and render
them, with no wrapper file:

```tsx
// app/page.tsx: a server component
import { Button, Stack, Text } from "@dbm-system/components";

export default function Page() {
  return (
    <Stack>
      <Text>Welcome back</Text>
      <Button>Continue</Button>
    </Stack>
  );
}
```

The components still render on the server for the first paint and hydrate on the client. The import is a client
component, so a server file has the limits any client component has, and a file that needs one of these starts with
`"use client"` itself:

- **A part of a compound** (`Card.Header`, `Tabs.List`) can't be read from a server file. Import it from a client file.
- **A function can't be passed as a prop**: an event handler such as `onClick`, or a render function such as
  `FormField`'s child.
- **A hook** (`useTheme`, `useToast`) can't be called in a server file.

```tsx
// app/settings-form.tsx
"use client";

import { Button, FormField, Input } from "@dbm-system/components";

export function SettingsForm() {
  return (
    <form>
      <FormField label="Work email" name="email">
        {(field) => <Input {...field} type="email" />}
      </FormField>
      <Button type="submit">Save</Button>
    </form>
  );
}
```

A server component renders `SettingsForm` as usual. Importing the components from a file that has `"use client"`
keeps working too.

For the fonts, the `<link>` tags from [Installation](?path=/docs/getting-started-installation--docs) go in the root
layout's `<head>`, or load Nunito and Lora with Next.js's own font loading, as long as the families are named
`Nunito` and `Lora`.

### The Pages Router

Import the stylesheet and the theme in `pages/_app.tsx`, and set `data-theme` on `<Html>` in
`pages/_document.tsx`. No directive is needed.

## Astro

Import the stylesheet and the theme in your base layout's frontmatter, and set `data-theme` on `<html>` there.
Components render to HTML at build time; add a `client:` directive (`client:load`, `client:visible`) to the ones
the reader interacts with:

```astro
---
import "@dbm-system/components/styles.css";
import "@dbm-system/tokens/css/purple-light.bundled.css";
import { Button } from "@dbm-system/components";
---

<html lang="en" data-theme="purple-light">
  <body>
    <Button client:load>Save</Button>
  </body>
</html>
```

## Server rendering

- **Every component renders on the server** without touching `window`, `document` or storage during the first
  render, so server and browser HTML match.
- **Set the theme in the HTML** (`data-theme` on the root element) so the first paint is already themed. A mode
  that follows the reader's system setting is only known in the browser: `ThemeProvider` with `mode="system"`
  applies it after load, so a small script in the head that sets `data-theme` before the first paint avoids a
  flash.
- **`ClientOnly`** renders its children only in the browser, for anything of your own that can't render on the
  server.
- **One copy of each package.** Install the same version of the four `@dbm-system/*` packages, so the app has one
  copy of the tokens and the shared code.
