# AI agents

DBM System is written to be read by machines as well as people. A coding agent working in your app can look up
exactly which components exist, what each prop accepts and how the parts fit, rather than inventing an API that
isn't there. Everything below ships inside the packages, so it always matches the version installed.

## Where an agent should start

Point it at `AGENTS.md` at the root of `@dbm-system/components`. It is the short guide for an agent: where to
look, how to set up, the rules that hold across every component, and every public name. A prompt to start from:

```text
We use DBM System (@dbm-system/components). Before writing UI code, read
node_modules/@dbm-system/components/AGENTS.md and the manifest it points to.
Only use components, parts and props the manifest lists, and style with the
semantic tokens (var(--dbm-…)), never literal values.
```

## The manifest

Every component, prop, part, hook and function, as JSON, generated from the components' types and documentation
on every build. The build fails if a prop is undocumented, so the manifest can't drift from the code.

## Ask instead of reading files

An agent that would rather ask than read can run the [MCP server](?path=/docs/getting-started-mcp-server--docs),
which answers the same questions from the files above: which components exist, what a prop accepts, which token to
use. It is read-only and reads the versions your project has installed.

```bash
claude mcp add dbm-system -- npx -y @dbm-system/mcp
```
