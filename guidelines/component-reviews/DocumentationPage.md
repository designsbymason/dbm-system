# Documentation Page — review findings

**Tier:** Template (a story-only example page, [ADR-0179](../adr/0179-templates-ship-as-composable-shells-in-the-components-package-with-story-only-example-pages-over-shipping-finished-pages-or-keeping-all-templates-storybook-only.md) and [ADR-0184](../adr/0184-a-story-only-template-page-is-a-folder-of-stories-and-a-story-kit-in-templates-with-demo-controls-and-no-playground-over-a-shipped-component-or-a-separate-pages-tree.md)) · **Category:** Data pages · **Finalized 2026-11-09**, at the maintainer's declaration, after review pass 1 below

Planned 2026-11-08 with `/plan-template`, approved by the maintainer with the recommendation on every decision. It is the "Docs or content shell" row of `04-component-inventory.md`, built as a recipe: a page on `PageShell` that an app copies, with nothing imported from it.

## Decisions
- **Kind and place:** a story-only example page in `src/templates/DocumentationPage/`, titled `Templates/Data pages/Documentation Page`, tagged `example-page`, not exported. Its name is Title Case, ends in "Page", and is not a component's ("Docs Page" would clash with Storybook's own Docs page).
- **Composition only:** `PageShell` (skip link, `Navbar` header, `Body`, `Main`, `Aside`, `Footer`), `Sidebar` for the site's navigation, `Breadcrumb` and `PageHeader` for the head of the page, `TableOfContents` in the aside, `Pagination`-style previous and next links if a component fits (else plain `Link`s), `BackToTop`. No part is drawn by hand beside a component that does it.
- **The open question, settled by a spike first:** whether a `Sidebar` can sit at the start of a `PageShell.Body`. `Sidebar` brings its own collapse state, a phone panel opened from `Sidebar.MenuButton` and a width; `Body` only lays out `Main` and `Aside`, and an aside is the wrong landmark for navigation. Three outcomes: it works with a documented wrapper (nothing is added); it needs a small `PageShell` part (a plan, an ADR and the maintainer's go-ahead first, since `PageShell` is Finalized, never a template-only pattern); or the page makes the `Sidebar` stick and scroll itself. The spike's result is recorded here before the page is built.
- **Demo:** a static documentation page (a component's page: a title, a lead, sections with headings, a code block, a table, a note), with demo controls, not a Playground. No router; the copy is in one place.
- **Responsive:** the viewport. Desktop: the navigation column, the page and the contents column. Tablet: the contents column drops under the page's head or becomes the `TableOfContents`' own folded bar (`sticky="folded"`). Phone: the navigation is the `Sidebar`'s panel behind the header's menu button and the contents list is folded. The page never scrolls sideways; a code block and a table scroll in their own frames.
- **States matrix:** the page (default), a page that is loading is not shown (a docs page is static); a page not found is the existing `EmptyState` recipe and is not repeated here. Selection and a destructive confirm do not apply.
- **Behaviour:** the keyboard path is the skip link, the header, the navigation, the page and the contents list, in markup order; choosing a contents entry scrolls to the section and marks it current as the page scrolls; the sidebar's phone panel opens and closes with the keyboard and returns focus to its button.
- **Landmarks:** one `banner`, the header's named `navigation`, the sidebar's named `navigation`, one `main`, the contents list's named `navigation` in a `complementary`, one `contentinfo`; one `h1`.
- **Checks planned, each broken once to see it fail:** the landmark tree; the layout at phone, tablet and desktop widths with no page overflow; a contents link by a real click and the current entry following a real wheel scroll; the sidebar's phone panel by real presses; a hydration and `StrictMode` test; print; forced colours; the snippets typechecked as real code (`pnpm check-snippets`, from its `DocumentationPage.snippetScope.txt`).
- **Registrations:** a `07` §6 row, this file, the `04` row (built as a page, with the "Docs or content shell" row marked as built as this recipe), the `example-page` tag, and an ADR only if the spike finds a gap that widens `PageShell`.
- **Order:** first of the two (the likeliest consumer is `apps/docs`, and it carries the open question). The Marketing Page follows ([MarketingPage.md](MarketingPage.md)).

## Spike result (2026-11-08)
A `Sidebar` is the first child of a full-width `PageShell.Body` (`width="full"`, `paddingInline={0}`), with `Main` and a sticky `Aside` holding a `TableOfContents`, the whole shell inside a `Sidebar.Provider`, the header's `Sidebar.MenuButton` opening the panel. Measured in the browser:
- **Works:** on a desktop the sidebar is a 256px column at the start edge and the contents list sticks under the header (59px, the published `--page-shell-header-height`); on a phone (375px) the sidebar's column is gone, the page does not scroll sideways, the aside stacks under the page, and the menu button opens the sidebar's panel (a dialog holding the navigation, focus on its first link). The wrapper is the `Sidebar.Provider` around `PageShell` (`AppShell` renders it for you), which the Docs say.
- **Two things to handle:** the header's `<nav aria-label="Main">` and the sidebar's default name collide (the page gives the sidebar its own, "Documentation"); and **`Sidebar` sticks at `top: 0`, behind a sticky `Navbar`**: its `stickyOffset` takes only a spacing-scale step (`SpaceValue`), so it cannot be given `--page-shell-header-height`, which `PageShell.Aside` uses. It works today by overriding its internal custom property in `style` (`--sidebar-sticky-offset: var(--page-shell-header-height, 0px)`, since the consumer's `style` is merged last), measured: the sidebar sticks at the header's bottom edge and takes the rest of the window (709px of 768px). **That is a gap in a Finalized component, not a `PageShell` part**, so it is brought to the maintainer before the page is built (options: widen `Sidebar`'s `stickyOffset` to take a CSS length, document the custom property, or use it undocumented in the recipe).

**Resolved (2026-11-08):** the maintainer chose to widen `Sidebar`'s `stickyOffset` to take a CSS length ([ADR-0195](../adr/0195-sidebars-stickyoffset-takes-any-css-length-as-well-as-a-spacing-step-over-a-custom-property-written-in-style-or-a-second-prop.md)), so the page passes `stickyOffset="var(--page-shell-header-height, 0px)"` and no internal property is touched.

## Built (2026-11-08)
Built to the plan above, in `src/templates/DocumentationPage/`: a story kit (`DocumentationPage`, with `sections` and `contents` as its demo controls), three stories (the page, a short page, without a contents list), three typechecked snippets, the Docs page, a print stylesheet, unit tests (7), a server render and hydration under `StrictMode` (4), and 8 real-browser checks.
- **Composition only:** `PageShell` (skip link, a sticky `Navbar` direct in it, `Body`, `Main`, `Aside`, `Footer`), `Sidebar` for the navigation, `PageHeader` (no breadcrumb), `TableOfContents` in the aside and, as a row, at the top of `Main` (drawn by `NavigationMenu`), `IconButton`, `Container`, `Heading`, `Text`, `Alert`, `CodeBlock`, `Table` and `Link`. The one thing it writes itself is a print rule that leaves the navigation out.
- **Found while building it:**
  - **The body stacks as a whole.** `PageShell.Body` goes to a column when its aside is below its step, so a sidebar that is still a column there sits above the page. The sidebar and the aside share one step (`lg`: `collapseBelow="lg"` on the `Sidebar.Provider`, the aside's default); the Docs say so.
  - **Header and one drawer (2026-11-08, after the first look).** The header spans the window (no `contained`): the brand at the start, `Navbar.Links align="center"` exactly in the middle (the two ends are equal-width above `lg`, the page's `.headerEnd`), and the actions (a search button) at the end. On a phone there is **one** menu button, not two: the links leave the bar below `lg` (`Navbar.Links hideBelow`, [ADR-0196](../adr/0196-navbar-links-gets-a-hidebelow-that-takes-a-set-out-of-the-bar-below-a-width-over-a-page-hiding-the-links-with-its-own-stylesheet.md); the bar is `collapseBelow="never"`, so it draws no button), and the `Sidebar`'s panel shows the site's links first (a part reading `useSidebar().inPanel`) with the documentation's sections under them. This replaces the earlier `labels.menu` naming of two buttons.
  - **Header links, drawer and head (2026-11-08, second look).** The links are Docs, Components (current) and Foundations; the actions are tertiary, brand-toned icon buttons and flush with the window's end (`.headerEnd` is `justify-content: flex-end`); on a phone the menu button is at the start, the brand in the middle and the search at the end (the menu button is first in the row and the brand and actions name their `column`). The sidebar belongs to the current header link, so it holds only the components; in the phone panel the header's links are items and the current one (Components) is an open `Sidebar.Group` holding that section. The page has no breadcrumb: `PageHeader` alone heads it.
  - **The outline as a row of pills below `lg` (2026-11-08, [ADR-0197](../adr/0197-tableofcontents-gets-a-layout-row-of-pills-with-a-dropdown-for-each-ones-children-over-a-second-outline-component-or-a-page-drawn-row.md)).** Where the column has no room, a `TableOfContents layout="row"` sits at the top of `Main` above the page's head, sticks under the header (`stickyOffset` as a CSS length) and opens the sections inside a pill (the demo's Variants has two) in a panel (the row is drawn by `NavigationMenu`, [ADR-0198](../adr/0198-the-tableofcontents-row-is-drawn-by-navigationmenu-and-layout-takes-a-width-map-over-keeping-the-hand-built-pills-and-a-two-element-pattern-only.md), and fades its ends when longer than the room); the column's outline shows from `lg`. The page's stylesheet hides the one that is not for the width, and each has its own name. `PageHeader` is kept (no look-alike header) and the breadcrumb is gone. This replaces the outline dropping under the page on a tablet.
  - **A sticky sidebar makes the page at least the window tall** (it takes the rest of the window), so a short page still scrolls by the footer's height; the footer ends it (the check says so).
  - **`Sidebar` has no print rule of its own**, so the page's stylesheet leaves the navigation out; whether `Sidebar` should leave a page in print by itself is not decided here.
  - **`Sidebar`'s `stickyOffset` took only a spacing step** ([ADR-0195](../adr/0195-sidebars-stickyoffset-takes-any-css-length-as-well-as-a-spacing-step-over-a-custom-property-written-in-style-or-a-second-prop.md)), already widened.
- **Checks, each broken once and failed:** the sticky offset (back to a step), the shared collapse step (removed) and the print rule: the sticking check, the tablet layout check and the print check failed. The real-browser checks: three columns on a desktop with each landmark once and no page overflow; the navigation and the outline stuck under the header after a real wheel scroll, the navigation as tall as the rest of the window; a real click on an outline entry scrolling to its section and marking it current, then a real scroll moving the mark; the footer ending a short page; the tablet (the navigation gone, the outline under the page); the phone panel by real presses (a click, focus inside, `Escape`, focus back); print; forced colours.
- **Not verified:** a real phone, Safari and Firefox, a screen reader, a real printer, and right to left (a page needs none).

## Review pass 1 (2026-11-09)
Five findings, all fixed; not yet Finalized.
- **`BackToTop` added** (it was in the plan and left out without a note): after the footer, with `scrollContainerRef` on a Docs page's frame.
- **A docs-token test** (`DocumentationPage.docs.test.ts`) holds the Docs page's token row to the stylesheet's one token (`space.32`); the inline spacing is in the prose.
- **No hardcoded offsets:** one `headerClearance` (80px: the header's 59px and a gap) is the sections' `scroll-margin` and the outline's `scrollOffset` (a pixel prop, so a CSS variable cannot be passed); the "Pages" navigation's name moved into the page's copy.
- **A real-keys-only check** (`PrimaryTaskByRealKeys`): `Tab` from the page's start reaches the skip link, the header, the navigation, the page and the outline in that order; `Enter` on an outline entry scrolls to its section, marks it and moves focus onto the section (the outline hands it on); a real wheel then brings up `BackToTop`.
- **The phone panel is `panelWidth="20rem"`** (the column is 16rem), asserted wider than the column and inside the window, and in the Docs and snippets.
- **Show code:** the three snippets now write the outline's entries once for the row and the column (the short page's row had listed sections the page does not have), carry the sections' `scroll-margin` and `BackToTop`, and are typechecked (`check-snippets`).
- Broken once and failed: the panel width (back to 16rem) and `BackToTop` (removed).
