# Timeline — review

**Status:** Built, with the checks below run. Not yet declared Finalized by the maintainer; the full `06-engineering-standards.md` §9 review pass over it (feature-completeness, design-quality and theming judgment items in particular) is still to do.

## What exists
`Timeline`, `Timeline.Item`, `Timeline.Group` and `Timeline.End`: a read-only record of events in an `<ol>`, each with a marker, a title, a time, an optional description, detail and body, joined by a line. Decisions: [ADR-0141](../adr/0141-timeline-is-a-read-only-ordered-list-of-items-configured-by-props-in-the-callers-order-with-a-hand-rolled-cap-and-no-windowing-over-sub-parts-a-data-array-a-reverse-prop-or-virtualizing.md) (props on the item, the caller's order, a cap and no windowing) and [ADR-0142](../adr/0142-timeline-takes-a-feed-surface-of-headings-an-end-links-detail-paging-and-two-more-layouts-over-leaving-them-to-the-caller-or-separate-components.md) (headings, an end, links and buttons, detail, paging, `alternate` and `horizontal`).

Props worth knowing: `size`, `variant` (`filled`, `outlined`), `tone` (seven, per event too), `connector` (`solid`, `dashed`, `none`), `colorfulConnector` (each line in its tone's subtle border, off by default), `timePlacement` (`top`, `side`, a breakpoint map), `orientation` (a breakpoint map is accepted), `align` (`start`, `alternate` from `md`, in both orientations), `timePlacement` (`top`/`side` vertical, `same`/`opposite` horizontal), `maxVisible` with `expanded`/`defaultExpanded`/`onExpandedChange`, `loading`/`loadingCount`/`onLoadMore`/`hasMore`/`empty`, `announce`, `formatNumber`, `labels`; an item takes `title`, `time`, `dateTime`, `description`, `icon`, `marker`, `tone`, `statusText`, `pending`, `connector`, `href`, `onPress`, `detail` with `open`/`defaultOpen`/`onOpenChange`, `children`. `formatRelativeTime` in `utils` writes a relative time for a `time`. Tokens: `timeline.marker-size.*`, `timeline.time-width` and `timeline.item-min-width` (`03-token-system-spec.md`).

## Decisions made while building
- The marker is centred on the first line of text, whichever is taller, by an offset worked out from the marker size and the line height; the time is that first line in both placements.
- The show-more row is a list item of its own holding a native `Button`, in the text column, so it stays one element across "show more" and "show fewer" and keeps focus.
- A heading and the end are flat list entries, not containers, so the cap, the order and the alternation work over one list; a fragment among the children is still not drawn.
- A linked or pressable event stretches its title over the event with a pseudo-element and one ring round the event; the body's own controls are lifted above it. Pressing "load more" disables the button while loading, so focus is handed back to it when loading ends if it was lost.
- `alternate` is a media query at `md` and the sides are decided by the order of events and the end (headings do not count); `horizontal` is resolved in the browser like `Stepper`'s orientation.
- A horizontal timeline's time goes in the row above or below the marker's row, opposite the content (`timePlacement="opposite"`), and alternation moves both with the event; the Playground has a Playground-only `horizontalTimePlacement` (labelled `timePlacement` through `control.label`, shown for a horizontal orientation) beside the vertical control, since one prop takes two sets of values.
- Every control in the Playground and in each story was driven through Storybook's channel and changed the canvas; stories whose render fixes a prop have that control off.
- The live region sits after the `<ol>` as a sibling (a fragment root), so the ref, `className` and the `aria-*` props all stay on the list.

## Not verified
- A real device, touch, and a screen reader: the roles, the hidden marker and line, the status text and the live region are checked by markup, axe and real-browser tests, not by listening.
- The placeholders' look in the four themes and a real device; `announce` and the disclosure were checked by tests and markup, not by listening.
- The full §9 review pass and the maintainer's declaration of Finalized.
- No guideline covers a feed that receives events while open; `announce` follows the first-appearance rule (nothing on the first render or when data first arrives), which is the component's own reading of it.

## Final review round
Found by the §9 pass and fixed:
- **Defect:** `loadingCount={Infinity}` threw a RangeError while rendering placeholders. It is now held between 0 and 20, with the default for a value that is not finite; a unit test covers each.
- **Defect:** focus fell to the page when the last page arrived and the "load more" button went away. It now goes to the "show fewer" button when there is one, else to the list (made focusable for the moment); unit tests and a real-browser check cover both ways, and a unit test that it is left alone when focus had moved on.
- **Defect:** a `tabIndex` the caller gave the list was silently overridden. It is kept except while a horizontal row scrolls.
- **Fragile:** the announcement effects depended on label functions that are new on every render. They now read the latest writer without depending on it; a test proves a re-render with the same events says nothing more.
- **Security:** an event's `href` now drops any scheme but `http`, `https`, `mailto` and `tel` (after removing the control characters a browser ignores inside a scheme), with a development warning ([ADR-0142](../adr/0142-timeline-takes-a-feed-surface-of-headings-an-end-links-detail-paging-and-two-more-layouts-over-leaving-them-to-the-caller-or-separate-components.md), amended). The `Link` atom itself checks nothing; it was left alone.
- **Checks added:** the detail, show-more and load-more buttons at 24 by 24 pixels at the smallest sizes (busy too), horizontal right to left, forced colours for the end bar and a horizontal line, and a server render and hydration of a horizontal timeline with loading, a link, a detail and an end. Two of them were broken on purpose and failed.
