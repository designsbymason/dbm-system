# Tree — review

**Status:** Finalized 2026-10-29, after the full `06-engineering-standards.md` §9 review pass and the rounds below, declared by the maintainer. Not verified: the items under "Not verified" in the rounds below (a screen reader and a real touch device, a phone's on-screen keyboard, 768px wide, and the render cost of a large tree that is not windowed).

## What exists
`Tree`: an expandable hierarchy of rows given as a `nodes` array, a flat `role="tree"` of `role="treeitem"` rows with roving focus. Decision: [ADR-0143](../adr/0143-tree-is-a-flat-roving-focus-wai-aria-tree-over-a-nodes-array-with-leaf-based-checks-and-a-window-of-fixed-height-rows-over-composed-item-parts-aria-activedescendant-or-nested-groups.md).

Props worth knowing: `size` (five steps), `selectionMode` (`none`, `single`, `multiple`) with `value`/`defaultValue`/`onValueChange` (always a list of ids), `checkable` with `checkedIds` (the checked leaves; a parent is derived) and `onCheckedChange`, `expandedIds`/`defaultExpandedIds`/`defaultExpandAll`/`onExpandedChange`, `loadingIds` and a node's `hasChildren` for children the caller fetches, `onItemActivate`, `renderLabel`, `highlightQuery`, `windowed` (`"auto"` from 200 visible rows, with `maxHeight`), `maxHeight`, `empty`, `dir`, `labels`/`formatNumber`, and `controllerRef` (`expandAll`, `collapseAll`, `expand`, `collapse`, `scrollToNode`). A node is `{ id, label, icon, description, children, hasChildren, disabled, trailing }`.

## Verified while building
- JSDoc on the component and every prop and type (`Tree.types.ts`), with a usage example.
- 147 unit tests across five files: the pure tree model (rows, levels, leaves, check state, toggling, ancestors), the component (structure and ARIA, expansion controlled and not, lazy children and the announcement, the whole keyboard model including typeahead and right to left, single and multiple selection, Shift ranges, Ctrl+A, checking and its mixed parents, a disabled row, the controller, a windowed long tree), the Show-code snippets, the Docs page's token table against the stylesheet, and a server render and hydration of a plain, a right-to-left and a windowed tree. jest-axe passes for closed, open, selectable, checkable, empty and right-to-left trees.
- 27 real-browser tests (15 stories, 12 hidden checks): every row is exactly its token's height at every size, selected or not, with check boxes or not; the arrow and the check box are hit on a box at least 24px tall at every size; a 500-row tree draws a window, keeps the scrollbar's height true, and `End` and `Home` reach the last and first rows through the window; the focus ring is drawn inside the row and inside the scrolling box; right to left indents from the right edge, mirrors the arrow and swaps the arrow keys; a real pointer opens from the arrow, checks from the box, selects from the label and activates on a double click; the tree is one tab stop that follows the arrow keys; forced colours keep a selected row's bar (`Highlight` against `Canvas`) and a checked box; a long label is cut with an ellipsis without changing the row's height; a disabled row is dimmed, cannot be hit, and is still reached by the arrow keys; a row that failed to load and the Empty row are exactly the row height at every size, with the words in the danger and quiet colours, the Empty row is not filled by a real pointer over it, and the retry mark is hit on a box 24px tall and asks to try again from a click and from Enter.
- The Show-code snippets pass the shared snippet checker, and were typechecked against the real components through a scratch file (removed afterwards).
- Bundle: see the last round below; 5.77KB JS and 1.67KB CSS gzipped at first, against the 10KB default budget.
- `pnpm lint` (ESLint and both typechecks) is clean, and so is `pnpm check-guidelines`.

## Decisions made while building
- **`value` is always a list of ids**, also in `single` (at most one). A type that changes with a prop does not work with a Playground, a manifest or a caller switching modes; the plan had `string | null` for `single`.
- **Flat markup, not nested groups.** Every row states `aria-level`, `aria-posinset` and `aria-setsize`, so a window can draw any slice of the visible rows and still announce each truthfully.
- **A parent's check state ignores disabled leaves** (unless all are disabled). Counting them left a parent with one disabled, unchecked leaf permanently "indeterminate", so it could never be shown as fully checked and a toggle could not tell which way to go. Found by the real-browser pointer story.
- **The check box is drawn, not a `Checkbox`.** A button inside a treeitem would be a second focus stop.
- **Hit areas** of the arrow and the check box are extended vertically to 24px and sideways halfway to their neighbour, so two never overlap (at `xs` they did when extended to a full square, and the check box swallowed the arrow's edge).
- **Typeahead restarts on any non-letter key**, so `Home` followed by a letter does not extend the word typed before it.
- **The tree element is `tabindex="-1"` while the row that holds the stop is drawn, and `0` while it is outside the window**; it hands focus to that row. (`-1` also satisfies the lint rule that a `tree` role be focusable.)
- **No dev-warning ref in render.** The missing-name warning runs in an effect.
- **The `readLengthToken` helper is a copy of `DataTable`'s** (`Tree.length.ts`), the second consumer; `05` §1 says to extract a shared module at the third.
- The Input.insertText real-browser check from the plan does not apply: the tree has no text field, and typeahead reads keys.

## Not verified
- A real device, touch and a screen reader: the roles, states, levels and the live region are checked by markup, axe and real-browser tests, not by listening, and a long press or a swipe was not tried.
- The Docs page and the stories were typechecked and their canvases mounted by the story runner; the lazy story was looked at in dark emerald and the Docs page in light purple, but not every story in every theme.
- Windowing was exercised in Chromium with 500 rows and in jsdom with 1000; thousands of rows with check boxes, and very deep trees, were not.
- Reordering and reparenting are not built (ADR-0143); `useSortable` is untouched.

## Second round: the gaps found after the first build
- **Check-state cost.** Every drawn row used to walk all the leaves under it, so a folder of tens of thousands of leaves slowed every check. The states are now one pass over the nodes (`checkStates`), which a test holds equal to the per-node answer for every node and time on a hundred thousand leaves.
- **A failed fetch.** `errorIds` and `onRetry`, with a warning mark in place of the arrow, `labels.loadFailed` in the row (so it is in the name), an announcement when one is added, and a retry from the mark, Right or Enter when the row is open. A closed row opens the ordinary way. The spinner wins while it loads again.
- **A fetch that found nothing.** `hasChildren` with `children: []` gives one disabled "Empty" row (`labels.emptyFolder`) under the open row. It is in the arrow-key order, cannot be selected or checked, carries `aria-selected="false"` in a selectable tree (the `treeitem` role requires it there), and is not counted among the leaves.
- **`scrollToNode` on a controlled tree** that never opens the rows above the target now warns once in development, and stays pending so an owner that applies the ids later still gets the scroll.
- **Contrast, measured in all four themes** (computed from the live tokens): every text pairing is at least 4.5:1 and every icon, mark and fill pairing at least 3:1 (selected and hover fills included, and the danger words and mark), except one real finding: the unchecked box's outline, `border.neutral`, is 2.3:1 on the surface in the two light themes. It is now `border.neutral-strong` (4.5:1 or more on the surface, the selected fill and the hover fill, in all four). `Checkbox` draws the same outline with `border.neutral`; that is its own component's to decide and was not touched.
- Found while writing the checks: the test library's `hover` sets no real `:hover`, so a hover check needs the browser protocol with the iframe's offset and scale added.
- Still not verified: a screen reader and a real device (touch), unchanged.

## Third round: loading, search, a row's menu and rename (ADR-0144)
- **Loading the rows.** `loading` and `loadingCount` draw placeholder rows (held between 0 and 20): with no rows they stand in for the tree in a busy group that says `labels.loading`, with rows they follow the last one, in a long tree only with the last window. The tree is `aria-busy`. Placeholders are `aria-hidden`, the height of a row at every size, and cannot be pointed at.
- **`filterTree`** (exported): matches, the rows above them, the rows to open, `keepDescendants`, a `match` function in place of the query, input never changed and unchanged rows shared. Ten tests, and the Search story drives it with `highlightQuery` and a controlled `expandedIds`.
- **A row's menu.** `onItemContextMenu({ id, element, point, via, event })` for a right-click, the context-menu key and Shift+F10. First written to cancel the browser's menu itself, which made the wrapped `ContextMenu` refuse to open (it skips an event another handler has already cancelled); the tree now cancels nothing. A real right-click and the context-menu key each open the menu for their row in a real browser, and Escape returns the focus to the row (the `ContextMenu` remembers the focused element at the moment it opens). A `contextmenu` event that follows the tree's own key request within half a second is counted as that press.
- **Rename.** `renamable`, `onRename`, `validateRename`, F2 and `controllerRef.rename`. The field fits the row at every size (it fills the smallest) with its ring inside it; keys and clicks in it never reach the tree; Enter and its blur are one commit; a refused name keeps the field and an alert; a row closed under the field drops it. The tree never changes a label.
- **Verification:** 194+ unit tests for the folder, and real-browser checks for the menu from a real click and a key, the rename field's fit and flow (including a taken name and the controller button), and the placeholder rows' height. The whole-library suites were run again after.
- **Not verified, as before:** a screen reader and a real touch device. In particular a long press opening the menu on touch is the `ContextMenu` trigger's own behaviour, wrapped round the tree, and was not tried on a device; the rename field on a phone's on-screen keyboard was not tried either.
- **Left out on purpose:** drag to reorder and reparent. It is the largest item left and the likeliest to need rework once an app uses it.

## Fourth round: refinements (11, 15 and a part of 16)
- **`selectable: false` on a node** (a row that only holds others): a click, Space, a Shift range (by click or by key) and Ctrl+A skip it, it has no `aria-selected`, and it can still be opened, checked and focused. A Shift-click on such a row does nothing rather than ending a range at it.
- **`expandOnClick`** (named for what it does; the gap list called it `expandOnSelect`, which would be wrong for a row that cannot be selected): a plain click on a row with rows under it opens or closes it, also on a row that cannot be selected; a click with Ctrl, ⌘, Shift or Alt only selects, and a double click is not a second toggle when nothing handles activation.
- **`selectOnFocus`** (single mode only): arrows, Home, End, Page Up and Down, Left to the parent, Right to the first child and a typed letter select the row focus lands on. Programmatic focus (the controller, a click's own focus, the tab stop returning) does not. A row that cannot be selected keeps the old selection.
- **Selected count:** after a change of selection in `"multiple"` a screen reader hears `labels.selectedCount(n)` ("30 selected", "None selected"); not in `single`, whose `aria-selected` is announced on focus anyway, and not for a selection the caller changes through `value`.
- **Page Up and Page Down** move by the rows that fit in the box that scrolls, less one (ten when it has no height), with Shift extending a multiple selection, and reach rows outside a window. A key that is part of an input method's composition is ignored by the tree.
- **Left out on purpose:** Ctrl+Shift+Home and End, per-parent check reporting, two-line rows, tooltips and indent guides, paged children (see the gap list).
- Tests: 210 unit tests for the folder; 38 real-browser tests, including paging through a window with a real measured box and a picker's folder and file clicks.

## Fifth round: the §9 review pass (13 findings, all fixed)
Found by the pass, with each fix proved by breaking it on purpose and watching a test fail:
- **A tree that was both `checkable` and selectable could not select a row from the keyboard** (Space only checked, Enter only activated): Shift+Space now selects when both are on, and a unit test and a real-browser check press the keys. ADR-0143 is amended for the detail.
- **`nodes` that was not a list threw** (`undefined`, `null`, a string, a number), and so did a node with no label in `filterTree`: `sanitizeNodes` draws what it can (an empty tree, a dropped node with no string `id`, a label written as text, `children` that are not a list ignored) with one development warning, and returns the very array it was given when nothing is wrong, so memoised work is kept.
- **A press inside a portal a row draws** (a tooltip in `trailing`) selected the row, because React bubbles a portal's events to the row: click, double click and focus now act only when the target is inside the row's own DOM.
- **The Playground left `loading`, `loadingCount` and `renamable` inert**, and its `maxHeight` text control turned a typed `200` into the invalid CSS `"200"`: all three are live (with a Playground tree that applies a rename the way a caller does), a bare number is pixels, and the Show-code snippet writes them.
- **The Properties table** showed no Default for the three `default…Ids` and `defaultValue` props (`[]`) and did not mark `nodes` required: both fixed and read back on the live page.
- **No `StrictMode` test**: tests now cover the loaded and failed announcements (and none for a failure there from the first render), the rename field's focus and selection, typeahead and the selected count inside `StrictMode`.
- **The duplicate-id warning repeated on every render** when `nodes` was a fresh array each time: it is now one warning per set of repeated ids, from an effect.
- **`defaultExpandAll` and `expandAll()` opened rows that only had `hasChildren`**, which then showed as open with nothing under them and never asked `onExpandedChange`: they open only rows that have rows to show.
- **A single-mode `value` with two ids marked both rows selected**: one warning, and the first is the one that shows.
- **Test gaps closed:** a label override of `undefined` keeps the default (all nine), the rename field takes text delivered in one input event (a unit test and a real-browser `Input.insertText`), and the hover check parks the pointer somewhere neutral first.
- **A long label beside a description** was cut as hard as the description: the description now gives up room first (`flex-shrink: 3`). At 375px and size `lg` the label of a row with trailing text such as "3 KB" is still cut, since the trailing text never shrinks.
- **ADR-0144 now says why the rename field is not the `Input` atom:** it is taller than a row at every size (30, 39, 42, 55 and 60px against 24, 32, 36, 44 and 52px, measured).
- **Docs page:** a Code example for a native `<div>` prop (`onFocus`, `title`), the picker, the search, rename, the row menu, loading and the failed fetch; "window" and "tab stop" are defined in the Intro; the keyboard table has Shift+Space; every Code example and every Show-code snippet was typechecked against the real components through a scratch file (a planted bad prop failed it) and every story's Show code was opened on the live Docs page.
- **Still not verified:** a screen reader and a real touch device (a long press opening a menu, a phone's on-screen keyboard), 768px wide, and the render cost of a large tree that is not windowed.
