# AppShell — review findings

First template, built 2026-11-04 under [ADR-0179](../adr/0179-templates-ship-as-composable-shells-in-the-components-package-with-story-only-example-pages-over-shipping-finished-pages-or-keeping-all-templates-storybook-only.md) with the `06-engineering-standards.md` §9 checklist applied as it was written. **Not Finalized**: that is the maintainer's to declare.

## Decisions
- Compound `AppShell` with `AppShell.Header`, `.Sidebar`, `.Main` and `.Footer`; layout and wiring only. The `Sidebar` and `Navbar` go in the slots with every prop they already have, so nothing is duplicated or hidden.
- A two-column CSS grid placed by named areas, so the markup order does not change the layout. The sidebar's column is `auto`, and the sidebar is `display: none` below its own `collapseBelow` step, so its column vanishes on a phone with no media query in the shell. `sidebarSide="end"` swaps the columns.
- `scroll="content"` (default) fits the frame to `100dvh` and scrolls only `<main>`; `scroll="page"` lets the page scroll as a whole and the shell keeps the header and the sidebar in view itself. A sticky box can only stay in view inside a grid area as tall as the shell, so the sidebar's slot (which spans every row) sticks in pure CSS, and the header measures its own height (`ResizeObserver`, only once mounted) so the first row can be that tall while the header spans every row. Until it is measured (the server render, the first paint) the header is an ordinary first row.
- The shell renders the `Sidebar.Provider`, so its state props (`collapsed`, `menuOpen`, `collapseBelow`, `labels` and the handlers) are the shell's, and a `Sidebar.MenuButton` in the header reaches the sidebar's panel.
- `<main id="main">`, matching `Navbar.SkipLink`'s default `#main`. `tabindex="-1"` so the skip link can focus it, and `0` while `scroll="content"` and it overflows (`useIsScrollable`, as `ScrollArea` and `Table` do), so a keyboard user can scroll a page with nothing focusable in it. A focus ring is drawn inside its edge (`overflow: auto` clips an outer one).
- No new token: `bg.surface`, `text.primary`, `font-family.primary`, `border-focus`, `border-width-2` and `z-index-sticky`.

## What was found while building it
- **The preview wraps every story in padding, `fullscreen` or not.** The global decorator in `preview.tsx` pads every story by `space-6` with a 100vh minimum, so a page-level template could never fill the window (a real-browser check measured the document 48px taller than the window and the main area 48px narrower than a phone). Fixed with an opt-in `parameters.fullBleed`, which every existing story ignores.
- **Markup order is tab order.** With the sidebar first in the markup, the first tab stop was the sidebar's first link, not the skip link. Documented and demonstrated: `AppShell.Header` goes first, and the layout is unchanged because the slots are placed by area.
- **`bg.canvas` is not the page colour.** Its description reserves it for the demo container, and `text.tertiary` fails on it; `bg.surface` is "page, card, sheet and drawer background", so that is what the frame uses.
- **A skip link with a real `href="#main"` closes the test browser** when a check presses Enter on it (the page's address changes under the runner). The demo's link moves focus itself and cancels the navigation, as the `Navbar` demos do.
- **A docs-only frame is needed.** On a Docs page a shell as tall as the window would fill the page, so the demo draws it in a 36rem box when `viewMode` is `docs`. The Docs page's contents list was checked: the demo page's own headings do not enter it.
- **ADR-0179 said the shell would take its own `labels`.** It draws no text, so it has none; the `labels` it accepts are the sidebar's. The ADR's detail is amended in place.

## Review pass (2026-11-04)
Found by reading the code, running the checks and reproducing in the preview with real input; all fixed.
- **A text-only page could not be scrolled by keyboard.** `tabindex="-1"` on a scrolling `main` made Tab skip it (a real Tab wrapped back to the skip link), where without the attribute the browser makes a scroller a tab stop. It is now `0` while the main area scrolls.
- **The focus ring on `main` was hidden** (`outline: none`, with `:focus-visible` true after the skip link and once it was a tab stop). Replaced by an inset ring from the focus tokens.
- **`scroll="page"` did not keep the header or the sidebar in view** (a real wheel scroll of 663px moved the banner to -663). The demo's `Navbar sticky` could only stick inside a slot as tall as the bar. The shell now owns it (see Decisions); the page-scroll story, snippet and Docs text were changed to match.
- **The Properties table's Default column was blank** for `collapseBelow`, `defaultCollapsed` and `defaultMenuOpen`; explicit `table.defaultValue` entries added.
- **The Code examples had no native-prop example**; one added (`aria-labelledby` on the main area).
- **The header-first rule had no guard.** A development warning now fires when `AppShell.Sidebar` comes before `AppShell.Header` in the markup.
- **A nested provider was untested.** A test now shows the shell's provider replacing an outer `Sidebar.Provider`, and the Docs page says so.
- **Checks that had never failed were broken on purpose**: the end-edge rule, the direction attribute, a sidebar column kept on a phone, a main area that cannot take focus, one that is never a tab stop, a removed ring, and a header and a sidebar that do not stick. Every one failed the check that guards it, and each file was restored byte for byte.
- **Not an AppShell change:** `Stat` (`variant="outlined"`, `tone="brand"`) has a border that is nearly invisible in the Emerald dark theme (measured `rgb(11,55,49)` on `rgb(44,42,52)`). Left to the maintainer's three-question test for a Finalized component.

## Checks run
- Unit and axe (jsdom): landmarks once each, the skip link and the focus target, a custom main id, a main-only shell, the data attributes, the menu button opening the panel through the shell's provider, the controlled collapsed handler, refs and passthrough, axe on the default and on the page-scroll, end-edge and right-to-left variants; a server render with `window` and `document` removed.
- Real browser (Chromium, hidden checks): desktop, tablet and phone layouts at pinned viewports (which assert the window width first), the sidebar at the end edge, right to left, the skip link and the ring, a text-only main area reached and scrolled with real keys (Chrome DevTools Protocol), a fitting one that is not a tab stop, the page-scroll mode (the frame grows, the header and the sidebar stay at the top, as tall as the window), and forced colours (system `Canvas`, same scroll behaviour).
- Real input in the browser pane: Tab then Enter on the skip link focuses `<main>`; a real click on the phone menu button opens the panel; a real wheel scroll of the page-scroll story leaves the header and the sidebar at the top; real Tab and arrow keys reach and scroll a text-only main area, which shows its ring. All four themes and the Docs page (Default column, "Show code" on every story, the framed page-scroll canvas) were looked at.
- The whole package's lint, type checks (components and Storybook), unit tests, build, Storybook tests and the Storybook bundle size budget. The one Storybook failure, `FieldFocusRing` > `Textarea`, is the known local flake and passes alone.

## Not verified
- **The native fragment jump.** The skip link was exercised through the demo's handler; a real `href="#main"` navigation moving focus to `<main>` was not run in a browser (pressing Enter on it closes the test browser).
- **A real phone, Safari and Firefox.** Everything was run in Chromium, with the phone width emulated. The address bar's collapsing on iOS and Android, which is what `dvh` is for, and Safari's and Firefox's handling of a sticky box in a grid area, were not tried.
- **Axe on a text-only scrolling main area in a real browser.** The keyboard behaviour is checked and the cause of the old `scrollable-region-focusable` risk removed, but the rule itself was not run on that page.
- **Other layouts:** the `collapseBelow` steps other than `md`, `3xl` and `never`; `Sidebar variant="floating"` in the slot; page scroll, the end edge and right to left at phone width; the header's height changing while the page is scrolled.
- **Right to left was measured, not read**: the check asserts which edge each part is on; nobody has looked at it.
- **The snippets were not typechecked as a file** against the real components; `storySnippets.test.ts` checks that each is valid TSX and uses only exports that exist.

## Additions after the first review (2026-11-05, at explicit direction)
Seven gaps found in a review of what an application needs, decided in [ADR-0180](../adr/0180-appshell-grows-an-aside-a-header-span-safe-area-insets-a-public-hook-and-page-change-props-with-the-aside-a-drawer-by-default-over-hiding-it-or-stacking-it.md): `AppShell.Aside` and `AppShell.AsideToggle` (a drawer below its collapse step by default, `asideCollapseTo="hidden"` to drop it), `headerSpan`, safe-area insets, `AppShell.SkipLink`, a public `useAppShell()` with a documented `--app-shell-header-height`, `AppShell.Header as="header"` and honest landmark wording, and `pageKey`/`pageTitle` for a page change. All additive (every default is the old behaviour), so nothing that existed renders differently. **Still not Finalized.** One new token, `app-shell.aside-width` (20rem).
- **Found while checking it:** the header's height observer watched the content box, so a change in padding alone (the safe-area top inset, which changes when a phone turns) never re-measured and the sticky offsets went stale (89px real against 59px stored). It now watches the border box. A flaky check caught it; the check now waits for layout to settle and fails 2 of 2 on the old code and passes 2 of 2 on the new.
- **The landmark wording in ADR-0179 and the Docs was wrong**: the shell never owned `<header>` or `<nav>`. Corrected in the Docs and by an amendment to the ADR.
- **The aside's drawer** is a `Drawer` opened from state, so focus is handed back to the toggle by hand (`onCloseAutoFocus`), as the Sidebar does. A scrolling aside is a tab stop with the same ring as `main`.
- **Checks:** 39 unit tests (the skip link and its `labels`, the header element, the layout attributes, the aside's landmark and drawer, controlled and uncontrolled open state, `hidden` and `never`, closing when the window widens, `useAppShell` inside and outside a shell, a page change including `StrictMode` and a key that arrives late), a server render of the new parts, and 12 real-browser checks (the aside on a desktop, as a drawer on a tablet, hidden on a phone and in right to left; the header's span with the sidebar on either side; the sticky offsets under a full header; the four safe-area insets, standing a value in through the custom properties, and the top inset on the header in page mode; a page change by a real press; the standalone skip link by a real Tab; a sticky bar at the header's height). Twelve deliberate breakages each failed a check (the aside not leaving the page, the toggle showing at the wrong widths, the header span, the aside's sticky rule, the left inset, the header's top inset, the content-box observer, a page change not moving focus, not scrolling, not announcing, the skip link's target and the header ignoring `as`).
- **Not verified:** the safe-area insets on a real notched device (a value was stood in, and the stylesheet was checked to ask for the real one); the aside's drawer on a real phone; `asideCollapseBelow` steps other than `lg` and `never`; a screen reader reading the page-change announcement; the aside with `sidebarSide="end"` at phone width; right to left looked at, not only measured.

## Layout and responsiveness additions (2026-11-05, at explicit direction)
Seven more, decided in [ADR-0181](../adr/0181-appshell-owns-the-sidebars-collapsed-state-and-width-to-add-an-automatic-rail-a-remembered-layout-and-a-resize-handle-over-leaving-them-to-the-sidebar-and-the-app.md): `railBelow` (an automatic rail that the reader can override), `AppShell.Banner` (`sticky` or scrolling away), `AppShell.Content`, `AppShell.Footer sticky`, `AppShell.Sidebar resizable` (`minWidth`, `maxWidth`, `labels`), `persistKey` with `sidebarWidth` and its handlers, and `scrolledEdge`. `useAppShell()` also reports the collapsed state, the width, the banner and footer heights, `scrolled` and `moreBelow`. All additive (every default is the old behaviour), so nothing that existed renders differently. **Still not Finalized.** No new token.
- **Found while checking it:** the sidebar's own `inline-size` transition animated a restored width or an automatic rail into place on every load, and made a drag lag the pointer; it is off for the first frames and while dragging. A pointer that is synthetic or has ended cannot be captured, so the capture is guarded.
- **The grid grew a banner row**, and the banner, the header and a sticky footer each keep their own row at their measured height while the page scrolls, the same way the header already did. Chromium lets a sticky grid item stick across the whole grid even without spanning rows, so the check that guards the banner's spanning cannot tell; the spanning is for browsers that follow the specification strictly, and is unverified there.
- **The collapsed state moved into the shell**: it is handed to `Sidebar.Provider` as a controlled value, so every `Sidebar` prop and hook behaves as before.
- **Checks:** 26 more unit tests (the rail with a controllable media query, the remembered layout and its failure modes, the handle's keys, bounds, directions and storage, the banner, the content wrapper, the sticky footer, the cue, and the state the hook reports) and 15 more real-browser checks (the rail on a tablet and where there is room, the banner's place, a sticky and a scrolling banner, the content's width and padding, the sticky footer and the end of the page, a real mouse drag, real keys, the bounds, right to left, no handle on a rail, a restored layout, and the cue in a scrolling main area, in a scrolling page, turned off, and in forced colours). Fourteen deliberate breakages each failed a check except one (above).
- **Not verified:** the rail across a real window resize (the check pins a width; the shell follows the media query's change, which the unit tests drive); the resize handle on a touch screen; `persistKey` in a private window or with storage blocked in a real browser (the unit tests simulate it); a banner or footer sticking in Safari and Firefox; the safe-area behaviour of a sticky banner and footer on a notched device (once a banner that scrolls away has gone, the header sticks under the notch, since the top inset belongs to whatever is first); right to left looked at.

## Loading, whole-page states, direction and layers (2026-11-06, at explicit direction)
Four additions, decided in [ADR-0182](../adr/0182-appshell-grows-a-busy-main-a-whole-page-state-and-a-layer-ladder-and-direction-reaches-the-shell-sidebar-and-navbar-through-a-provider.md). All are additive; the shell is still not Finalized.
- **`busy` and `labels` on `AppShell.Main`**: `aria-busy`, a zero-height sticky strip with a thin `ProgressBar` along the top edge (below the banner and header in page mode), a polite status region that empties when `busy` clears.
- **`AppShell.State`** on `EmptyState`: `kind` `empty` or `error`, `title` (an `h1` unless `level`), `description`, `icon`, `actions`; centred in the main area. New token row: `space.6`.
- **Direction**: the shell now resolves `dir` through the new `DirectionProvider` and provides it to the `Sidebar` and `Navbar` inside, so the demo no longer passes it to them. Their own `dir` still wins.
- **Layer ladder**: page content (the `sticky` step) < sidebar, aside, footer < header < banner. **Found while checking it:** the header and a consumer's `Affix` both sat on the `sticky` step, so an `Affix` inside the main area painted over the header in page mode.
- **Checks:** 10 unit tests and 1 server render, plus 3 real-browser checks (bar position, state centring, the `Affix` under the header). Each was proved by breaking the CSS once (header back on the content step, bar not offset by the header, state not centred) and watching exactly that check fail.
- **Not verified:** busy and the states on a real screen reader; the layer ladder against a consumer's other sticky elements; the other ~20 direction-aware components still need their own `dir`.
