# AppShell — review findings

**Tier:** Template · **Category:** Application shells · **Finalized:** ✅ 2026-11-07 (declared by the owner after the final review below)

First template, built 2026-11-04 under [ADR-0179](../adr/0179-templates-ship-as-composable-shells-in-the-components-package-with-story-only-example-pages-over-shipping-finished-pages-or-keeping-all-templates-storybook-only.md) with the `06-engineering-standards.md` §9 checklist applied as it was written. **Not Finalized**: that is the maintainer's to declare.

## Decisions
- Compound `AppShell` with `AppShell.Header`, `.Sidebar`, `.Main` and `.Footer`; layout and wiring only. The `Sidebar` and `Navbar` go in the slots with every prop they already have, so nothing is duplicated or hidden.
- A two-column CSS grid placed by named areas, so the markup order does not change the layout. The sidebar's column is `auto`, and the sidebar is `display: none` below its own `collapseBelow` step, so its column vanishes on a phone with no media query in the shell. `sidebarSide="end"` swaps the columns.
- `scroll="content"` (default) fits the frame to `100dvh` and scrolls only `<main>`; `scroll="page"` lets the page scroll as a whole and the shell keeps the header and the sidebar in view itself. A sticky box can only stay in view inside a grid area as tall as the shell, so the sidebar's slot (which spans every row) sticks in pure CSS, and the header measures its own height (`ResizeObserver`, only once mounted) so the first row can be that tall while the header spans every row. Until it is measured (the server render, the first paint) the header is an ordinary first row.
- The shell renders the `Sidebar.Provider`, so its state props (`collapsed`, `menuOpen`, `collapseBelow`, `labels` and the handlers) are the shell's, and a `Sidebar.MenuButton` in the header reaches the sidebar's panel.
- `<main id="main">`, matching `Navbar.SkipLink`'s default `#main`. `tabindex="-1"` so the skip link can focus it, and `0` while `scroll="content"` and it overflows (`useIsScrollable`, as `ScrollArea` and `Table` do), so a keyboard user can scroll a page with nothing focusable in it. A focus ring is drawn inside its edge (`overflow: auto` clips an outer one).
- No new token: `bg.surface`, `text.primary`, `font-family.primary`, `border-focus`, `border-width-2` and `z-index-sticky`.

## What was found while building it
- **The preview wraps every story in padding, `fullscreen` or not.** The global decorator in `preview.tsx` pads every story by `space-6` with a 100vh minimum, so a page-level template could never fill the window (a real-browser check measured the document 48px taller than the window and the main area 48px narrower than a phone). Fixed with an opt-in `parameters.fullBleed`, which every existing story ignores.
- **Markup order is tab order.** With the sidebar first in the markup, the first tab stop was the sidebar's first link, not the skip link. Documented and demonstrated: `AppShell.Header` goes first, and the layout is unchanged because the slots are placed by area.
- **`bg.canvas` is not the page colour.** Its description reserves it for the demo container, and `text.tertiary` fails on it; `bg.surface` is "page, card, sheet and drawer background", so that is what the frame uses.
- **A skip link with a real `href="#main"` closes the test browser** when a check presses Enter on it (the page's address changes under the runner). The demo's link moves focus itself and cancels the navigation, as the `Navbar` demos do.
- **A docs-only frame is needed.** On a Docs page a shell as tall as the window would fill the page, so the demo draws it in a 36rem box when `viewMode` is `docs`. The Docs page's contents list was checked: the demo page's own headings do not enter it.
- **ADR-0179 said the shell would take its own `labels`.** It draws no text, so it has none; the `labels` it accepts are the sidebar's. The ADR's detail is amended in place.

## Review pass (2026-11-04)
Found by reading the code, running the checks and reproducing in the preview with real input; all fixed.
- **A text-only page could not be scrolled by keyboard.** `tabindex="-1"` on a scrolling `main` made Tab skip it (a real Tab wrapped back to the skip link), where without the attribute the browser makes a scroller a tab stop. It is now `0` while the main area scrolls.
- **The focus ring on `main` was hidden** (`outline: none`, with `:focus-visible` true after the skip link and once it was a tab stop). Replaced by an inset ring from the focus tokens.
- **`scroll="page"` did not keep the header or the sidebar in view** (a real wheel scroll of 663px moved the banner to -663). The demo's `Navbar sticky` could only stick inside a slot as tall as the bar. The shell now owns it (see Decisions); the page-scroll story, snippet and Docs text were changed to match.
- **The Properties table's Default column was blank** for `collapseBelow`, `defaultCollapsed` and `defaultMenuOpen`; explicit `table.defaultValue` entries added.
- **The Code examples had no native-prop example**; one added (`aria-labelledby` on the main area).
- **The header-first rule had no guard.** A development warning now fires when `AppShell.Sidebar` comes before `AppShell.Header` in the markup.
- **A nested provider was untested.** A test now shows the shell's provider replacing an outer `Sidebar.Provider`, and the Docs page says so.
- **Checks that had never failed were broken on purpose**: the end-edge rule, the direction attribute, a sidebar column kept on a phone, a main area that cannot take focus, one that is never a tab stop, a removed ring, and a header and a sidebar that do not stick. Every one failed the check that guards it, and each file was restored byte for byte.
- **Not an AppShell change:** `Stat` (`variant="outlined"`, `tone="brand"`) has a border that is nearly invisible in the Emerald dark theme (measured `rgb(11,55,49)` on `rgb(44,42,52)`). Left to the maintainer's three-question test for a Finalized component.

- **Axe on a text-only scrolling main area in a real browser.** The keyboard behaviour is checked and the cause of the old `scrollable-region-focusable` risk removed, but the rule itself was not run on that page.

## Loading, whole-page states, direction and layers (2026-11-06, at explicit direction)
Four additions, decided in [ADR-0182](../adr/0182-appshell-grows-a-busy-main-a-whole-page-state-and-a-layer-ladder-and-direction-reaches-the-shell-sidebar-and-navbar-through-a-provider.md). All are additive; the shell is still not Finalized.
- **`busy` and `labels` on `AppShell.Main`**: `aria-busy`, a zero-height sticky strip with a thin `ProgressBar` along the top edge (below the banner and header in page mode), a polite status region that empties when `busy` clears.
- **`AppShell.State`** on `EmptyState`: `kind` `empty` or `error`, `title` (an `h1` unless `level`), `description`, `icon`, `actions`; centred in the main area. New token row: `space.6`.
- **Direction**: the shell now resolves `dir` through the new `DirectionProvider` and provides it to the `Sidebar` and `Navbar` inside, so the demo no longer passes it to them. Their own `dir` still wins.
- **Layer ladder**: page content (the `sticky` step) < sidebar, aside, footer < header < banner. **Found while checking it:** the header and a consumer's `Affix` both sat on the `sticky` step, so an `Affix` inside the main area painted over the header in page mode.
- **Checks:** 10 unit tests and 1 server render, plus 3 real-browser checks (bar position, state centring, the `Affix` under the header). Each was proved by breaking the CSS once (header back on the content step, bar not offset by the header, state not centred) and watching exactly that check fail.
- **Not verified:** busy and the states on a real screen reader; the layer ladder against a consumer's other sticky elements; every component that takes a `dir` now reads the `DirectionProvider` (2026-11-06).

## Verification pass (2026-11-06, at explicit direction)
The unverified and open items from the gap list that a real browser could settle. Decided in [ADR-0183](../adr/0183-appshell-prints-the-page-without-its-navigation-chrome-over-printing-the-screen-layout-or-leaving-print-to-each-app.md) (print). 
- **Hydration (`AppShell.ssr.test.tsx`):** `hydrateRoot` over the server HTML, with `onRecoverableError` collected, for a page-scrolling shell with every part, a right-to-left one and content-scrolling ones, and a test that the measured heights are not in the server HTML and are set after hydrating. A deliberate mismatch made two of them fail.
- **No unmeasured painted frame:** the header, banner and footer measured in a passive effect, so a frame could be painted before a `sticky` part was kept in view. `useElementHeight` now measures in a layout effect in the browser (an ordinary effect where there is no `window`). A real-browser check reads the shell from a `MutationObserver` as soon as the task that drew it has finished, which is what the first painted frame will show; deferring the measurement makes it fail. What the *server* draws before hydration is unavoidably unmeasured, and a second check shows the header, main area and sidebar are where they will be once measured (the sticky footer pins to the window's bottom only after hydration, by design).
- **`StrictMode`:** a measuring shell ends up measured with exactly the observers a plain mount has (no observer left from the first mount), follows a later height change, and forgets the header's height when the header is removed. Breaking the disconnect or the reset in the cleanup fails them.
- **Print (ADR-0183):** two real-browser checks with the print media emulated and cleared afterwards (a content shell's main area is laid out in full and the sidebar and aside are left out; a page shell's banner, header and footer are static and in order). Found while checking it: before the rule, the main area printed only what fit its box, and the measured sticky parts spanned every row. Each rule was broken once and its check failed.
- **The floating `Sidebar` in the slot:** inside its column, clear of the main area and the edges, inset with rounded corners and a shadow, and in place while the page scrolls. Nothing needed fixing.
- **The header's height changing while scrolled:** the recorded height, a bar parked below the header and a sidebar below it all follow at once and again on the way back; with the observer removed the check fails.
- **A text-only scrolling main area** is a tab stop reached by a real Tab and scrolled by a real arrow key, and passes the accessibility run; with its `tabindex` removed it fails.
- **Router recipe:** a "With a router" code example (typechecked) and a test that pressing a router-style link closes the phone panel and announces the new page. The Docs' advice to pass `dir` to the `Sidebar` and `Navbar` was stale (the shell provides it) and is corrected.
- **Found and fixed: on a phone, choosing a page from the open menu panel left focus on the Menu button, not on the main area.** The shell moved focus to the main area when `pageKey` changed; the `Sidebar`'s phone panel then finished closing and handed focus back to the menu button unconditionally (`06` §9: a late hand-back returns focus only if it is still there). Fixed in `Sidebar` (see its review file), and the shell's own aside drawer, which handed focus back to its toggle the same way, got the same rule. Checks: a real-browser one (a phone, real presses), unit tests for the router link and for a link in the aside's drawer, each failing against the old code.
- **Not done:** a real phone, Safari and Firefox; the native `href="#main"` jump; the rail-toggle performance measurement; a keyboard shortcut for the sidebar; bottom navigation.

## Final review (2026-11-07, at explicit direction)
The full `06` §9 pass on the current shell, after the additions of ADR-0180 to ADR-0183. Nine findings, all fixed; declared Finalized by the owner on 2026-11-07.
1. **The resize handle's target was 8px wide (item 57, WCAG 2.5.8).** An invisible, centred `::before` of `space.6` (24px) widens it; a real-browser check presses points up to 11px either side with `elementFromPoint` and starts a real drag 10px off the centre, and fails without the pseudo-element. **Accepted limit:** the header and the footer paint above the handle (the layer order, ADR-0182), so beside them only the sidebar side of the target, 12px, is grabbable; beside the main area's body it is the full 24px. There is still no single-pointer alternative to dragging (WCAG 2.5.7): the arrow keys and a double press cover the keyboard, and a pointer-only alternative (buttons for the steps) is a design decision not taken.
2. **Stale direction text** in the `dir` JSDoc, its Controls description and the Right-to-left and Playground snippets, all of which still told an app to pass `dir` to the `Sidebar`; the shell has provided it since ADR-0182.
3. **Properties table defaults:** `dir` now shows "the provider's, else 'ltr'", `scroll` and `sidebarSide` use the same quoting as the rest, and `labels` shows its defaults on the root, `SkipLink`, `Sidebar`, `Aside` and `AsideToggle`, as `Main` did.
4. **A public type name collided with a part:** `AppShellState` (what `useAppShell()` returns) sat beside `AppShell.State` and `AppShellStateProps`; it is now `UseAppShellResult`.
5. **The hooks were undocumented:** the Docs page has a `useAppShell` table, and the Hooks guide lists and shows `useAppShell` and `useDirection`.
6. **Right-to-left demos are in Persian** (the shell's, the sidebar's and the parts' own words through `labels`), through `demoCopy` in `AppShellStoryKit.tsx` and `demoSidebarCopy` in the Sidebar's demo kit; the Playground follows its `dir` control. A standing preference: every right-to-left story uses Persian.
7. **Performance, measured** (rail toggle with a heavy static table, frame times over the transition): 500 cells, slowest frame 17ms; 3,000 cells, 25ms with one frame over 20ms; 10,000 cells, 50ms (collapse) and 85ms (expand) with several frames over 20ms. Nothing changed in the stylesheet: the cost is the table being laid out each frame, a table that long should be a `DataTable` (which draws only the rows in view), and the Docs say so.
8. **Housekeeping:** this file and the status row.
9. **Prop order (2026-11-07, at explicit direction):** the Controls panel, the Properties table, the Playground panel and the `AppShellProps` declaration read in one order: `children`; layout (`scroll`, `headerSpan`, `sidebarSide`, `dir`, `scrolledEdge`); the sidebar's collapse and menu state (`collapseBelow`, `railBelow`, then each default, controlled and handler triple); width (`persistKey` and its triple); the aside (`asideCollapseBelow`, `asideCollapseTo`, its triple); page change (`pageKey`, `pageTitle`); `labels`; then `style`, `className`, `id`, `data-testid`. Checked live on the Docs page. **Found on the second look:** Storybook's own Controls panel lists a type's *inherited* props before its own, so with `AppShellProps` extending `SidebarStateProps` and the parts' shared base, `collapsed`, `labels`, `id`, `className`, `style` and `data-testid` came first. `AppShellProps` now declares every prop itself, in the Docs order (it no longer extends either), and the panel, read live after a restart, shows the escape-hatch props last.

**Show code, all 21 variants and the Playground reviewed against their stories and typechecked as code:** the sticky-bar snippet had no background or layer (a bar the page showed through); the rail snippets lacked the collapse button their comment named; the aside, hidden aside, sticky banner, content, busy, empty, error and resizable snippets showed props, words or limits their story does not (now the story's own); the Right-to-left and Playground snippets are Persian and no longer put `dir` on the `Sidebar`.

**Not done:** a real phone, Safari and Firefox; a real printer; the native `#main` jump; a screen reader.

**After the review, before Finalizing (2026-11-07):** the banner demo, snippets, Docs example and JSDoc use `Alert banner` (edge to edge) and say the banner holds any content; the Related components cards preview live `Sidebar`, `Navbar`, `Alert`, `Drawer` (its trigger button) and `Container` instances. Both checked on the Docs page.

**Persian demos name their language (2026-11-07):** the right-to-left demo (the Right-to-left story and the Playground with `dir` set to `rtl`) puts `lang="fa"` on the shell next to `dir="rtl"`, its two snippets and the Docs say to set both, and two real-browser checks guard it (`lang` and `dir` on the frame; a left-to-right demo sets no `lang`).

**Right-to-left story removed (2026-11-07, at explicit direction):** the visible "Right to left" story, its snippet and its Docs section are gone, since a template needs no right-to-left story. The `dir` prop and its Playground control stay, and the hidden right-to-left checks (layout, aside, resize handle, phone panel, `lang` and `dir` together) still run. Docs-only, so by question 1 of the three-question test (`06-engineering-standards.md` §9) the shell stays Finalized.

**Story kit: `DemoShell` takes `sidebarCurrent` (2026-11-07, at explicit direction):** an optional id for the sidebar item that starts as current (`"home"` by default), so a page that is not Home does not show Home highlighted (the Data Table List Page sets `"team"`). Additive and docs-only (no shipped code, no AppShell story changes), so by question 1 of the three-question test (`06-engineering-standards.md` §9) the shell stays Finalized.
