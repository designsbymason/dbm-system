# MultiSelect — build findings

Fifteenth organism and the second 🟡 v1.5 one (item 15 in the organism build order, `04-component-inventory.md`), built 2026-10-25 on `Combobox`'s list and `TagsInput`'s box with the `06-engineering-standards.md` §9 checklist applied as it was written. **Not yet declared Finalized:** the final review pass (`/review-component MultiSelect`) has not been run, and only the user declares a component Finalized.

## Decisions
- **The floating list is shared with `Combobox` through `internal/optionList`, and the box and chips are `TagsInput`'s** (its stylesheet, its chip and its `fitCount`); `MultiSelect` is its own component, not a `multiple` prop on `Combobox`: [ADR-0123](../adr/0123-the-floating-option-list-is-shared-by-combobox-and-multiselect-through-internal-and-multiselect-draws-tagsinputs-box-and-chip-over-copying-them-or-adding-a-multiple-prop-to-combobox.md). Extracting the list rebuilt `Combobox` (Finalized) on it with no change to its output; see [Combobox.md](Combobox.md).
- **A combobox over a multi-selectable listbox; the list stays open and keeps chosen rows; chips outside the list; a two-key Backspace; "Select all" covers the matches:** [ADR-0124](../adr/0124-multiselect-is-a-combobox-over-a-multi-selectable-listbox-that-stays-open-and-keeps-chosen-rows-with-chips-outside-the-list-and-a-two-key-backspace-over-closing-on-choice-hiding-chosen-rows-or-removing-on-one-backspace.md).
- **One hidden input per value; `required` and `minSelected` as a custom validity on the typing field:** [ADR-0125](../adr/0125-multiselect-submits-one-hidden-input-per-value-and-refuses-through-a-custom-validity-on-its-own-entry-over-a-hidden-validating-control-or-a-name-array.md).
- **No new token and no new dependency.** The list's rows use `Combobox`'s tokens (`combobox.list-max-height`, `combobox.option-height.*`, `combobox.option-height-described.*`) and the box uses `TagsInput`'s (`tags-input.entry-min-width`). No new colour pairing: the chosen, highlighted row is `Combobox`'s, and a real-browser check measures it in all four themes. The Docs page's token table lists the union of the four stylesheets, held to them by a test.
- **Bundle size:** 12.45KB of JS and 3.38KB of CSS gzipped, against a 14KB JS budget set for it (`scripts/check-component-bundle-size.mjs`, with the reason). `Combobox` is 8.66KB and `TagsInput` 6.47KB.
- **Flat props, not compound.** The only required thing is an accessible name (a development warning when it is missing). `ref`, `id`, `data-testid` and the `aria-*` props go to the typing field; `className`, `style` and every other native `<div>` prop go to the outer box (`05` §3's split, stated on the props and the Docs page).
- **Defaults differ from `Combobox` where the job does:** `clearable` is on (a field of several values is cleared often), `autoHighlight` is on always, and the text is dropped, not committed, when the field is left.

## What was found while building it
- **The unseen chip that holds the row's height must hold a non-breaking space.** A plain space collapses to nothing and the empty box came out 1.8px shorter than `TagsInput`'s at three sizes; the real-browser check that compares the two at every size found it.
- **`Form` ties a hidden validating control to its field only by id or name,** so a `TagsInput`-style hidden `required` control surfaced as an unnamed "field-3" in the form's summary and nothing at the field. The first Form test failed for exactly this. The rule moved onto the typing field itself (ADR-0125), which `FormField` gives its id to; a disabled hidden input keeps the name in the form's controls while nothing is chosen, so `Form`'s own "no control submitted under that name" warning stays quiet.
- **`FormField` hands a control `hasError`, `required` and `disabled` but not `aria-invalid`;** the field sets `aria-invalid` itself from `hasError`, and redeclares `aria-invalid` so a caller's own value reaches the typing field instead of the outer box.
- **A box with caret and clear buttons at the end of a wrapping row put the buttons on the last line.** The chips and typing area now sit in a row of their own beside the buttons, so the buttons stay at the end of the box, centred on it, however many lines the chips take; `.root .box` out-ranks `TagsInput`'s own `flex-wrap` whichever stylesheet is read last. A real-browser check measures the centring (and was seen to fail with the alignment broken).
- **`Tag` warns once when `removable` has no `onRemove`.** The unseen sizer and the measuring copies pass a no-op, so the field adds no warnings (`TagsInput` still does in a test run, as before; not touched).
- **Keyboard flow in a multi-pick:** after a choice the text is cleared and the highlight stays on the option, so ArrowDown, Enter picks the next one; the first ArrowDown on a closed list highlights the first enabled option (a single-choice field would rest on the chosen one).
- **A choice made while text is typed:** Enter chooses the first match, never the "Select all" row, which is skipped by the automatic highlight; "Create …" is highlighted only when nothing else matches.
- **The storybook bundle-size tripwire** (`check-storybook-bundle-size.mjs`) tripped at 20.1MB against a 20MB total set at the first measurement; raised to 24MB with a note. It was a pre-existing near-limit, not something this component alone caused.

## Deviations from the plan
- **`controllerRef` has no matching hook.** `05` §3 pairs a controller with a `use…()` hook inside the component; `MultiSelect` renders no parts a caller's component sits inside (a `renderOption` row is drawn by the list), so a hook would have nothing to be called from. The controller (`open`, `close`, `clear`, `focus`, each returning whether it had anything to do) is the whole surface.
- **The chip row's logic is written again as a hook (`useSelectedChips`)** rather than lifted out of `TagsInput` (ADR-0123): the model is the same, `TagsInput` is untouched apart from moving its chip into `TagsInputChip.tsx`, and it can adopt the hook later.

## Known limits
- Typed text is a way to find an option and is dropped on leaving the field; there is no free-text chip (that is `TagsInput`), and `onCreate` needs the owner to add the new option to `options` (until then its chip keeps the label).
- The chips are reached by the left arrow or Backspace, never Tab; a keyboard user who doesn't know it relies on the hint (`labels.chipsHint`) or a screen reader's browse mode.
- With `overflow="collapse"` hidden chips are unmounted while idle, so a form that reads the DOM for chips sees only the visible ones; the hidden inputs hold every value.
- The caret and clear icons are the field's own size step (ADR-0103), which reads large beside chips one step smaller; it matches `Combobox` and `Input`.
- No type-ahead by first letter (typing already opens and narrows the list), no chip reordering and no per-option chip tone.
