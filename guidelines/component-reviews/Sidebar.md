# Sidebar — review findings

Twelfth organism, built 2026-10-19 with the `06-engineering-standards.md` §9 checklist applied as it was written. **Finalized 2026-10-21**, at the maintainer's declaration after the first-look changes, three rounds of additions and a final review pass (below). The open items at the end are what a later pass should read first; per `06` §9, further changes to the Sidebar's code, stories, docs or tokens need the maintainer's go-ahead first.

## Decisions
- Optional `Sidebar.Provider` holds the collapsed and open state so a toggle and a menu button can sit outside the sidebar (in a `Navbar`); a `Sidebar` with none holds its own: [ADR-0104](../adr/0104-sidebar-holds-its-collapsed-and-open-state-in-an-optional-provider-that-a-toggle-and-a-menu-button-outside-it-read-over-props-only-or-an-imperative-ref.md).
- The children are drawn on the page and in a `Drawer` panel below a CSS step (`collapseBelow`), and the panel is never a rail: [ADR-0105](../adr/0105-sidebar-is-drawn-on-the-page-and-in-a-drawer-panel-below-a-css-step-and-the-panel-is-never-a-rail-over-measuring-its-width-or-moving-one-rendered-copy.md).
- The rail keeps an icon where it was, shows an item's text as a tooltip (still its name) and opens a group as a `Menu`; expanded groups open with `Collapse` to three levels: [ADR-0106](../adr/0106-sidebar-collapses-to-a-rail-where-an-icon-stays-put-its-text-is-a-tooltip-and-a-group-is-a-menu-and-expanded-groups-open-with-collapse-to-three-levels-over-hiding-the-column-or-a-tree.md).
- A plain `<div>` root with a landmark per `Sidebar.Nav`, native scrolling for the content, and a width that is a length with one token: [ADR-0107](../adr/0107-sidebar-is-a-plain-box-with-a-landmark-per-nav-its-content-scrolls-natively-and-its-width-is-a-length-with-one-token-over-an-aside-a-scroll-area-or-a-size-scale.md).
- Compound: `Sidebar` (a `<div>`), `Header`, `Content`, `Footer`, `Nav` (a named `<nav>` holding a `role="list"` list), `Section`, `Item`, `Group`, `Account`, `Separator`, `Skeleton`, `Toggle`, `MenuButton` and `Provider`, plus the `useSidebar()` hook. Items are parts rather than an `items` prop so a router's own link (`asChild`), a `Badge` and state of their own can be passed.
- `variant` (`outlined`, `filled`, `ghost`, `floating`) is the sidebar's own look, as `Navbar`'s is, and `currentVariant` (`subtle`, `bar`, `solid`) is the vertical counterpart of `Navbar`'s (`bar` for `underline`).
- **One new token, `sidebar.width`** (16rem), in `03`'s component-token table, since the spacing scale tops out at 8rem. The rail's width, an item's height and the group indent are derived in CSS from `icon-size`, `space` and the item's step, so they need none. **No new colour pairing:** every pairing is one `Navbar` already uses (`text.brand` on `bg.brand-subtle`, `text.on-brand` on `bg.brand`, `text.secondary` on the tint, `border.focus` on the surface).
- `Sidebar.Item` draws its own `<a>` or `<button>` (and `Slot` for `asChild`) rather than the `Link` atom, as `Navbar.Link` does: its look is a full-width row that collapses to an icon. It shares small ideas with `Navbar.Link` (the capture-phase click guard, the external mark, the grow-in marker) but not code; if `NavigationMenu` needs the same, the rows are the third consumer and the shared part moves to `internal/` then (`05` §1).
- Not built, additive later: dragging it wider (`Splitter` composes it), a keyboard shortcut to toggle, reordering and pinning, and a group that is also a page. Remembering the collapsed state and filtering the navigation are recipes on the Docs page, with a story each ([ADR-0111](../adr/0111-sidebar-measures-a-rail-flyout-from-the-rails-edge-caps-a-rail-count-at-99-rolls-a-groups-counts-up-and-adds-a-floating-look-and-a-skeleton-part-over-a-fixed-offset-a-wider-mark-an-explicit-total-or-a-loading-prop.md)).

## What was found while building it
- **`ScrollArea` was the wrong scroller for the content (a deviation from the plan, which recommended it).** It makes its viewport a tab stop whenever it overflows, so `Tab` landed on an unnamed box before the first item and a real-browser check that tabbed into the first item failed; and Radix wraps its content in a `display: table` box that sizes to the widest label, which stops an ellipsis. `Sidebar.Content` scrolls natively ([ADR-0107](../adr/0107-sidebar-is-a-plain-box-with-a-landmark-per-nav-its-content-scrolls-natively-and-its-width-is-a-length-with-one-token-over-an-aside-a-scroll-area-or-a-size-scale.md)).
- **The toggle changes its name instead of carrying `aria-expanded`** ("Collapse sidebar" / "Expand sidebar", for the press it would answer to, with a tooltip). The plan said `aria-expanded`; a changing name and a state attribute together double-announce, so the name does the work.
- **The collapse button overflowed the rail.** An `IconButton` is 30–61px and the rail's inner width is 24–44px, so at `md` the footer's toggle was clipped out of sight. Inside a sidebar it is the size of an item (`button.toggleBox`), and the rail's header and footer are columns.
- **A count badge covered the icon in the rail** (found by looking at it): it is now a 16px mark on the icon's corner.
- **A group's text and its items didn't line up** (found by looking): the indent is the icon plus the gap, so an opened group's items start under the group's own text, and a nested group steps in by one level.
- **An item was 38px tall, not square with the rail.** The line height of the text added 2px; the item's line height is the icon's size, so the item and the rail are exactly `icon + 2 × padding`.
- **The "end" and right-to-left demos were drawn wrong by the demo frame, not the component** (the frame put the content after the sidebar and read the page's direction): the frame takes `reverse` and `dir`.
- **An accessible name in a flex row has no space between the text and the hidden cue in jsdom** ("Docs(opens in a new tab)"); the tests accept the space or none, as `Navbar`'s do, and a browser's accessibility tree puts one between the boxes.
- **The first real-browser checks failed on mistakes in the checks:** a width measured against a box that has a 1px border, a name queried without its badge ("Inbox" for "Inbox 12"), a content element found by a class name that `Avatar` also uses, and a sticky check that put a window-tall sidebar in a 20rem box. Each is now a check that fails when the thing it guards breaks (the first run is what showed they did).
- **Focus after opening the panel started on a button, not the first link.** Radix's focus scope skips links when it picks where to begin. Fixed in the first review's additions below: the panel now opens on its first item.

## After the first look (2026-10-19)
- **Section headings are set in capitals** (`text-transform: uppercase`; the name a screen reader reads is unchanged), and the collapse button is a single caret (`CaretLeftIcon` / `CaretRightIcon`, pointing toward the edge while open and away while a rail).
- **Every demo sidebar fills its box.** The demo stage stretches its one child and the frame is a minimum height, so a sidebar is as tall as the dashed box; a hidden check asserts it. A frame that must scroll its content holds a fixed height.
- **A passed `Badge` is shown and tested**: the "Kinds of item" story draws one beside the built-in text badge, unit tests assert its own tone, variant, size, class and style win and that it is one pill, and a real-browser check measures the fills, the pill's height and its place in the rail. The built-in badge's height rule has `Navbar`'s specificity, so `style` always wins.
- **Snippets now mirror their stories** (the demo's header, two sections, groups and footer, the same `current` item, `defaultCollapsed` for the rail, the real controlled example, and no `sticky` in the page-shell one), and were typechecked against the real components again. The footer's name in every demo is "John Doe", in the sidebar's own text size.
- **The built-in badge is `Badge`'s solid brand look** (subtle on a current item drawn as a brand fill, where a solid pill would vanish), as `Navbar`'s now is; a passed `Badge` is unchanged. It is drawn at `Badge`'s own size (`xs` in an expanded item, and a smaller 20px mark in the rail, at the maintainer's direction), so a one- or two-digit count is `Badge`'s circle, and a negative block margin keeps a badged row the height of a plain one (the first version shrank the badge to fit the row, which made two digits an oval).

- **The external-link mark is one step below the item's icon** (12px beside a 16px icon, 16px beside a 20px one) and so is a group's caret, rather than a fixed 12px, at the maintainer's direction.

## Final review (2026-10-22)
A full pass against `06` §9, with the findings fixed:
- **Collapsible section headings kept the browser's own button padding** (`1px 6px`): the text started 6px right of a plain heading's and the heading was 2px taller. `.sectionToggle` now has `padding: 0`, and `SectionsFold` measures the label's place and the heading's height against a plain heading (it fails without the fix).
- **A responsive collapse dropped focus.** Shrinking the window past `collapseBelow` with focus in the sidebar left focus on `body`. The sidebar now hands focus to the menu button, from a flag kept by its focus events, since the browser clears focus when anything reads the layout, which can be before the width change is reported (a blur from the column being hidden does not clear the flag). `FocusSurvivesTheCollapse` resizes the story's frame and fails without the fix; it also failed in a first version that read `document.activeElement` at the change.
- **`Sidebar.Account` did not scale with `size`:** at `sm` and `xs` its 36px picture overflowed a 32px or 24px button. The default avatar is now as wide as an item (`--avatar-dimension-base`), and `AccountScalesWithSize` checks all four sizes (it fails without the fix).
- **`Sidebar.Section` takes a `value`,** as `Group` does: two sections with the same label shared a fold, and a label that is not text kept one in each copy (now a development warning).
- **Magic numbers:** the rail flyout's gap is `Menu`'s own default (`MENU_SIDE_OFFSET`, shared by path and not exported from the package), and the peek delays are named.
- **Coverage:** the StrictMode and server-render/hydration tests now include `exclusive`, `peek`, collapsible sections, descriptions, group badges, `Account`, `Skeleton` and `floating` (a probe had shown they already worked).

## Post-Finalization (2026-10-22)
CodeQL alert `js/polynomial-redos` on `pathOf`: stripping trailing slashes with `/\/+$/` is quadratic on a long run of slashes that does not end the string. It is now a loop, with the same results; `Sidebar.paths.test.ts` pins them for long runs. Hrefs and the current path come from the app, so this was a hardening fix; Finalized status unchanged.

## Post-Finalization follow-up (2026-11-04, at explicit direction): `panelWidth`
`width` set both the column on the page and the phone panel (the drawer's size), so a developer could not give the panel its own width. A new optional `panelWidth` (a number of pixels or any CSS length) sets the phone panel alone; left out, the panel is `width`, and left out too, the `sidebar.width` token, as before. **Additive: nothing that already existed renders differently**, so the Sidebar stays Finalized, with a scoped pass on the new prop.
- The drawer still keeps its sliver of the page showing, so on a narrow phone the panel is capped there however large `panelWidth` is. The column on the page is not affected by `panelWidth`.
- Checks: four unit tests (the token, `width` alone, `panelWidth` winning and leaving the column alone, a number as pixels) and a real-browser check (the column is `width` wide, the panel `panelWidth` wide, capped at the window); breaking each of "the prop is ignored" and "the prop also moves the column" failed them. A Playground control, a "phone panel at its own width" story and snippet, and a Properties row were added, and the AppShell Docs page points to it.
- Not verified: a `panelWidth` wider than a real phone's screen (the cap is the drawer's and was measured by the check in a wide window); right to left.

## Focus hand-back after the phone panel closes (2026-11-06, at explicit direction)
A bug fix to a Finalized component, found by the AppShell verification pass; Finalized status is unchanged. The phone panel's `onCloseAutoFocus` handed focus to the menu button unconditionally. When the shell answered a page change by moving focus to the new page's main area, the panel finished closing afterwards and took focus back to the button, so a keyboard or screen-reader user landed on "Menu" instead of the new page (reproduced with real clicks in Chromium). It now hands focus back only if focus is still in the panel or has fallen to the page, as `06` §9 asks of a late hand-back, and always stops Radix's own return to a trigger the panel does not have. Tests: a link pressed with focus still in the panel returns focus to the button; focus moved elsewhere before the close is left alone; breaking the condition either way fails exactly the matching tests, and an `AppShell` real-browser check (a phone, a real press on a page in the open panel) fails against the old code.

## `stickyOffset` takes a CSS length (2026-11-08, at explicit direction, additive, [ADR-0195](../adr/0195-sidebars-stickyoffset-takes-any-css-length-as-well-as-a-spacing-step-over-a-custom-property-written-in-style-or-a-second-prop.md))
`stickyOffset` is `SpaceValue | string`: a step of the spacing scale as before, or any CSS length, so a sticky sidebar under a `PageShell` header can stick at its measured height (`"var(--page-shell-header-height, 0px)"`). Nothing that existed changed (a number is the same custom property as before), so by question 1 of the three-question test (`06-engineering-standards.md` §9) the sidebar stays Finalized, with a scoped mini-pass: the JSDoc, the control and Docs wording, a unit test (a step, a length, a rem value and the offset only while sticky) and a real-browser check (a 59px offset, which is no step, is where the sidebar sticks and the height it takes); broken once (the string branch), both failed.
